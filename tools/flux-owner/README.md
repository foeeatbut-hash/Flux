# Flux Владелец

Локальное приложение владельца для выдачи лицензий и подписи обновлений Flux. Файлы хранилища и закрытые ключи остаются на компьютере владельца; не отправляйте их вместе с исходниками.

## Получение portable

Исходники приложения находятся в `tools/flux-owner` общего репозитория Flux.
Windows-сборка запускается при изменении этой папки или вручную в Actions →
«Flux-Owner portable». Готовый `Flux-Owner-1.0.0-x64.exe` добавляется в Releases
рядом с текущей сборкой Flux и доступен в артефактах сборки.
Программа владельца не входит в меню и portable для сотрудников.

## Первый запуск

Запустите `Flux-Owner-1.0.0-x64.exe` в Windows. При первом старте задайте две разные длинные фразы-пароля: одну для основного хранилища, другую для запасного ключа владельца. Приложение предложит сохранить зашифрованную резервную копию с расширением `.flux-owner` отдельно, например на отключаемый носитель. Хранилище находится в `%USERPROFILE%\\.flux-owner\\vault.flux-owner`.

При первой инициализации откройте вкладку «Ключи и резервные копии», экспортируйте открытый конфиг `flux-public-keys.json` и примените его к исходникам Flux кнопкой «Закрепить открытые ключи». Исходные public-константы изначально пустые: пока конфиг не закреплён и Flux не собран с ним, вход владельца и проверка лицензий/обновлений не активируются. Передайте только JSON сборщику, если сборку выполняет другой человек. В конфиге только открытые ключи, закрытых ключей там нет. Соберите и разверните Flux и сервер с тем же конфигом, затем установите эту первоначальную сборку вручную.

В конфиге три основных открытых ключа: `license` проверяет лицензии и списки отзыва, `update` проверяет подписи обновлений, `owner` подтверждает вход владельца на сервер. `ownerBackup` — дополнительный открытый ключ для восстановления входа из отдельной резервной копии. Храните основной и запасной `.flux-owner` зашифрованными и отдельно друг от друга. Потеря закрытого ключа обновлений требует отдельного перехода на новые ключи и первоначальной сборки клиентов.

## Лицензии и обновления

Для активации сотрудников администратор Flux формирует запрос лицензии и передаёт его владельцу. Вставьте запрос, проверьте компанию и список сотрудников, выберите срок и выпустите лицензию; верните полученный код администратору для ввода в Flux. Для публикации обновления выберите Windows EXE Flux, укажите новую версию и описание, подключитесь к HTTPS-серверу компании под учётной записью владельца и подтвердите публикацию. Приложение проверяет файл, подписывает его закрытым ключом `update` и загружает на сервер. Клиенты принимают обновления только с действительной подписью закреплённого открытого ключа.

Flux-Owner не предоставляет автоматическое самообновление этого инструмента: новый EXE Flux-Owner устанавливается владельцем вручную. Описанный процесс публикации обновляет клиентский Flux для сотрудников.

## Сборка из исходников

Требуются Node.js и зависимости из `package-lock.json`:

```sh
npm ci
npm run build
npm test
npm run portable -- -c.win.signAndEditExecutable=false
```

Команды запускаются из `tools/flux-owner`. `npm test` проверяет хранилище, public-конфиг, лицензии `FLUX2`, отзывы `FLUXREV1` и подписи обновлений на совместимость с Flux из этого же репозитория. Проверки используют временные файлы и случайные ключи и удаляют временную папку после завершения. Portable-артефакт создаётся в `release/`.
