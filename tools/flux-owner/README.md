# Flux Владелец

Локальное приложение владельца для выдачи лицензий и подписи обновлений Flux. Вход подтверждается закрытым ключом с этого компьютера: обычного логина сотрудника у Flux Owner нет. Закрытые ключи остаются у владельца; сборщику Flux передают только открытый конфиг.

## Первый запуск

Запустите `Flux-Owner-1.0.1-x64.exe` в Windows. Программа хранит основное зашифрованное хранилище в `%USERPROFILE%\\.flux-owner\\vault.flux-owner`.

1. Придумайте пароль основного хранилища и другой пароль запасного ключа. Каждый пароль должен быть не короче 12 символов; Flux Owner попросит повторить оба для проверки. Это пароли защиты локальных файлов, а не логины для Flux.
2. В диалоге сохранения выберите место для зашифрованной копии `.flux-owner`, лучше на отключаемом носителе. Запасной ключ имеет отдельный пароль. Держите его отдельно от файла и основного хранилища.
3. После создания приложение откроет «Ключи и резервные копии». Экспортируйте `flux-public-keys.json` и передайте его тому, кто собирает Flux. Это файл только с открытыми ключами; он не позволяет подписывать документы, выпускать лицензии или входить владельцем.
4. Соберите Flux с этим конфигом и вручную установите первоначальную сборку на сервере компании и рабочих местах. Затем подключитесь к серверу через Flux Owner и выпускайте лицензии сотрудникам.

`flux-public-keys.json` и `.flux-owner` — разные файлы. JSON можно передавать сборщику. Копия `.flux-owner` содержит закрытый ключ запасного входа владельца; её не передавайте и не помещайте в исходники или на сервер.

## Как работает вход владельца

Flux Owner не просит придумать необычный логин. При входе он разблокирует локальный закрытый ключ, подписывает одноразовый запрос сервера и отправляет подпись. Сам закрытый ключ и пароль хранилища серверу не передаются. Для удалённого сервера используется HTTPS; на этом компьютере можно подключиться к `http://localhost:3000`.

Основной и запасной файлы используют разные пароли, заданные при первом запуске. Для сохранённого тогда запасного `.flux-owner` нужен пароль запасного ключа. В блоке «Войти с запасным ключом» можно открыть его временно для входа, сохранив основное хранилище лицензий и обновлений. Файл `flux-public-keys.json` для входа не используется.

В `flux-public-keys.json` ключ `license` проверяет лицензии и отзывы, `update` — подписи обновлений, `owner` — вход владельца. `ownerBackup` — открытая часть отдельного запасного ключа входа. Потеря закрытого ключа обновлений требует перехода на новые ключи и первоначальной сборки клиентов.

## Лицензии и обновления

Администратор Flux формирует запрос лицензии и передаёт его владельцу. Вставьте запрос, проверьте компанию и список сотрудников, выберите срок и выпустите лицензию; полученный код верните администратору для ввода в Flux. Для публикации обновления выберите EXE Flux, укажите версию и описание, подключитесь к серверу компании и подтвердите публикацию. Приложение проверяет файл, подписывает его ключом `update` и загружает на сервер.

Flux Owner не обновляет себя автоматически: новый EXE устанавливается владельцем вручную. Публикация обновляет клиент Flux для сотрудников.

Подробные шаги: [docs/owner-first-run.md](../../docs/owner-first-run.md).

## Сборка из исходников

Требуются Node.js и зависимости из `package-lock.json`:

```sh
npm ci
npm run build
npm test
npm run portable -- -c.win.signAndEditExecutable=false
```

Команды запускаются из `tools/flux-owner`. `npm test` проверяет хранилище, public-конфиг, лицензии `FLUX2`, отзывы `FLUXREV1` и подписи обновлений на совместимость с Flux из этого же репозитория. Проверки используют временные файлы и случайные ключи и удаляют временную папку после завершения. Portable-артефакт создаётся в `release/`.
