# Flux Владелец

Отдельная программа владельца для выдачи лицензий и подписи обновлений Flux. Пароль открывает зашифрованные ключи на вашем компьютере; это не пароль сотрудника и не пароль базы данных. Закрытые ключи и этот пароль серверу не передаются.

## Первый запуск и замена потерянных ключей

1. Запустите `Flux-Owner-1.1.0-x64.exe`. Выберите создание ключей. Если прежний пароль утерян, откройте мастер создания новых ключей; старое хранилище сохранится отдельно.
2. Задайте один пароль от 12 символов и повторите его. Этот пароль защищает новое рабочее хранилище и обе копии нового комплекта. У старых файлов остаются их прежние пароли.
3. Выберите папку для комплекта восстановления, желательно на отдельном носителе. Программа создаст внутри отдельную папку и не заменит имеющиеся файлы.
4. Создайте комплект и введите пароль ещё раз. Программа проверит повторное открытие рабочего файла и обеих резервных копий.
5. Передайте сборщику **только `flux-public-keys.json`**. Пароль и файлы `.flux-owner` не передавайте.
6. Дождитесь сборки Flux с этими публичными ключами. Установите её вручную на сервере и рабочих местах. При смене ключей прежние лицензии нужно перевыпустить; прежние подписи обновлений не подходят к новым ключам.

Рабочее хранилище: `%USERPROFILE%\.flux-owner\vault.flux-owner`. Прежний файл при замене копируется без изменений в `%USERPROFILE%\.flux-owner\previous`. Программа не может восстановить забытый пароль старого зашифрованного файла.

## Что находится в комплекте

| Файл | Для чего нужен |
| --- | --- |
| `Flux-Owner-Полная-копия.flux-owner` | Восстановить все ключи: лицензии, обновления и вход. |
| `Flux-Owner-Аварийный-вход.flux-owner` | Временный запасной вход владельца. Не выпускает лицензии и не подписывает обновления. |
| `flux-public-keys.json` | Публичные ключи для сборки Flux. Его можно передать сборщику. |
| `Как-пользоваться.txt` | Инструкция, без пароля и закрытых ключей. |

Копии используют единый пароль, заданный для этого комплекта. Сохраните пароль отдельно от файлов. После выпуска лицензий и обновлений экспортируйте свежую полную копию: исходный комплект содержит реестр на момент создания. Смена пароля рабочего файла не меняет пароль уже сохранённых копий.

## Восстановление и обычный вход

При следующем запуске введите пароль рабочего хранилища. Для полной копии используйте восстановление: введите пароль выбранной копии и новый пароль рабочего файла. Старый рабочий файл будет сохранён отдельно. Для аварийного файла выберите временный аварийный вход: он не заменит основной файл. У резервных файлов, созданных прежними версиями, мог быть отдельный пароль.

`flux-public-keys.json` не подходит для входа: закрытых ключей в нём нет. В новом комплекте поле `license` проверяет лицензии и отзывы, `update` — подписи обновлений, `owner` — обычный вход, `ownerBackup` — аварийный вход.

## Подключение, лицензии и обновления

Подключение владельца использует HTTP(S)-адрес работающего сервера Flux, например `https://flux.company.example` или локально `http://127.0.0.1:3000`. Адрес `mysql://...` указывается в настройках подключения к БД самого Flux; он не является адресом веб-сервера. Публичные ключи серверной сборки должны совпадать с комплектом владельца.

Администратор Flux передаёт запрос лицензии. Вставьте запрос, проверьте компанию, сотрудников и срок. Выданный код верните администратору для установки. Для обновления выберите EXE Flux, укажите версию и описание, подключитесь к серверу и подтвердите публикацию. Программа проверяет файл, подписывает его и загружает через сервер в БД. Flux-Owner обновляется вручную отдельным EXE.

## Сборка

Из `tools/flux-owner`: `npm ci`, `npm test`, `npm run build`. Windows portable собирается отдельным GitHub Actions `build-owner.yml` и публикуется в этом же репозитории под тегом `owner-v<версия>`. Сборка Owner не пересобирает Flux и не заменяет его публичные ключи. Проверки используют случайные временные ключи и удаляют их после завершения.
