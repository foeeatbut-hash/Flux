# Проверка API E3.series для Flux

Отдельный скрипт, не зависит от Flux. Подключается к запущенному E3 через COM,
пробует всё, что понадобится мосту E3Flux, и записывает журналы. По журналам
мост пишется сразу, без второго круга: видно, какие имена вызовов в вашей версии
E3 работают, а какие нет, и что вернул каждый вызов.

Ничего устанавливать не нужно: нужен только Windows PowerShell 5.1 (он есть в
каждой Windows 10 и 11).

## Что подготовить

1. Откройте E3.series и **ТЕСТОВЫЙ проект или его копию**. Лучше такой, где есть
   хотя бы один пустой лист и несколько устройств. Рабочий проект не берите.
2. Проект должен быть открыт на запись и не заблокирован другим пользователем.
3. Закройте в E3 все диалоговые окна: пока диалог открыт, E3 отвечает на вызовы
   «занят», и проверка получится пустой.
4. По желанию выделите в E3 какой-нибудь объект: скрипт проверит, видно ли
   выделенное.

## Запуск

Сначала распакуйте архив целиком в обычную папку (например, на рабочий стол): из окна архива
`run.cmd` не запустится. Затем двойной щелчок по `run.cmd`. Скрипт покажет имя проекта и попросит ввести `Y`.
Любой другой ответ — выход, ничего не изменится.

Параметры (дописываются после `run.cmd` в командной строке):

| Параметр | Что делает |
|---|---|
| `-SolutionName Имя` | Имя типового решения (компонент, блок или символ из базы E3) для проверки вставки. По умолчанию `Клапан_К24_КП2`. Если такого нет, проба сама попробует «клапан_DIx2_DOx2», затем «датчик_DI_условный_ДГП_2» и напишет в сводке, какое взято; можно указать любое своё существующее. |
| `-CatalogOnly` | Только проверка «Каталога по API» (опрос выделения в базе E3), без подтверждения Y; в меню вопроса — пункт «К». |
| `-PlaceOnly "имя символа"` | Режим «только разместить» без вопроса (см. выше). |
| `-NamesFile e3-names.txt` | Проверка «по списку названий» (раздел ниже): ТОЛЬКО ЧТЕНИЕ, без подтверждения Y, проект не нужен. |
| `-PlaceSample N` | Только вместе с `-NamesFile`: поставить первые N найденных названий на временный лист и снять картинку листа (с подтверждением Y). |
| `-NoConfirm` | Не спрашивать подтверждение и выбор экземпляра E3. |
| `-KeepSheet` | Не удалять временный лист в конце, чтобы посмотреть его глазами. |
| `-ProcessId 1234` | Номер процесса E3, если запущено несколько. Без него скрипт покажет список и спросит. |
| `-OutDir папка` | Куда писать журналы. По умолчанию рядом со скриптом. |

Работа занимает от нескольких минут до четверти часа: зависит от размера проекта
и от того, сколько вариантов имён не подошло. Окно закрывать не надо.

## Режим «только разместить»

Если нужно просто поставить одно изделие на открытый лист, не запуская полную проверку:

1. Откройте в E3 проект и тот лист, на который нужно поставить изделие.
2. Запустите `run.cmd`. Перед подтверждением скрипт спросит: «Разместить один символ на открытом листе? Введите имя
   символа (как в базе символов E3, поле «Имя символа»)». Введите имя символа и нажмите Enter. Просто Enter — идти к полной проверке.
   То же без вопроса: `run.cmd -PlaceOnly "имя_символа"`.
3. Скрипт покажет активный лист и точку, спросит `Y` и поставит ОДИН символ (`Symbol.Load` + `Symbol.Place`; успех — только
   если на листе появился новый символ). Если символа нет в базе символов, в сводке так и будет сказано, и скрипт попробует
   запасные планы по компоненту с тем же именем (`PlacePart`, затем `Device.Create`; устройство без символа не удаляется). Больше он ничего не делает: не создаёт
   временный лист, не пишет атрибуты, не удаляет, не трогает базу, не сохраняет проект.
4. В конце он напишет, что вставлено (номер устройства, обозначение, лист, координаты) и каким вызовом. Отменить можно
   обычным `Ctrl+Z` или `Delete` в E3.

Имя вводится с клавиатуры кириллицей; введённая строка и коды её символов пишутся в `log.txt`. Если консоль испортила
буквы (появились знаки `?`), создайте рядом со скриптом файл `place-name.txt` (UTF-8) с одним именем символа и запустите
снова либо используйте `-PlaceOnly "имя"`.

### Блоки: файл .e3p/.e3s и подсхема из базы

Единица вставки — БЛОК (готовый фрагмент схемы), а не только символ. Вопрос принимает три вида ввода:

- имя символа: `Symbol.Load` + `Symbol.Place`, в отчёте «вставлен символ»;
- имя подсхемы из базы E3: запасные планы `Job.LoadPart` + `Sheet.PlacePart`, в отчёте «вставлена подсхема/блок из базы»;
- путь к файлу `.e3p`/`.e3s` (можно перетащить в окно, кавычки снимаются; имя файла без пути ищется рядом со скриптом):
  `Job.ImportDrawing(путь, 1, x, y)` на активный лист в свободной точке, затем `ImportDrawingEx` с flags 0.
  Успех — ненулевой ответ И рост числа устройств, блоков или символов на листе (до/после: `GetAllDeviceIds`, `GetBlockIds`,
  `Sheet.GetSymbolIds`). В отчёте: сколько устройств и символов добавилось, их id и имена, лист символов, вызов.
  Ничего не удаляется и не сохраняется.

## Проверка по списку названий

Решение владельца: «Название схемы» типового решения в классификаторе — это имя блока в базе E3, поэтому выделять строки в базе
не нужно: Flux спрашивает E3 по имени. Эта проверка отвечает на вопросы, которые остались открытыми: есть ли такие имена в
базе, чем они там являются (символ, компонент, подсхема/блок), какой у них габарит без вставки, как их поставить и как снять
картинку листа для предпросмотра.

**Как запустить**

1. Во Flux: E3Flux, «Типовые решения», тихая кнопка **«Скачать названия для пробы»**. Скачается `e3-names.txt`: по одному
   названию схемы в строке, UTF-8 с BOM, без снятых решений, пустых названий и повторов (повтор считается без учёта регистра).
2. Положите файл рядом с `run.cmd` (или укажите полный путь) и откройте E3.series. Проект для чтения не нужен.
3. Запустите: `run.cmd -NamesFile e3-names.txt`. Подтверждение Y не спрашивается: этот режим только читает.
4. Дополнительно, на ТЕСТОВОМ проекте (копии): `run.cmd -NamesFile e3-names.txt -PlaceSample 5` — после чтения скрипт покажет
   проект и спросит Y, создаст временный лист `__flux_names__`, поставит первые 5 найденных названий, снимет картинку листа и
   удалит всё созданное. Проект не сохраняется.

**Что делает чтение (только чтение; в проект ничего не вставляется, `Job.LoadPart` не вызывается — он подгружает деталь в проект)**

Для каждого названия по порядку, до первого попадания:

1. `Symbol.Load(имя, "1")` (затем с версией `""`): ненулевой ответ — это **символ**; габарит без размещения — `Symbol.GetArea`
   (запасной `GetPlacedArea`), ширина и высота в единицах E3.
2. `Component.Search(имя, "")` (затем `"1"`): это **компонент**; читаются имя, версия (без пробельного хвоста), тип, подтип,
   число выводов.
3. Таблицы баз компонентов и символов напрямую (ADO, режим «только чтение», нужен драйвер ACE OLEDB, как в разделе D полной
   проверки): имя ищется в текстовых колонках с «name/symbol/comp/block/имя/назв/наимен». Если таблица или колонка называется
   как блок или подсхема (`block`, `module`, `подсх`, `блок`), вид — **подсхема**; иначе по базе: символов — символ (без
   габарита), компонентов — компонент. Такие находки помечены «по таблице базы», в отчёте видны таблица и колонка.

До и после чтения скрипт считает компоненты и устройства проекта и пишет, не изменились ли они (если проект открыт).

**Что получается** (в папке журналов `e3-probe-…`):

| Файл | Что в нём |
|---|---|
| `names-report.json` | По записи на каждое название: `name`, `kind` (`symbol` / `component` / `subcircuit` / `notfound`), `via` (`api` или `db` — только по таблице базы), `width` и `height` (габарит символа), `call` (какой вызов сработал), `error` (у ненайденных — что и с какой версией пробовали), `ms` (время на имя), `details` (для компонента — тип, подтип, выводы; для находки в базе — таблица и колонка), у образцов `placed` (вызов, символы, рамка на листе). В `info` — файл, число названий, средняя скорость, проект до и после, итог размещения |
| `names-notfound.txt` | Не найденные названия, по одному в строке (UTF-8 с BOM) |
| `summary.txt`, `log.txt` | Строка «символ N · компонент/подсхема M · не найдено K», время, список не найденных; в `log.txt` — строка на каждое имя с временем в мс |
| `export\names-sheet.*` | Только с `-PlaceSample`: картинка листа с образцами (форматы png, emf, svg, pdf — снимается тот, который вышел) |

**Размещение образцов (`-PlaceSample N`)**

- Символ ставится `Symbol.Load` + `Symbol.Place`; компонент и подсхема — запасными планами (`Job.LoadPart` + `Sheet.PlacePart`,
  `Device.Create` + символ компонента, затем устройство без символа). Успех — только если на листе появился символ.
- Образцы стоят на пустом листе сеткой по 4 в ряд, слева направо и сверху вниз в порядке файла; рамка каждого — в
  `names-report.json` (`placed.area`) для обрезки общей картинки.
- Картинка листа: перебираются вызовы `Sheet.Export` / `Sheet.ExportImage` / `Job.ExportPDF` (форматы в верхнем и нижнем регистре);
  какие сработали, видно в `log.txt` («картинка листа .png: …»), в `names-report.json` (`info.placeSample.exports`) и в разделе «Экспорт листа» сводки.
- Уборка: удаляются устройства, которых не было до размещения, и временный лист (только с именем `__flux_names__`). Подсхемы,
  вставленные через `Job.LoadPart`, могут остаться в списке компонентов проекта — закройте проект **без сохранения**. `-KeepSheet`
  оставляет лист, чтобы посмотреть его глазами.

**Что прислать**: папку `e3-probe-…` (или одноимённый `.zip`) целиком. Главное в ней: `names-report.json`, `names-notfound.txt`,
`summary.txt`, `log.txt`, `trace.log`; с образцами — ещё папка `export`. Если часть названий не нашлась, пришлите и список этих
названий, и 2–3 имени, которые инженер видит в базе E3 руками (с пометкой, где: символы, изделия, блоки).

Если в `log.txt` сказано «сохранён не в UTF-8» или буквы в названиях искажены, файл пересохранён не в той кодировке: скачайте его
из Flux заново и не открывайте в Блокноте с пересохранением. В строке «Первое название» журнал пишет коды его знаков.

## Каталог по API (только чтение)

Flux берёт данные об изделиях и символах E3 по API, а не из `components.mdb`/`symbols.mdb`. Полного списка базы в API нет:
доступны только выделенные пользователем строки базы и компоненты проекта. Запуск: `run.cmd -CatalogOnly` или буква `К` в
вопросе перед `Y` (и последним разделом полной проверки).

1. Выделите символы в E3 и ничего не нажимайте: скрипт сам опрашивает 20 секунд, раз в секунду, без возврата фокуса в
   консоль (иначе выделение сбрасывается). Выделять можно в панели «База данных» окна проекта (дерево Символы/Изделия)
   ИЛИ в окне редактора базы E3. Читаются `GetDatabaseTreeSelectedSymbols`, `GetDatabaseTreeSelectedComponents`,
   `GetDatabaseTableSelectedComponents` у приложения и у УЖЕ открытого окна редактора базы
   (`Marshal.GetActiveObject("CT.DbeApplication")`; новый экземпляр не создаётся). Все методы имеют два `[out]` (имена и
   версии); пробуются четыре способа передачи: `ref=$null`, `ref=[object[]]@()`, `ref=[string[]]@()` (через
   ParameterModifier) и `[ref]` адаптера PowerShell. В `trace.log` и `log.txt` каждую секунду пишется счётчик; как только
   имена появились — опрос заканчивается и в журнале названо, какой источник и какой вариант сработал.
2. Для первых трёх символов — `Symbol.Load` и габарит (`GetArea`, `GetPlacedArea`) без размещения. Так же проверяется
   подтверждённый символ «Вентилятор_ЗТД_К».
3. Для выделенных изделий и компонентов проекта (`Job.GetAllComponentIds`, по 5 шт.) читаются имя, версия, тип, подтип,
   атрибуты, выводы и виды.

Результат: блок «КАТАЛОГ ПО API» в сводке и файл `catalog-api.json` в журналах. Редактор компонента (`EditComponent`) не открывается,
ничего не пишется и не сохраняется.

## Что скрипт делает

Проверяет по порядку, ничего не прерывая на первой ошибке:

1. **Подключение.** `CT.Application`, `CT.Dispatcher` (несколько запущенных E3),
   версия, имя и путь проекта.
2. **Листы.** Список, активный лист, формат, рабочее поле, единицы (угадываются по
   размеру поля), сетка, список форматов и смена формата.
3. **Атрибуты.** Чтение и запись на проекте, листе, устройстве, блоке, пине:
   `FLUX_PROJECT`, `FLUX_BLOCK`, `FLUX_VER`, `FLUX_ID`, `GLOBAL_ID_IN_PROJECT`;
   что бывает с атрибутом, которого нет в базе. Записанное возвращается как было.
4. **База E3.** Путь и тип, определения атрибутов, классы, компоненты, символы,
   блоки; поиск решения по имени среди всего этого и среди файлов на диске.
5. **Вставка** решения на временный лист в точку (100,100) всеми способами:
   `Sheet.PlacePart`, `Job.ImportDrawing`/`ImportDrawingEx`, `Symbol.Load`+`Place`,
   вставка компонента, создание устройства. Что появилось: устройства, символы,
   выводы, координаты, время.
6. **Обозначения.** `SetName`, установка, место, связь с `Device Designation`,
   что делает E3 при совпадении.
7. **Выводы и провода.** Выводы, цепи, создание соединения между двумя выводами,
   что происходит с ним при удалении символа, переподключение.
8. **Графика и экспорт.** Примитивы символа; экспорт временного листа в EMF, SVG,
   DXF, PDF, PNG, BMP, JPG, WMF, DWG, TIF (файлы кладутся в папку `export`).
9. **Остальные объекты.** Кабели, цепи, сигналы, клеммы, разъёмы, тексты, графика,
   группы, блоки, варианты, опции, поля, форматки: чтение и, где возможно,
   создание и удаление на временном листе.
10. **Взаимодействие.** Чтение выделенного в E3, переход к объекту, сообщение в
    окно вывода E3, активация листа.
11. **Скорость.** Время чтения атрибутов у 100 и у всех устройств, пакетное чтение.
12. **Возможности без вызова.** Есть ли `Undo`, сохранение, запуск скриптов E3
    (только по описи API, ничего не вызывается).
13. **Устойчивость.** Повторное подключение, число экземпляров E3.

Отдельно, и это самое ценное: для приложения и каждого объекта, который отдаёт
`Create*Object`, скрипт снимает **полную опись API** из библиотеки типов — все
методы и свойства с параметрами и типами (файлы `api-*.txt` и `api.json`, плюс
библиотека типов целиком). По ней видно все вызовы вашей версии E3, а не только
угаданные.

## Безопасность

- Работа идёт только на временном листе `__flux_probe__` и временных объектах; в
  конце всё удаляется. Остаток прошлой пробы удаляется в начале.
- Проект **не сохраняется**: ни один вызов сохранения не делается. Если что-то
  пошло не так, закройте проект без сохранения.
- Атрибуты проекта, которые пришлось временно записать, возвращаются как были.
  Если вернуть не получилось, скрипт скажет об этом в `summary.txt`, раздел
  «Верните вручную».
- Никаких данных наружу скрипт не отправляет: всё остаётся в папке журналов.

## Куда смотреть результат

Папка `e3-probe-<дата-время>` рядом со скриптом и **архив `e3-probe-<дата-время>.zip`**
с ней. Пришлите нам архив целиком.

| Файл | Что внутри |
|---|---|
| `summary.txt` | Сводка по-русски: что работает, что нет, что завести в базе E3, итоговая таблица «операция — какой вариант сработал». Начните с него. |
| `log.txt` | Подробный журнал: шаг, ✓/✕, время в мс, что вернул вызов или текст ошибки. Пишется по ходу: если E3 упадёт, всё до этого места сохранится. |
| `trace.log` | Метка «начинаю вызов X» перед каждым вызовом E3 и перед каждым разделом, пишется сразу на диск. Если проверка встала или E3 упал, последняя строка называет виновника. |
| `log.json`, `log.ndjson` | То же машинным языком: операция, вариант вызова, аргументы, результат или ошибка и HRESULT, время. `log.ndjson` дописывается по ходу. |
| `environment.json` | Версия E3, Windows, разрядность PowerShell, ProgID и их регистрация, найденные экземпляры E3. |
| `api.json`, `api-*.txt` | Полная опись API: методы и свойства каждого объекта. |
| `attribute-check.csv` | Каждое имя из `attributes.txt` (список владельца): есть ли в базе и на каких носителях пишется. |
| `attribute-definitions.txt`, `database-lists.txt`, `project-attributes.txt` | Списки из базы E3 и атрибуты проекта. |
| `export\` | Файлы, полученные при экспорте листа. |

## Если что-то пошло не так

- **«К E3 подключиться не удалось».** E3 не запущен или запущен от другого
  пользователя (скрипт и E3 должны работать от одного и того же). Запустите E3 и
  повторите.
- **Окно долго ничего не пишет.** Подождите 5 минут. Если не сдвинулось, закройте окно и пришлите папку журналов целиком: по последней строке `trace.log` видно, на чём встало.
- **«В E3 НЕ ОТКРЫТ ПРОЕКТ».** Откройте копию тестового проекта и запустите снова; без проекта снимается только опись API.
- **Много пометок «E3 ЗАНЯТ».** В E3 открыт диалог или идёт операция. Закройте
  окна и повторите.
- **Скрипт запущен в 32-разрядном PowerShell.** Запускайте через `run.cmd`: он
  берёт 64-разрядный.
- **Политика выполнения скриптов.** `run.cmd` запускает с `-ExecutionPolicy Bypass`
  и ничего в системе не меняет.
- **Проект закрыт.** Скрипт запишет, как E3 отвечает без проекта, и остановится.
  Это тоже полезно: запустите его один раз без проекта и один раз с проектом.

## Для разработчиков

Файлы: `e3-probe.ps1` (главный), `lib\*.ps1` (разделы), `lib\TypeInfoDump.cs`
(разбор библиотек типов, собирается Add-Type), `test\fake-e3.ps1` (подставной COM
для проверки без E3). Скрипт обязан работать в Windows PowerShell 5.1: без `??`,
`?.`, тернарного оператора, `&&` и `||`; файлы в UTF-8 с BOM. Проверка:
`node_modules/.bin/tsx scripts/test-e3-probe.ts` (в контейнере без PowerShell —
`FLUX_PWSH=<путь к pwsh>`; на Windows CI запускается в `verify-windows-shell.yml`
и дополнительно собирает C# и снимает опись настоящего COM-объекта).
