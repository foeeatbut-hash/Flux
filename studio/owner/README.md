# Раздел владельца Flux Studio (бывший Flux Owner)

**Flux Owner как отдельная программа заменён.** Весь его код — этот каталог —
входит в сборку `FluxStudio-Владелец.exe` (решение владельца от 9 ноября 2026,
этап 4а; устройство — `docs/methodology/03-programs/studio.md`). Отдельный portable
Flux Owner больше не собирается и не выпускается. Хранилище ключей прежнее: тот же
путь `%USERPROFILE%\.flux-owner\vault.flux-owner` и формат — перевыпуск лицензий и
смена закреплённых ключей не нужны. Запуск локального сервера по адресу базы
вынесен в `studio/shared` (он нужен и разработчику).

Ниже — прежнее описание функций; слова «Flux Owner» относятся к этому разделу.

## Что умеет раздел

Используйте уже
созданное хранилище владельца: повторное создание ключей потребует обновления
закреплённых публичных ключей Flux и перевыпуска лицензий.

## Подключение

В разделе «Подключение» введите URI общей MariaDB/MySQL, например
`mysql://USER:PASSWORD@HOST:3306/Flux` или
`mariadb://USER:PASSWORD@HOST:3306/Flux`. Пример вымышленный. Нужна отдельная
учётная запись приложения с необходимыми правами и TCP-доступом к базе с этого
компьютера. Настольный Flux и Flux Owner используют одну общую БД; адрес
внешнего HTTP-сервера Flux вводить или размещать не нужно.

Flux Owner запускает на компьютере локальный Flux API на loopback для работы с
общей БД. Это внутренняя часть приложения, а не отдельная служба компании.
После отключения или нового запуска Owner попросит ввести URI снова. Owner не
сохраняет его в хранилище владельца. Не отправляйте URI с настоящим паролем в
переписке или снимках экрана.

При direct DB SQL-реквизиты используются на рабочих станциях, а права учётной
записи действуют непосредственно в MariaDB/MySQL. Это не защищает абсолютно от
изменённой клиентской программы или администратора БД с достаточными правами.
Ограничивайте сетевой доступ к базе и не выдавайте приложению лишних прав.
Дополнительные детали и ограничения: [`docs/company-server.md`](../../docs/company-server.md)
и [`docs/manual-security-review-2026-10-03.md`](../../docs/manual-security-review-2026-10-03.md).

## Лицензии и обновления

Для входа владельца и публикации нужны соответствующие закрытые ключи из уже
созданного хранилища. Flux Owner публикует подписанные обновления Flux в общей
БД. Сам Flux Owner обновляется вручную отдельным portable EXE.

## Сборка и проверки

Из корня репозитория: `npm run test:studio-owner` (проверки раздела),
`npm run build:studio-owner`. Portable `FluxStudio-Владелец.exe` собирает только ручной
запуск `build-studio-owner.yml`; артефакт не публикуется в общие выпуски. Сама Studio —
Владелец обновляется вручную новым файлом.

В репозитории намеренно есть непроизводственные приватные тестовые ключи в
fixtures для изолированных проверок (в том числе синтетическое хранилище прежнего
формата `scripts/fixtures/legacy-vault.fixture.json`). Они не являются ключами владельца и не
должны использоваться для реальных лицензий, обновлений или входа.
