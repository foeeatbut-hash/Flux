# Flux — постоянные распоряжения

Этот файл читается в начале каждой сессии. Здесь только то, о чём владелец
проекта не обязан напоминать заново. Устройство кода, стиль, проверки, выпуск и
обращение с данными вынесены в skills (`.claude/skills/flux-*`) — сюда их
переписывать не надо, иначе они разойдутся.

## Методология

Единые правила программы — `docs/methodology/` (сейчас «Дизайн», следом
«Логика»). Обязательны для каждого нового экрана и каждой правки старого;
если правило мешает, его меняют там, с причиной, а не обходят на месте.

## Пул-реквест после каждого обновления

**Закончил обновление — открой пул-реквест.** Просить об этом не нужно: так
распорядился владелец проекта. Общее правило «не создавать PR без явной
просьбы» здесь не действует.

Обновление считается законченным, когда работа проверена, собрана и отправлена
в рабочую ветку `claude/custom-table-builder-design-38h1b8`.

Порядок:

1. Проверить, нет ли уже открытого PR для этой ветки, — если есть, он и
   продолжает жить, второй заводить не надо.
2. Открыть PR в `main` с русским заголовком, называющим суть, а не ветку
   («Claude/custom-table-builder-design-38h1b8» заголовком не является).
3. В теле — что сделано и почему, чем проверено и какие дефекты найдены по
   дороге. Тело объясняет причину и следствие, а не перечисляет файлы; то же
   правило, что для сообщений коммита.
4. Если выпускалась сборка — дать ссылку на выпуск.
5. Дать владельцу ссылку на PR в ответе.

Шаблона PR в репозитории нет. Появится (`.github/pull_request_template.md`) —
заполнять его разделы.

## Сводка версии для сотрудников

**Выпустил сборку — дай владельцу сводку** для поля «Список изменений» при
публикации релиза. Её видят все сотрудники, поэтому язык человеческий: что
изменилось для человека, а не что изменилось в коде. Пять–восемь строк,
поломки называются поломками, в конце — требует ли обновление действий.
Подробнее — в README, раздел «Постоянные правила работы над программой».

Уже слитый PR новую работу не отслеживает: следующее обновление — новый PR, а
ветку перед ним переставить на свежий `main`.

## Чего не должно попадать в репозиторий

- Идентификатор модели — ни в коде, ни в комментариях, ни в сообщениях коммита,
  ни в заголовках и теле PR.
- Приватный ключ лицензии: `tools/license-generator.html` исключён в
  `.gitignore` намеренно.
