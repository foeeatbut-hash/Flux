# Flux — правила для ИИ-агентов (Codex и другие, кроме Claude Code)

Этот файл читают агенты, которые ищут `AGENTS.md` (Codex и совместимые).
Claude Code читает `CLAUDE.md`; правила по смыслу одни и те же, источник
подробностей — общий: навыки `.claude/skills/flux-*/SKILL.md` и документы
`docs/`. Меняешь правило — меняй его там, где оно записано, а не копию здесь.

## Подготовка рабочей копии

- Облачный контейнер чистый: перед работой
  `CLAUDE_CODE_REMOTE=true scripts/session-start.sh` (npm ci и prisma
  generate только при изменении lock-файла и схем; без переменной скрипт
  ничего не делает). Electron ставится без бинарника — для проверок он не нужен.
- Редакторы Office (`public/genoffice`) нужны только наборам интерфейса.

## Постоянные распоряжения

- **Методология** `docs/methodology/` обязательна для каждого нового экрана и
  каждой правки старого; мешает правило — меняй его там, с причиной. Для правки
  готового экрана — словарь компонентов (раздел 5) и проверочный список
  (раздел 8) `01-design.md` плюс страница программы в `03-programs/`; уровни
  проверки — таблица в начале `04-testing.md`. Мелкая правка не тянет перевод
  экрана целиком (`README.md` методологии). Кто меняет программу, тот
  обновляет её страницу в `03-programs/`.
- **Разведка — по карте, а не обходом кода:** страница программы в
  `docs/methodology/03-programs/`, затем нужный код. Большие файлы (больше
  ~800 строк) — сначала поиск по меткам, потом нужный кусок.
- **Начало новой задачи:** `docs/plan.md` → документ проекта из него;
  E3/E3Flux — `docs/e3-integration.md`, разделы 4.3 (подтверждённые вызовы COM
  и подводные камни; сигнатуры не угадывать) и 13 (решения владельца и план
  этапов A–G).
- **Одна сессия — одна задача.** Закончил задачу — пул-реквест в `main`;
  решения и устройство записываются в документы проекта, а не остаются в
  разговоре.

## Навыки: что прочесть и когда

Это обычные файлы — открой нужный, когда дошёл до его области, а не все сразу.

| Когда | Файл |
|---|---|
| Пишешь любой код или разметку (комментарии по-русски и про «почему», токены оформления, черновики «__», формат коммита) | `.claude/skills/flux-style/SKILL.md` |
| Создаёшь файл, папку, раздел или экран; выносишь код из крупного файла | `.claude/skills/flux-architecture/SKILL.md` |
| Задача пишет в базу: импорт, захват с экрана, массовые операции, новый эндпоинт записи | `.claude/skills/flux-data-safety/SKILL.md` — обязательно |
| Перед тем как объявить работу законченной; добавляешь легко ломаемую логику | `.claude/skills/flux-verify/SKILL.md` |
| Сборка exe, версия, выпуск; обрыв git push, пропали node_modules | `.claude/skills/flux-release/SKILL.md` |
| Пул-реквест: заголовок и тело | раздел «Пул-реквест» в `.claude/skills/flux-lead/SKILL.md` (остальное там — про раздачу задач субагентам Claude, к тебе не относится) |

`.claude/agents/*.md` описывают субагентов Claude Code; из
`flux-executor.md` к тебе относятся разделы «Проверки», «Код и коммиты» и
«Контрольные точки» — кратко они повторены ниже.

## Проверки

- `NODE_OPTIONS=--max-old-space-size=8192 node_modules/.bin/tsc --noEmit` —
  смотреть код выхода, а не вывод: при нехватке памяти tsc падает молча.
- `node_modules/.bin/tsx scripts/run-checks.ts <слова области>` — наборы своей
  области, сначала на нетронутой ревизии (запомнить итог), потом после правок.
  Полный `npm run check` — один раз перед пул-реквестом. Падение, которое было
  и до тебя, — описать, не чинить.
- Тесты не отключать, не пропускать и не ослаблять.
- Интерфейс: замер (getBoundingClientRect / getComputedStyle), затем снимок
  Playwright в светлой и тёмной теме и просмотр глазами. Chromium уже стоит:
  `/opt/pw-browsers`, `playwright install` не запускать.
- Порт 3000 не занимать.

## Код и коммиты

- Новый файл — до ~400 строк (предел проверки 1200). Храповик размеров
  `scripts/test-architecture.ts` не ослаблять.
- Коммиты по смысловым кускам, сообщение по-русски — про причину и следствие,
  а не перечень файлов.
- Без force-push и без переписывания чужой истории.

## Контрольные точки

Работа может оборваться; незакоммиченное при обрыве потеряно. Долгую задачу
дели на шаги: после шага — коммит `wip: <задача> — шаг N из M: <что>` и файл
хода `.claude/progress/<имя-задачи>.md` (задание, шаги [x]/[ ], ветка, итоги
проверок «до», на чём остановился). Нашёл такой файл в начале работы — не
начинай заново, продолжай с первого невыполненного шага. В конце файл хода
удалить.

## Чего не должно попадать в репозиторий

- Идентификатор или название модели — ни в коде, ни в комментариях, ни в
  сообщениях коммита, ни в заголовках и теле PR.
- Приватный ключ лицензии: `tools/license-generator.html` исключён в
  `.gitignore` намеренно.
- Файлы владельца (классификатор, списки атрибутов, выгрузки E3, архивы) — это
  данные компании: загружаются в программу, в репозиторий не кладутся.
