# Локальные редакторы PDF и таблиц

Редактор в зеркальном Проводнике получает ссылку на файл Windows или локальный черновик Flux. Содержимое остаётся на этом компьютере: главный процесс Electron открывает редактор GenOffice над отдельной временной копией в `userData/local-office/view-*`. Сервер компании, его API и БД в этом пути не участвуют.

Каждое окно PDF/таблицы получает отдельный идентификатор Flux, независимо от внутренних счётчиков редакторов. Идентификатор закреплён за `webContents` владельца. Все вызовы, сообщения и закрытие проверяют владельца; уничтожение окна закрывает его native-сеансы и удаляет их временные файлы. Каталоги имеют ограниченные права на ОС с POSIX-правами; на Windows используются права пользовательского каталога Electron.

Временные снимки движка XLSX, его файлы восстановления и вспомогательные файлы используют отдельный контекст окна через `AsyncLocalStorage`, поэтому параллельные вызовы разных окон не переключают глобальную папку. Обычные серверные редакторы, не передающие этот контекст, сохраняют существующее поведение.

Сохранение проверяет актуальные права/лицензию и исходные идентичность и SHA-256 файла. Запись в Windows проходит через `WindowsFilesService.write` с атомарной заменой и сверкой SHA-256. Если файл изменили снаружи, исходные байты Windows остаются, редактор и его журнал правок остаются открыты: можно сохранить отдельную копию. Для таблицы проверка и запись выполняются до переключения внутреннего native-сеанса. При отказе временный исходник возвращается к предыдущему состоянию, чтобы повторная попытка не повторяла уже применённые операции.

«Сохранить как» создаёт файл рядом с исходником без замены существующего файла. Для локального черновика копия тоже остаётся черновиком Flux. PDF использует обмен запросом, вызовом сохранения и подтверждением; ожидание копии не блокирует вызовы её же редактора. Отмена и закрытие окна завершают ожидание без создания файла. Копирование таблицы сохраняет исходную native-сессию и её несохранённые правки.

### Обычное сохранение XLSX

При обычном Save редактор сохраняет исходную native-сессию и снимок книги. Запись каждый раз строится от этого исходного снимка с полным накопленным журналом правок. Редактор не пересоздаёт открытую книгу, выделение и историю Undo. Проверка SHA-256 исходного файла на диске остаётся отдельной защитой от внешних изменений: при отказе сессия и журнал остаются доступны для повтора или сохранения копии.

Перед IPC редактор фиксирует номер ревизии журнала. Успешный ответ подтверждает только эту ревизию, поэтому правка во время записи остаётся несохранённой. Отмена или ошибка ничего не подтверждает. Журнал считается грязным по номеру ревизии, даже если Undo вернул его содержимое к пустому состоянию.

Если структурные изменения требуют двух фаз, промежуточная запись использует временную native-сессию. Успех второй фазы возвращается к исходной сессии; при отмене или ошибке временная сессия закрывается, а исходный журнал остаётся грязным. Save As и CSV сохраняют свои прежние пути работы с сессией и экспортом; восстановление использует отдельный writer восстановления.

Поддерживаются PDF, XLSX и XLSM. Произвольные пути, создание файлов через внутренние диалоги GenOffice, объединение с чужими файлами и внешняя печать не принимаются этим IPC. Функции, которым нужен отдельный выбор файла или места выгрузки, требуют отдельной интеграции через capability Проводника; отказ сообщает об этом прямо. Восстановительная копия таблицы находится внутри приватного каталога сеанса; интерфейс восстановления после аварийного завершения приложения отдельной функцией пока не реализован.

Проверки:

- `node --import tsx scripts/test-local-office-sessions.ts`: владение, поддельные пути, лицензия после native-сохранения, CAS, копия черновика, отмена и уничтожение окна.
- `node --import tsx scripts/test-local-office-native.ts`: настоящие PDF и Rust XLSX, изменение ячейки и сохранение формул, сохранность других частей книги, SaveAs после CAS-отказа, конкурентные снимки разных окон, пометка PDF в копии и исходнике. Нужны собранные native-редакторы и их synthetic fixtures из `scripts/officeHarness.ts`.

Эти проверки выполняют файловые операции и native-движки в Linux. Поведение окон, диалогов и прав пользовательской папки на Windows дополнительно проверяется в portable-сборке.
