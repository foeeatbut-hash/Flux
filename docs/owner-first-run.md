# Первый запуск Flux Owner

Flux Owner — отдельная локальная программа для владельца Flux. Она не входит в установщик сотрудников и не использует обычный логин из списка сотрудников. Вход подтверждается закрытым ключом: программа подписывает одноразовый запрос сервера. Пароль только разблокирует ключ на компьютере владельца; пароль и закрытый ключ серверу не отправляются.

## Создание хранилища

1. Создайте пароль основного хранилища и отдельный пароль запасного ключа. Оба должны содержать не менее 12 символов. Повторите каждый пароль в поле подтверждения. Пароли защищают файлы ключей и не являются логинами Flux.
2. В появившемся окне сохраните зашифрованную резервную копию `.flux-owner` на отдельный отключаемый носитель. Запасная копия содержит ключ для восстановления входа. Сохраните её пароль отдельно от файла.
3. Flux Owner сохранит основное хранилище на этом компьютере и сразу откроет экспорт открытых ключей. Сохраните файл `flux-public-keys.json`.
4. Передайте сборщику только `flux-public-keys.json`. Соберите Flux с ключами из конфига и вручную установите первоначальную версию на сервере компании и рабочих местах. После установки подключитесь к серверу из Flux Owner и выдавайте лицензии.

## Какие файлы можно передавать

- `flux-public-keys.json` содержит только открытые ключи. Он предназначен для первоначальной сборки Flux и может передаваться сборщику.
- `.flux-owner` из диалога первого запуска — зашифрованная копия запасного закрытого ключа владельца. Держите её отдельно и не передавайте сборщику, не добавляйте в исходники и не загружайте на сервер.
- Основной файл хранилища остаётся в `%USERPROFILE%\\.flux-owner\\vault.flux-owner`. Не удаляйте его после сохранения резервной копии.

## Восстановление и вход

Для запасного `.flux-owner`, сохранённого при первом запуске, нужен **пароль запасного ключа**. Пароль основного хранилища этот файл не открывает. В Flux Owner выберите «Войти с запасным ключом», введите его пароль и нажмите «Открыть запасной ключ без замены». После открытия появится «Сервер компании»; основной файл с ключами лицензий и обновлений остаётся на месте. Запасной ключ предназначен только для входа: он не заменяет ключи подписи лицензий и обновлений.

В самом Flux выберите «Вход владельца», затем основной или запасной `.flux-owner` и пароль **именно выбранного файла**. Кнопка показа пароля помогает проверить раскладку; включённый Caps Lock отмечается отдельно. `flux-public-keys.json` для входа не подходит: это открытая конфигурация сборки.

При переносе полного основного хранилища откройте Flux Owner, выберите восстановление из полной резервной копии `.flux-owner`, укажите пароль копии и задайте пароль для хранения на новом компьютере. Уже экспортированные копии сохраняют свой прежний пароль после смены пароля локального хранилища. Для обычного входа откройте вкладку «Сервер компании», укажите адрес сервера и нажмите «Войти владельцем». Удалённый сервер требует HTTPS.

Если в компании есть только MySQL/MariaDB или PostgreSQL, настройте в Flux на экране входа «Подключение → Общая база данных». Вставьте строку подключения к БД и перезапустите Flux. Встроенный сервер Flux подключится к общей БД; Flux Owner на этом же компьютере подключается к нему по `http://localhost:3000`. Строка `mysql://…` — адрес базы данных, её не вводят в поле веб-сервера Flux Owner. Сохранение настройки не проверяет доступность БД в сети; результат подключения виден после запуска Flux.

Если резервная копия или её пароль недоступны, запасной путь входа восстановить нельзя. Храните копию и пароль раздельно, но оба — в контролируемом владельцем месте.
