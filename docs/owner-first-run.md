# Первый запуск Flux Owner

Flux Owner — отдельная программа владельца. Пароль открывает локальные ключи, а вход на сервер подтверждается подписью одноразового запроса. Пароль и закрытые ключи серверу не отправляются.

## Настройка в версии 1.1.0

1. Нажмите создание новых ключей. Задайте один пароль от 12 символов и повторите его. Сохраните пароль отдельно от резервных файлов.
2. Выберите папку для комплекта восстановления. Лучше отдельный отключаемый носитель. Программа создаст собственную подпапку и сохранит полную копию, аварийный ключ, публичный JSON и инструкцию.
3. Подтвердите создание. Если на компьютере уже было хранилище, прежний зашифрованный файл сохранится без изменений в `%USERPROFILE%\.flux-owner\previous`. Смена ключей требует новой сборки Flux и перевыпуска лицензий.
4. Повторно введите пароль: программа проверит чтение рабочего файла и обеих копий с диска.
5. Передайте сборщику **только `flux-public-keys.json`** из созданной папки. Файлы `.flux-owner` и пароль остаются у вас.
6. После получения публичного JSON сборщик подключит ключи к Flux и отдельно соберёт Flux. До установки этой сборки сервер использует прежние публичные ключи.

Рабочее хранилище находится в `%USERPROFILE%\.flux-owner\vault.flux-owner`. Для обычного входа достаточно его пароля. Создавать новые ключи при каждом запуске не нужно.

## Какую копию использовать

**Полная копия** `Flux-Owner-Полная-копия.flux-owner` восстанавливает ключи лицензий, обновлений и входа. Используйте восстановление полной копии, введите пароль этой копии и задайте новый пароль рабочего файла. Прежний рабочий файл будет сохранён отдельно. После выдачи лицензий экспортируйте свежую полную копию, чтобы сохранить актуальный реестр.

**Аварийный вход** `Flux-Owner-Аварийный-вход.flux-owner` открывается временно и не заменяет основное хранилище. Он предназначен для входа владельца; выдача лицензий и подпись обновлений ему недоступны.

У обоих файлов нового комплекта один пароль. **Старые** резервные файлы сохраняют свои прежние пароли: отдельный пароль запасного ключа из версий 1.0.x не меняется после установки 1.1.0. Смена пароля рабочего хранилища не меняет ранее экспортированные копии. Забытый пароль невозможно узнать из зашифрованного файла.

`flux-public-keys.json` содержит только публичные ключи и не открывает хранилище. Его передают для сборки, а не для входа.

## Адрес сервера и БД

Поле сервера владельца принимает адрес работающего сервера Flux: например `https://flux.company.example` или на том же компьютере `http://127.0.0.1:3000`. Для удалённого подключения нужен HTTPS. Публичные ключи сборки сервера должны совпадать с комплектом владельца.

Строка `mysql://…` или `postgresql://…` задаёт подключение к базе данных самого Flux, а не вход владельца. Если компания располагает только БД, в самом Flux настройте «Подключение → Общая база данных» и перезапустите Flux. Owner подключается к запущенному серверу Flux, который уже работает с этой БД. Доступность корпоративной БД проверяется после запуска в сети компании.
