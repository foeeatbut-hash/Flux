# Первый запуск Flux Owner

Для текущего подключения нужны Flux `1.20.4` и Flux Owner `1.2.1` в portable EXE. Положите оба файла в одну папку. В Flux Owner откройте уже созданное новое хранилище его паролем. Не создавайте ключи повторно: создание нового комплекта меняет ключи и требует обновления Flux и повторного выпуска лицензий.

## Подключение к общей MariaDB

1. Откройте раздел «Подключение».
2. Введите URI базы, например `mysql://USER:PASSWORD@HOST:3306/Flux`. Используйте имя отдельной учётной записи приложения, её пароль и адрес MariaDB, доступный по TCP с этого компьютера.
3. Нажмите «Подключиться». Flux Owner найдёт Flux portable в той же папке и запустит локальную серверную часть без окна. Если Flux не найден, выберите его EXE в появившемся диалоге.
4. После входа нажмите «Открыть Flux как владелец», чтобы открыть рабочий интерфейс Flux.

Пароль внутри URI скрыт в поле и очищается после успешного подключения. URI SQL не является HTTPS URL. Для подключения Owner к уже развёрнутому общему HTTPS API укажите его `https://...` адрес вместо SQL URI.

Для обычной работы самого настольного Flux сохраните общую базу в его настройках подключения и перезапустите программу. Такой режим не требует установки Node.js, SSH или службы на NAS.

## Доступ к MariaDB

Проверьте, что MariaDB принимает TCP-подключения на порту `3306` с компьютера пользователя и что учётной записи приложения разрешён доступ к нужной базе. URI-пример `mysql://USER:PASSWORD@HOST:3306/Flux` не содержит реальных реквизитов; замените все значения своими и не отправляйте URI в переписке или снимках экрана.

Страница phpMyAdmin, показывающая подключение к `localhost` через UNIX socket, подтверждает только локальный доступ phpMyAdmin. Она не доказывает сетевой TCP-доступ и права удалённого подключения. `root@localhost` — локальная административная запись MariaDB, а не пользователь приложения; используйте отдельную запись с необходимыми правами.

## Хранилище и обновления

Используйте пароль уже созданного нового хранилища владельца. Закрытые ключи остаются в локальном хранилище; URI содержит только реквизиты MariaDB и не заменяет пароль Owner. Сохраняйте резервные копии хранилища отдельно и защищайте их пароль.

Публикуйте Flux обновления существующим комплектом ключей через Owner. Flux Owner обновляется вручную отдельным portable EXE. Старые сборки Flux с другими открытыми ключами требуют ручной установки сборки с актуальными ключами и повторного выпуска лицензий.

## Полная копия и аварийный вход

Рабочий файл хранится в `%USERPROFILE%\.flux-owner\vault.flux-owner`. При обычном запуске достаточно открыть его паролем. Публичный `flux-public-keys.json` нужен для сборки и не подходит для входа.

`Flux-Owner-Полная-копия.flux-owner` восстанавливает все ключи и реестр. Выберите восстановление полной копии, введите пароль копии и задайте пароль рабочего файла. Прежнее хранилище сохраняется отдельно в папке `previous`. После выдачи лицензий и публикации обновлений экспортируйте свежую полную копию, чтобы сохранить актуальный реестр.

`Flux-Owner-Аварийный-вход.flux-owner` открывается временно и не заменяет рабочий файл. Этот ключ подтверждает запасной вход владельца, но не выпускает лицензии и не подписывает обновления.

У двух копий нового комплекта один пароль. Старые копии версий 1.0.x сохраняют прежние пароли, включая отдельный пароль запасного ключа. Смена пароля рабочего файла не меняет ранее экспортированные копии. Забытый пароль невозможно узнать из зашифрованного файла.
