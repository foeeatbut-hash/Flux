# Окна Flux вместе с окнами Windows

Состояние: простой вариант написан и проверен на подставном Electron и в
Chromium (PR 165, 12 ноября 2026); **на Windows не проверялся** — проверка
владельцем обязательна (раздел «Проверка владельцем на Windows» ниже).
Вариант с подчинёнными окнами — план после выпуска. Решение владельца
9 ноября 2026; порядок: до «Выпуска» рабочих версий (`README.md`, раздел
«Порядок внедрения»).

## Что не так сейчас

Главное окно Flux — одно обычное окно Windows на весь экран; разделы — рамки
внутри него. Нажатие на пустой стол Flux поднимает всё главное окно над Word,
Excel и Проводником: открыл раздел, потом Word, щёлкнул по столу — Word «ушёл
за рабочий стол Flux».

## Как должно быть (запись владельца)

1. Стол Flux ведёт себя как рабочий стол Windows: нажатие по пустому месту
   стола **не поднимает** Flux над окнами Windows.
2. Окна разделов Flux **остаются окнами Flux**: не выходят за пределы
   программы, не становятся отдельными окнами Windows (нет своих кнопок на
   панели задач Windows, нет в Alt+Tab, не уводятся за пределы экрана Flux).
3. Окно раздела Flux, на которое нажали, выходит вперёд над Word и Excel;
   окна Windows, на которые нажали, выходят вперёд над Flux. Порядок
   — как у обычных окон.
4. При запуске Flux стол виден поверх всего; повторный запуск, «Показать
   Flux» в трее, нажатие на уведомление, Ctrl+Alt+D выводят Flux вперёд
   намеренно. Win+D не прячет стол Flux.
5. Выключатель в «Параметры → Мониторы» возвращает прежнее поведение.

## Как устроить (направление, не ТЗ)

Присланный патч (`electron/desktopLayer.ts`, `electron/zOrder.ts`: стол на
дно через `SetWindowPos(HWND_BOTTOM)` и `setFocusable(false)`) берётся как
основа для пункта 1, но разделы в нём — отдельные окна Windows, что
противоречит пункту 2. Варианты для пункта 3, выбрать замером на Windows:

- **Окна-«подчинённые» главного окна** (owned windows Win32 / `parent` в
  Electron): каждое окно раздела — своё окно, но принадлежит Flux — не
  попадает на панель задач и в Alt+Tab, сворачивается вместе с Flux,
  передвигается только в пределах экрана Flux, а по глубине может стоять
  между окнами Windows. Даёт пункт 3 полностью. Цена: перенос рамок в
  отдельные окна (перетаскивание между разделами, общий стор, фокус).
- **Весь Flux выходит вперёд при нажатии на любое его окно** (как сейчас,
  только стол больше не поднимается от пустого места). Проще, но при
  нажатии на раздел Flux перекрывает Word целиком.

Решение владельца (11 ноября 2026): до выпуска — второй, простой вариант;
первый — отдельным шагом после выпуска, с проверкой на Windows по ходу.
Прежняя рекомендация руководителя — первый вариант, если проверка на Windows
подтвердит поведение подчинённых окон (масштаб, несколько мониторов,
развёрнутые окна).

## Внедрено: простой вариант (12 ноября 2026)

Устройство — страница оболочки, раздел «Нажатие по столу и окна Windows»
(`docs/methodology/03-programs/shell.md`). Коротко:

- Только средствами Electron, без нативного помощника и PowerShell: пока
  главное окно не активно, оно следит за указателем; над пустым столом оно
  становится неактивируемым (`setFocusable(false)`, WS_EX_NOACTIVATE) — щелчок
  по столу не поднимает Flux над Word и Excel. Над окном раздела, панелью
  задач Flux, Пуском, значком или виджетом стола — окно обычное, щелчок
  выводит весь Flux вперёд, как раньше.
- Намеренный выход вперёд (запуск, повторный запуск, «Показать Flux» в трее,
  нажатие на уведомление, Ctrl+Alt+D, возврат после захвата) идёт через одну
  функцию `bringToFront` (`electron/windowForeground.ts`): сначала окно снова
  активируемо, потом `restore/show/focus`.
- Выключатель «Нажатие по столу не выводит Flux поверх других программ» в
  «Параметры → Мониторы»; включён по умолчанию, хранится в
  `display-workspace.json` (ключ `deskStaysBack`, пишется только когда
  выключен). Выключен — слежения нет, поведение прежнее. Не Windows — режим не
  включается и строка в параметрах не показывается.
- Проверки: `test-desk-focus-native` (порядок вызовов, выключатель, доверие
  IPC, частота, все пути «вперёд»), `test-desk-focus-ui` (Chromium: пустой
  стол, значок, окно раздела, панель — верные сигналы; строка в параметрах в
  обеих темах).

### Что осталось (план «после выпуска»)

- Win+D, панель задач Flux поверх развёрнутых окон, «подчинённые» окна
  разделов (первый вариант выше) и опускание стола на дно (`HWND_BOTTOM`,
  помощник PowerShell) — в простой вариант не вошли.
- Окна нативных программ Flux (отдельные BrowserWindow) в простой вариант не
  входят: они ведут себя как раньше.
- Пока Flux активен, любое нажатие обычное: «не поднимать» относится только к
  нажатию по столу, когда Flux уже стоит позади другой программы.

### Что не проверено и чем это грозит

В контейнере Windows нет: `setFocusable` проверен только на подставном
Electron (какие вызовы и в каком порядке), настоящий WS_EX_NOACTIVATE — нет.
Побочные эффекты `setFocusable` на Windows, которые обязан проверить
владелец (чинить вслепую не надо; при любой из них выключатель возвращает
прежнее поведение):

- пропадает или мигает кнопка Flux на панели задач Windows, пока указатель
  над пустым столом (Electron может заодно менять скрытие с панели задач);
- Flux пропадает из Alt+Tab, пока окно неактивируемо;
- кнопка Flux на панели задач Windows не восстанавливает свёрнутое окно
  (в модели свёрнутое и скрытое окно всегда активируемо — проверить, что это
  так и на деле);
- первое наведение после потери активности: окно считает, что указатель не над
  столом, пока оно не увидит движение над столом (иначе окно осталось бы
  неактивируемым вслепую) — первый щелчок без движения поднимет Flux;
- два монитора с разным масштабом: наведение на пустой стол на втором
  мониторе.

### Проверка владельцем на Windows

Включённый выключатель, Flux запущен, открыты Word и Flux:

1. Развёрнутый Word поверх Flux (свернуть Flux нельзя — он за Word): щёлкнуть
   по Word, подвести указатель к видимому краю Flux и щёлкнуть по **пустому
   месту стола** — Word остаётся перед Flux.
2. Щелчок по **окну раздела** Flux — Flux выходит вперёд над Word целиком.
3. Щелчок по **значку стола**, по панели задач Flux, по «Пуск» — Flux выходит
   вперёд.
4. Рамка выделения и меню правой кнопки на столе работают, пока указатель над
   пустым столом неактивного Flux.
5. Значок в трее и «Показать Flux»; нажатие на уведомление; Ctrl+Alt+D;
   повторный запуск Flux — каждый раз Flux выходит вперёд, и затем обычные
   нажатия работают.
6. Два монитора (включая разный масштаб): пункты 1–3 на каждом мониторе.
7. Кнопка Flux на панели задач Windows и Alt+Tab: Flux на месте, не мигает
   при движении указателя по столу и окнам, из свёрнутого состояния
   возвращается.
8. Выключатель снят — прежнее поведение (щелчок по столу поднимает Flux).

## Нюансы, без которых не внедрять

- **Пуск и панель задач Flux** сейчас внутри главного окна: стол на дне —
  развёрнутый Word закроет их, и до Flux не добраться. Панель задач Flux —
  отдельная полоса, которую развёрнутые окна не перекрывают (как панель
  задач Windows); Пуск и всплывающие панели трея — поверх всех окон.
- Разделы «одним окном» (Почта) выводят вперёд уже открытое окно, а не
  открывают второе.
- Перетаскивание и связи между разделами («открыть рядом», переход с
  подсветкой) — проверить и при необходимости связать заново, если разделы
  станут отдельными подчинёнными окнами.
- Помощник PowerShell (опускание стола на дно) может быть запрещён
  политикой компании: запасной режим — стол просто не активируется от
  нажатия; проверить, что запасной режим рабочий.
- Путь вернуться к Flux, пока стол на дне: значок в трее, Ctrl+Alt+D,
  повторный запуск.

## Проверка

Наборы `scripts/test-*.ts` на подставном Electron (порядок, фокус, выключатель,
доверие IPC) и обязательная ручная проверка владельцем на Windows: развёрнутый
Word, нажатие по столу и по разделу, Win+D, два монитора с разным масштабом.
