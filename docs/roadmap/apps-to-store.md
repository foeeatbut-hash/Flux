# Программы Flux — через Store

Статус: идея · обновлено 5 ноября 2026

Решение владельца (5 ноября 2026): программы, не сильно встроенные во Flux
(мессенджер, переводчик, браузер, Office, почта, Конструктор и т. д.),
со временем переносятся в Flux Store, чтобы каждую обновлять отдельно, без
выпуска portable. Выпуск самого Flux — только когда меняется основа.

Так сделано и в Windows: Блокнот, Paint, Терминал, Фотографии — часть
Windows, но обновляются через Microsoft Store отдельно от системы.

## Два уровня подпрограмм

| | Подпрограммы разработчиков | Программы Flux (системные) |
|---|---|---|
| Кто делает | любой разработчик в Studio | команда Flux |
| Подпись | ключ разработчика + сертификат владельца | ключ владельца |
| Разрешения | только объявленные и допущенные; данные Flux — на чтение | шире: запись в данные Flux через API со сверкой версий, сеть (почта), уведомления, файлы |
| Удаление | пользователь может удалить | нельзя удалить; можно вернуть прошлую версию |
| Установка | из Store по выбору | у всех сразу, обновление через Store |

Изоляция остаётся и для системных программ: шире разрешения, а не «всё
можно». Ошибка в почте не должна ронять Flux.

## Что остаётся в самом Flux (основа)

Оболочка (рабочий стол, Пуск, окна, панель задач), вход, лицензия, права,
встроенный сервер и база (схема, миграции), офлайн-копия и сверка, API
Flux для подпрограмм, Store, Проводник (глубоко связан с Windows), основные
данные — проекты, Оборудование, Теги, Каталог, ВДР — и всё нативное
(помощник Windows, движок Excel на Rust, мост к E3).

## Что переносить и в каком порядке

От самого независимого к самому связанному; каждая — отдельный этап,
перенос следующей — после того, как предыдущая отработала в Store.

1. **Переводчик** — мало связей с данными; пилот уровня «системная
   программа».
2. **Блокнот (заметки)** — свои данные, простая запись.
3. **Мессенджер** — свои данные, нужны живые события и уведомления.
4. **Почта** — нужна сеть (IMAP/SMTP) как подключение и хранение учётных
   данных.
5. **Flux Guide** (справка и туры) — читает все программы, но ничего не пишет.
6. **Конструктор** — пишет документы и связан с тегами и выпуском.
7. **Office** — тяжёлый, с нативными частями (редакторы GenOffice, движок на
   Rust): нативное остаётся во Flux, в Store — только интерфейс и логика.
8. **Браузер** — **остаётся во Flux**: ему нужен встроенный браузерный
   движок Electron, а это основа, не подпрограмма.

## Почему логика не рухнет — условия

1. **API Flux с номером версии.** Программа объявляет, с какой версией API
   работает; Flux держит текущую и предыдущую. Ломающее изменение API —
   только с выпуском Flux.
2. **Граница: что можно выпустить через Store, а что только с Flux.**
   - через Store: интерфейс и логика программы, её свои данные в своём
     хранилище;
   - только с Flux: изменение схемы общей базы и миграции, серверные
     маршруты, нативные части, новые возможности API. Программа, которой
     нужно новое в API, ждёт выпуска Flux («требуется Flux ≥ X»).
3. **Свои данные программы — в её хранилище** с номером формата; новая
   версия читает старый формат, возврат к прошлой версии восстанавливает
   копию (как в «Flux Store», план модулей).
4. **Запись в общие данные** (Конструктор, мессенджер) — только через API со
   сверкой версий и журналом (этапы 0–1 `offline-work.md`), тогда и офлайн,
   и конфликты работают одинаково для всех программ.
5. **Проверка совместимости в CI:** каждая программа гоняется против
   текущего и предыдущего Flux; Store не допустит выпуск, не прошедший её.
6. **Перенос без двойной работы:** программа сначала переводится на API
   Flux, оставаясь внутри portable (тот же код, но через API, а не напрямую),
   и только потом уходит в Store — так видно, чего не хватает в API, до
   переноса.

## Что может пойти не так

| Риск | Что делать |
|---|---|
| У людей разные версии программ и Flux | договор с версией, CI совместимости, «требуется Flux ≥ X» |
| Программе нужна правка схемы базы | это выпуск Flux, не Store |
| Плохой выпуск системной программы у всех | обновление по решению пользователя, отзыв выпуска откатывает всех |
| Офлайн-сверка разных версий программы | действия идут через API с версией, сервер сверяет как обычно |
| API разрастается | новые возможности — по нужде переносимой программы, каждая с проверкой |
