# Flux Studio и программы: что решено и что осталось

Состояние на 12 ноября 2026. Сводка решений владельца за 9–12 ноября и
очередь работ — чтобы продолжить в новой сессии без пересказа разговора.
Устройство — `modules.md`, `module-api.md`, страница
`docs/methodology/03-programs/studio.md`.

## Суть (слова владельца)

Studio — аналог Visual Studio для программ Flux: проект — папка с файлами,
код на любом из семи языков, собрать, запустить, опубликовать через
владельца в Store. Программа — полноценное приложение: свои окна, разделы,
меню, панели, ввод, графики, чертежи (образец — расчётная программа уровня
«Веросы»), в оформлении Flux и внутри Flux. Программа может обращаться к
данным любых разделов Flux, к другим программам, к программам на
компьютере и к интернету — по разрешениям. В интерфейсе и документах —
«программы», не «подпрограммы».

## Порядок работ (решение владельца 12 ноября 2026)

1. **Сначала всё, что осталось по плану** — сделано (PR 167); остались
   только находки ручной проверки владельца на Windows, когда появятся.
2. **Потом Studio:** проверка любой своей программы до Store (раздел ниже)
   — запуск во Flux из Studio, полный запуск в Studio на всех языках,
   кроме Python, отдельная программа без проекта и базы.
3. **Потом «Офлайн»** (`offline-work.md`, начиная с этапа 0 и раздела
   «Условия корректности»).

Этот порядок главнее нумерации в разделах ниже.

Ответы владельца 12 ноября 2026 (на вопросы руководителя):

- **«Выпуск»** (версия, сборка, приёмка на Windows) — после «Офлайна», одним
  выпуском после всех трёх этапов.
- **«Запустить во Flux» из Studio** — узкое доверие подтверждено: только
  компьютер и вход самого разработчика; тестировщикам — пробная группа Store.
- **Программа без проекта и базы** — во Flux всё равно сначала входят:
  при связи — с актуальными данными, без связи — тем же логином и паролем
  с последними данными на компьютере. Отдельного запуска программы «мимо
  входа» не делать. Вход без связи при удалённой базе — пункт 2.6
  `offline-work.md`, сейчас его нет (без связи входят только при локальной
  базе), поэтому запуск такой программы без связи появляется вместе с
  входом без связи; хранилище программы на компьютере и метка «работает
  без связи» от него не зависят.

## Решение владельца (12 ноября 2026): проверка любой своей программы до Store

Слова владельца: «должна быть возможность прям в студии протестировать все
программы свои собранные — как будет отображаться у пользователя, либо
запустить во Flux через студию, как разработчик, не выпуская в Store».
Отдельная расчётная программа «работает офлайн и без подключения к базе
данных», изолированно; результат потом можно прикрепить к проекту.

1. **Полный запуск в Studio на всех языках, кроме Python** — TypeScript,
   C, C++, Rust, Go, C# (WebAssembly): форма или своя страница, расчёт,
   окна, диалоги, `flux.net.fetch`, подключения к внешним программам,
   вызов другой своей программы (`flux.programs.call` — вторая программа
   разработчика ставится в тестовую базу). Выглядит и ведёт себя как у
   пользователя: тот же кадр, мост, тема и пределы. Python — позже
   (Pyodide в Studio), сейчас его проверяет запуск во Flux (пункт 2).
2. **«Запустить во Flux» из Studio, без Store и без проверки владельцем.**
   Studio передаёт собранный пакет Flux на этом же компьютере; Flux
   запускает его только у этого разработчика (право `module.develop`
   проверяет сервер или сохранённый вход), с плашкой «Разработка — не
   выпущено», на настоящих данных его проектов и с настоящими
   разрешениями (запрос согласия — как при установке). Другим людям и в
   Store пакет не попадает; подписан ключом разработчика, а не владельца —
   поэтому доверие отдельное и узкое: только этот компьютер, этот человек,
   до закрытия Studio или явного «Убрать». Все языки, включая Python.
   Нужна сверка с `flux-data-safety` и доверием выпусков
   (`modules/trust/`): запись в данные Flux по-прежнему невозможна.
3. **Отдельная программа без проекта и без базы.** Программа, которая не
   читает данные Flux (`reads` пуст, вход «Пуск»), — самостоятельное
   приложение: открывается без выбранного проекта и без связи с общей
   базой, но после входа во Flux (без связи — входом без связи, см. ответы
   владельца выше; на кэше проверенного выпуска, как решено 5 ноября для
   офлайна). Свои данные она хранит сама (`flux.state` сейчас
   только в памяти — нужно постоянное хранилище программы на компьютере,
   с пределом размера). В Store и окне установки — метка «работает без
   связи».
4. **Прикрепить результат к проекту — позже, заложить сейчас.** Например,
   расчёт в программе уровня «Веросы» сделан офлайн, потом «Прикрепить к
   проекту…»: человек выбирает проект и место (файл в Проводник, вложение
   к позиции оборудования), Flux показывает план и записывает сам —
   только через план и предпросмотр (`module-api.md`, «Запись через план»).
   Сейчас заложить: результат программы как файл (`flux.saveFile` уже
   есть) и действие `attach` в договоре — новым `op`, без записи, пока не
   сделан план изменений; разрешение «прикреплять результаты к проектам» —
   новым видом в реестре разрешений.

Порядок: 2 → 1 → 3, пункт 4 — проектом после них. Пункт 2 даёт проверку
всех языков сразу и закрывает и Python, и «как у пользователя».

## Работа на случай обрыва сессии

Лимит может кончиться посреди задачи. Поэтому каждая задача сразу живёт в
пул-реквесте: ветка и черновой PR открываются до первой правки, после
каждого принятого шага — коммит, отметка в `.claude/progress/<имя>.md` и
push. Новая сессия продолжает по файлу хода и PR, а не по памяти
разговора.

## После выпуска

- Отладка с точками останова в Studio.
- Печать и выгрузка PDF/Word/Excel из программ; общие базы данных
  программ (каталоги оборудования).
- Запись программ в данные Flux — только через план и предпросмотр
  (`module-api.md`).
- Расчётная программа уровня «Веросы» — отдельная разработка; нужны
  формулы и правила подбора от владельца.
- E3Flux программой через Store; почта программой; режим «ИИ» в Flux Guide
  (`ai-guide.md`); окна — вариант «вперёд только нажатое окно».
- Отдельные `.exe` (WinForms, Qt) как программы Store — не предусмотрено:
  это обход разрешений; только отдельным решением владельца.

## Урок этих дней

Зелёный CI не означал, что программа запускается: проверки шли на
заглушках, собранный Flux никто не запускал с первого этапа Studio.
Теперь сборки проверяют настоящий запуск до окна. Правило: этап не
объявляется готовым, пока собранная программа не запущена настоящим
Electron в CI и не названо, что проверено только владельцем на Windows.
