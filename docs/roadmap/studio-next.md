# Flux Studio и программы: что решено и что осталось

Состояние на 12 ноября 2026. Сводка решений владельца за 9–12 ноября и
очередь работ — чтобы продолжить в новой сессии без пересказа разговора.
Устройство — `modules.md`, `module-api.md`, страница
`docs/methodology/03-programs/studio.md`.

## Суть (слова владельца)

Studio — аналог Visual Studio для программ Flux: проект — папка с файлами,
код на любом из семи языков, собрать, запустить, опубликовать через
владельца в Store. Программа — полноценное приложение: свои окна, разделы,
меню, панели, ввод, графики, чертежи (образец — расчётная программа уровня
«Веросы»), в оформлении Flux и внутри Flux. Программа может обращаться к
данным любых разделов Flux, к другим программам, к программам на
компьютере и к интернету — по разрешениям. В интерфейсе и документах —
«программы», не «подпрограммы».

## В работе

**Одно рабочее окно Studio** — ветка `studio/workspace`, файл хода
`.claude/progress/studio-workspace.md`. Владелец: «слишком всё сложно…
зачем все эти непонятные разделы». Состав:
- стартовый экран «Мои программы», «Новая программа» одним диалогом;
- рабочее окно: дерево файлов и папок, редактор с вкладками, кнопки
  «Запустить», «Проверить», «Опубликовать», журнал внизу («Запуск»,
  «Проблемы», «Публикация», «Сбои у пользователей»);
- **проект привязан к папке на диске, как в Visual Studio**: «Открыть папку
  как проект», слежение за папкой (внешние изменения видны сразу, конфликт с
  несохранённым — вопрос), правка внешним редактором и git;
- сборка TypeScript внутри Studio, ошибки по файлам и строкам;
- ключ разработчика создаётся сам; одна кнопка «Запросить право
  публиковать»; **выдача права — только владельцем по запросу** (решение
  владельца: это оставить);
- адрес базы берётся у лежащего рядом Flux;
- у владельца три пункта: «Программы на проверку», «Flux: обновления»,
  «Лицензии»; пароль хранилища один раз за сеанс; пробный запуск
  программ-страниц;
- `flux.openFile` — открыть файл пользователя через диалог Flux;
- человеческие слова вместо «канал», «договор», «манифест».

## Очередь до выпуска

1. Довести «одно рабочее окно» (выше), ревью, слияние.
2. Переименование «подпрограммы» → «программы» по всему репозиторию
   (Flux, Store, справка, документы); в Studio уже сделано.
3. Убрать учебную программу «Параметры позиции» из обычного Flux
   (`modules/bundled.ts`), оставить образцом в Studio (решение владельца).
4. Реестр разрешений программ: «любой адрес в интернете», локальная сеть,
   обращение к другим программам (`flux.programs.call`), согласие при
   установке и при расширении прав; интернет сейчас — только через
   объявленное подключение.
5. Окна программ: диалоги через Flux, заголовок и размер в
   `flux.windows.open`, вопрос о несохранённом при закрытии.
6. Полноценный тест в Studio: Python (Pyodide в сборке Studio), подключения
   к внешним программам, запуск «как у пользователя» (проект, права).
   Исполнитель был остановлен владельцем до начала работы.
7. Функции «как в GitHub»: история версий проекта, сравнение, откат,
   замечания владельца к строкам в редакторе, список выпусков.
8. Переводчик — перевести пример на свой экран (ввод текста, пачка строк).
9. Разобрать нестабильные проверки CI (Office-native, тайм-аут входа — шли
   со второго раза) и найти наборы, которые молча пропускают себя
   (`FLUX_VERIFY_SKIP` с кодом 0); падение `test-metrics` на `Taskbar.tsx`
   есть и в `main`.
10. Остановлено владельцем («пока не трогай»), начато не было:
    «Окна Flux вместе с окнами Windows» — простой вариант
    (`windows-layer.md`); «Офлайн», этап 0 с уникальностью кода тега
    (`offline-work.md`, пункт 4 порядка в `README.md`).
11. «Выпуск» и приёмка владельцем на Windows.

## После выпуска

- Отладка с точками останова в Studio.
- Печать и выгрузка PDF/Word/Excel из программ; общие базы данных
  программ (каталоги оборудования).
- Запись программ в данные Flux — только через план и предпросмотр
  (`module-api.md`).
- Расчётная программа уровня «Веросы» — отдельная разработка; нужны
  формулы и правила подбора от владельца.
- E3Flux программой через Store; почта программой; режим «ИИ» в Flux Guide
  (`ai-guide.md`); окна — вариант «вперёд только нажатое окно».
- Отдельные `.exe` (WinForms, Qt) как программы Store — не предусмотрено:
  это обход разрешений; только отдельным решением владельца.

## Урок этих дней

Зелёный CI не означал, что программа запускается: проверки шли на
заглушках, собранный Flux никто не запускал с первого этапа Studio.
Теперь сборки проверяют настоящий запуск до окна. Правило: этап не
объявляется готовым, пока собранная программа не запущена настоящим
Electron в CI и не названо, что проверено только владельцем на Windows.
