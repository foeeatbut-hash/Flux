# Отказ от лицензии: только вход по логину и паролю

Статус: возможное развитие — **не внедряется сейчас**, продумано на будущее · обновлено 29 октября 2026

Владелец планирует убрать лицензирование: Flux запускается без ключа,
доступ — только по учётной записи сотрудника. Права остаются ролевыми.

## Что есть сейчас

Лицензия персональная — на сотрудника, а не на компьютер; есть режим
«только чтение».

(`server/legacyIdentity.ts`).

## Что НЕ убирать вместе с лицензией

1. **Подпись обновлений.** Ключ Ed25519 обновлений — отдельный
   (`electron/updateKey.ts`, подписывает `tools/update-sign.mjs`), с
   лицензией не связан. Без него подменённый в базе exe поставился бы всем.
2. **Вход владельца по ключу** (`license/ownerKey.ts`, Owner-ключи). Это не
   лицензия, а самая сильная учётная запись: публикация обновлений
   (`requireOwnerMiddleware`, `server/accessPolicy.ts:49`), делегирование
   кампаний. Остаётся.
3. **Номер установки.** Нужен кампаниям обновлений и, позже, модулям.
   Хранится в `AppSetting` `license.install_id` — переименовывать ключ
   нельзя без переноса значения, иначе все устройства потеряют кампании.
4. **Ролевые права** (`src/lib/permissions.ts`, `server.ts` `permAllows`) —
   лицензия их не заменяла и не заменяет.

## Этапы

### 1. Номер установки отдельно от лицензии
- Вынести чтение/создание в свой модуль (например, `server/installation.ts`);
  `licenseService.ts:47` и `owner.ts:18` вызывают его.
- Ключ `license.install_id` в базе **оставить как есть** (данные), меняется
  только код.
- Готово: кампании обновлений работают при выключенной лицензии.

### 2. Выключатель вместо удаления
- Настройка «Лицензирование: включено/выключено» (по умолчанию —
  включено, пока не решено иначе). При «выключено» `personLicenseMiddleware`
  пропускает всё, `licenseForUser` возвращает «лицензирован без срока»,
  `electron/license.ts` отдаёт `licensed: true`.
- Зачем выключатель, а не удаление сразу: откат одним переключателем, если
  что-то держалось на лицензии незаметно.
- **Ловушка:** `electron/localFileAccess.ts` — без лицензии закрыт доступ к
  локальным файлам. Если выключатель не дойдёт до Electron, сломаются
  Проводник, импорт и Office. Проверить отдельно.
- **Ловушка:** старые версии Flux у сотрудников продолжат требовать
  лицензию, пока не обновятся. Значит: сначала выпуск с выключателем,
  обновление всех, потом выключение.

### 3. Первый администратор в пустой базе
Сейчас пустую базу открывает только владелец ключом. Это и так не лицензия —
оставить: владелец входит Owner-ключом и заводит администраторов. Отдельный
«одноразовый код» не нужен. Проверить, что путь Owner работает без
лицензии.

### 4. Удаление
- Клиент: экран `LicenseGate`, раздел настроек, право
  `admin.license.activate`, статья справки.
- Сервер: `personLicense.ts`, `personLicenseMiddleware`, сокет
  `license-required`, ответы 402.
- Electron: `electron/license.ts`, каналы `license:*` в `ipcAllow.ts`;
  `localFileAccess.ts` — доступ по входу пользователя, а не по лицензии.
- Таблицы и записи лицензий в базе не удалять сразу: оставить на один
  выпуск, потом убрать миграцией.
- Проверки: убрать `FLUX_TEST_LICENSE*`, переписать ~35 сценариев, убрать
  подмену в `scripts/demo-video/record.ts`.
- Ключ подписи лицензий (`LICENSE_SIGNING_PUBLIC_KEY_HEX`) и генератор
  (`tools/license-generator.html`, в `.gitignore`) — убрать; Owner-ключи и
  ключ обновлений — оставить.

### 5. Чем заменить защиту, которую давала лицензия
Лицензия ограничивала, кто вообще может запустить Flux с базой компании.
Без неё это держат:
- доступ к MariaDB/PostgreSQL только из сети/VPN компании и отдельная
  учётная запись SQL с минимальными правами
  ([company-server.md](../company-server.md));
- отключение учётной записи уволенного сотрудника (сессии отзываются —
  `server/authSessions.ts`).

## Что может пойти не так

| Риск | Как избежать |
|---|---|
| Незаметная зависимость от лицензии (как `localFileAccess.ts`) | этап 2 — выключатель и полный прогон проверок, включая Windows CI, до удаления кода |
| Кампании обновлений теряют устройства | номер установки не меняется (этап 1) |
| Старые клиенты блокируются | выпуск с выключателем раньше выключения |
| Проверки молча проходят, потому что лицензию подменяли | переписать сценарии на реальный вход |
