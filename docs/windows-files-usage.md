# Файлы Windows в Flux

В portable Проводник и рабочий стол используют настоящие папки текущего
пользователя Windows. В браузере остаётся проектный архив: браузеру нельзя
выдать произвольный доступ к диску. Старые проектные документы не удаляются;
они доступны через «Документы проекта».

## Где находится файл

Обычный файл редактируется в своей папке Windows. «Только в Flux» означает
локальный черновик на этом компьютере. При создании запоминается открытая
папка; «Отобразить в Windows» сохраняет файл туда без повторного выбора пути.
Черновик переживает перезапуск Flux. При совпадении имени публикация сообщает
о конфликте и предлагает другое имя, существующий файл не заменяется.

Содержимое личных файлов и черновиков не отправляется на сервер компании при
открытии, редактировании, сохранении или публикации. Локальные теги, ревизия,
ответственный и ссылки на проекты записываются отдельно от содержимого файла.
Названия доступных проектов и тегов поступают из общей базы.

## Сохранение и конфликты

Flux проверяет исходные байты перед записью. Если файл изменили в Word,
Проводнике или другом окне Flux, редактор сохраняет пользовательские правки
и показывает конфликт. Отдельная копия сохраняется в той же папке;
«Обновить» загружает исходник только после успешного сохранения. Ошибка
сохранения оставляет окно открытым.

DOCX, XLSX и PDF открываются во встроенных редакторах. Текстовые файлы
редактируются в UTF-8 с сохранением BOM и Windows-окончаний строк. Другую
кодировку нельзя молча заменить пустым или повреждённым текстом: такие файлы
доступны через программу Windows. Остальные форматы открываются штатной
программой. «Сохранить копию» сохраняет исходный файл без изменений.

В режиме истёкшей лицензии доступно чтение; запись, создание, удаление,
переименование и изменение свойств требуют действующей лицензии и сессии.
Проверку выполняет главный процесс программы по адресу настроенного сервера.

## Папки, корзина и ограничения

Копирование папок проверяет дерево до записи. Перенос проверяет копию и
отправляет исходную папку в корзину Windows, чтобы можно было восстановить
её при сбое. Удалённые черновики помещаются в отдельную локальную корзину.
Ссылки и junction не обходятся автоматически: папку назначения подключают
явно. Файл с совпадающим именем никогда не перезаписывается скрытно.

Чтение и редактирование ограничено 64 МБ на файл. Для папок предел составляет
5000 элементов, 512 МБ и 64 уровня вложенности. Список папки выдаётся
страницами по 500 элементов; при превышении 50 000 элементов показывается
ограничение. Эти пределы предотвращают зависание интерфейса и позволяют
понятно отказаться от слишком большой операции.

Windows-ветка сохранения использует ReplaceFileW для сохранения прав доступа,
атрибутов и дополнительных потоков исходника. Работа с заблокированными
файлами, OneDrive, сетевыми папками и настоящей корзиной дополнительно
проверяется на Windows; Linux-проверка не подтверждает эти особенности ОС.

## Рабочий стол Windows

Значки читаются из активного вида рабочего стола Проводника, включая общий
рабочий стол, ярлыки и виртуальные элементы. Их позиции возвращаются в физических
пикселях, затем Electron переводит каждую точку в координаты мониторов с учётом
масштаба. Если Проводник или локальный помощник недоступны, Flux сообщает об
отказе, а не заменяет расположение значков своей сеткой.

Для обычных файлов и папок главный процесс сопоставляет настоящий Shell-путь
с подключённым корнем. Редакторы Flux получают только идентификатор корня и
относительный путь и сохраняют исходный файл через обычную проверку версии.
Общий рабочий стол подключается по Windows Known Folder, а не по предположению
о пути `C:\Users\Public`. Символьная ссылка или junction не расширяет доступ.
Ярлыки и виртуальные элементы запускаются через Shell по непрозрачному
идентификатору из последнего успешного снимка.

Изображения берутся из `IShellItemImageFactory`, включая доступные миниатюры.
Совпадение пиксель в пиксель с уже нарисованным Проводником, включая значки
состояния OneDrive и оверлеи сторонних Shell-расширений, этим API не гарантировано.
Координаты, прозрачность изображений, размеры на мониторах с разным DPI,
перезапуск Проводника и запуск виртуальных элементов требуют живой Windows-приёмки.
В Linux проверены преобразование координат и файловые capability; C#-помощник
здесь не компилировался и не запускался.

## Уведомления других программ Windows

Центр Flux может включать события других программ Windows только через
установленный companion «Уведомления Windows в Flux». Electron `Notification`
публикует собственные уведомления, но не предоставляет доступ к центру Windows.

Для такого доступа нужен отдельный установленный пакет с Windows app identity
и capability `uap3:userNotificationListener`. Компонент должен запрашивать
`UserNotificationListener.RequestAccessAsync` из своего интерфейса по явному
действию человека, проверять `GetAccessStatus` перед чтением и прекращать
чтение после отзыва разрешения. После согласия источником станут
`GetNotificationsAsync(NotificationKinds.Toast)` и `NotificationChanged`;
полученные события должны сохранять отдельный источник «Windows» и не менять
статус прочтения событий Flux.

Исходный проект, manifest и инструкция сборки находятся в
[tools/windows-notification-bridge](../tools/windows-notification-bridge/README.md).
Главный процесс Flux обнаруживает установленный пакет и читает фиксированный
снимок его LocalState; устаревший снимок или отозванное разрешение очищают
список. При отсутствии пакета Flux сообщает, что компонент нужно установить.
Программа не устанавливает сертификаты и не выдаёт согласие автоматически.

В текущем Linux-окружении компонент не собирался и не запускался на Windows;
подписанного установленного пакета здесь нет. Чтение настоящего центра Windows
остаётся непроверенным до сборки MSIX и живой проверки разрешения, получения
уведомлений и его отзыва. Наличие исходного C#-проекта не подтверждает доступ
API на компьютере сотрудника.
