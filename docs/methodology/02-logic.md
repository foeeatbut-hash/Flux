# 02 — Логика

Заготовка. Часть пишется следующей: здесь будет то, как программа
обращается с данными, одинаковое для всех разделов. Так же, как «Дизайн»
отвечает на вопрос «как выглядит», «Логика» ответит на вопрос «как себя
ведёт».

Пока часть не написана, действуют правила из skills. При написании их
содержимое переносится сюда, а в skills остаётся ссылка, чтобы правила не
расходились:

| Тема | Где сейчас |
|---|---|
| Слои кода, границы разделов, размер файлов | `.claude/skills/flux-architecture` |
| Запись в базу: план, предпросмотр, откат, конфликты | `.claude/skills/flux-data-safety` |
| Проверки и снимки | `.claude/skills/flux-verify` |
| Сборка и выпуск | `.claude/skills/flux-release` |

## Что войдёт

- **Запись** — всегда через план «было → станет», одна транзакция, отмена
  одним действием.
- **Одновременная правка** — сверка версии, отказ 409 с понятным текстом,
  перечитывание.
- **Живые обновления** — сокет плюс перечитывание при возврате фокуса: на
  общей базе сокет до чужого сервера не доходит.
- **Права** — открытые по умолчанию и выдаваемые явно; явный запрет хранится
  записью.
- **Ошибки** — что видит человек, что уходит в журнал, чего в журнал не
  попадает никогда (пароли, ключи).
- **Итог действия** — правдивое сообщение: что сделано, что пропущено и
  почему.
- **Удаление** — что уходит вместе с объектом, чтобы не оставались сироты.
