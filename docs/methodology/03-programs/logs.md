# Журнал

Назначение — узнать, кто что делал и что изменилось, и перейти к объекту.

## Что на экране

- Записи из двух источников одним списком: события проекта и действия
  сотрудников, которые пишет сервер (вход, правка, удаление, выгрузка,
  права).
- Поиск, фильтр по сотруднику, фильтр по разделу.
- Переход к объекту по щелчку по записи, если у записи есть адрес.
- Обновление списка.

## Раскладка

- Шапка: «Журнал» · «N записей · M сотрудников» · справа «Обновить».
- Панель инструментов: поиск → сотрудник → раздел → «Сбросить» (только когда
  фильтр задан) → справа «последняя запись …».
- Таблица: Когда · Сотрудник · Раздел · Действие · стрелка перехода (при
  наведении, только у записей с адресом). Строка — по плотности (32 px).
- Раздел — значок и слово второстепенным цветом, без цветной плашки:
  категория не несёт смысла «хорошо/плохо», и цвет ей не положен.

## Что было смешано

- Карточка-шапка с подзаголовком, три плитки-сводки и карточка «Параметры
  фильтрации» занимали полэкрана. Сводки стали счётчиком в шапке, фильтры —
  одной панелью инструментов.
- «Сбросить настройки» над фильтрами и «Сбросить фильтры» в пустом списке —
  одна функция в двух местах под разными словами. Осталась одна кнопка.
- Щелчок по записи всякий раз показывал уведомление «Переход к разделу…»,
  а у записи без адреса — «нет прямой ссылки». Переход виден и так; запись
  без адреса просто не нажимается.
- Загрузка называла внутреннее устройство («…базы данных PostgreSQL»).
- У серверных действий нет символа сотрудника: пустой кружок и «ID: ».
  Символ показывается, только когда он есть.
- Подсказка «Нажмите на запись…» курсивом в рабочем поле — убрана: переход
  виден по стрелке при наведении.
