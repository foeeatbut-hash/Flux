# Оборудование

Назначение — вести оборудование проекта: установки, их состав и
характеристики, связь с тегами; ввозить расчёты и бланки; выгружать.

## Что на экране

- Категории (центральные кондиционеры, радиальные вентиляторы, клапаны,
  воздушные завесы и свои).
- Дерево позиций категории — по составу или по типу; список позиций.
- Карточка выбранного: блок (параметры, состав, теги, история, где
  используется) или установка (схема, общие характеристики).
- Импорт из документов, выгрузка в Excel по шаблону, центр операций,
  отмена последнего импорта, настройки оборудования, вид категории.

## Раскладка

- Шапка: «Оборудование» · текущая категория и число · справа «Центр
  операций», главное «Импорт из документов», настройки
  значком.
- Три колонки по потоку «навигация → список → карточка»: категории
  (боковой список) → дерево → карточка.
- Под шапкой — строка «можно отменить импорт», только когда есть что
  отменять.
- Подсказка о форматах — в подвале списка категорий, а не кнопками.

## Что было смешано

## Исключения из общих правил

- Цвет типа оборудования (`TypeChip`) остаётся цветом: по нему тип читают
  в дереве и карточке глазами, как цвет этапа закупки.
- Действия в шапке карточки блока (все параметры, сохранить вид, история,
  где используется) видны всегда: это шапка объекта, а не строка таблицы.

## Логика

Импорт документов проходит через один мастер: файлы разбираются по очереди,
инженер проверяет общий предпросмотр и подтверждает запись. Для повторного
импорта мастер сохраняет ID общей привязки источника и передаёт её ревизию
журнала вместе с именем файла, правилом сопоставления, ревизией документа,
SHA-256 и переносимым адресом папки. Сервер в одной транзакции записывает
оборудование и общую привязку; если ревизия журнала успела измениться, обе
записи отклоняются, мастер обновляет ревизию и просит подтвердить импорт снова.

Для источника «XML + каталог» заполненное значение XML остаётся основным, но
если у каталога есть соответствующий параметр с совместимой единицей (включая
пересчёт поддерживаемых эквивалентных единиц), его значение сравнивается с XML. Отличия показываются в карточке оборудования как
расхождения с явной подписью «XML» и «Каталог» (включая источник каталога,
если он указан); пустые поля по-прежнему заполняются каталогом. Сравнение не
выполняется в режимах «Только XML» и «Каталог».

Повторный ввоз расчёта ищет запись не только по адресу: сначала по тегу из
файла, затем по адресу с проверкой, что изделие то же (тип, вид, типоразмер,
мощность), затем среди переехавших. Код сопоставления — `server/equipmentIdentity.ts`
(позиции), `server/equipmentSystemMatch.ts` (установки), общий обход для плана
и записи — `server/equipmentResolve.ts`; правила — `docs/e3-integration.md`, 1.3–1.6.

В окне предпросмотра спорные места собраны за кнопкой «Спорные позиции»:
переехавшая позиция, другой типоразмер или тип по тому же адресу,
переименованная установка («это она?»), одинаковые имена. Каждая строка —
переключатель «То же изделие / Переподобрано / Другое изделие» с
умолчанием по таблице 1.4. Выбор уходит в запись полем `choices`; прежняя
запись при «Переподобрано» и «Другом изделии» получает `status = 'REMOVED'`,
связь «заменено на» лежит в её `conflictLog` (ключ `__removal`).

Позиция, которой нет в новом файле расчёта, не удаляется, а снимается
(`REMOVED`, отметка `__removal` с партией и причиной `missing`); ручные
позиции файл не знает и не снимает. Фрагмент — распознанный документ —
не снимает ничего. Вернулась в расчёт — та же запись, статус OK. «Переподобрано»
переносит теги на новую запись, «Другое изделие» оставляет их у снятой.
Отмена партии возвращает всё: снятые, прежние адреса переехавших, теги.

Карточка позиции показывает непустые группы характеристик в компактных
раскрываемых разделах; состояние разделов сохраняется для этой позиции. Источник
данных выбирается отдельно: XML, гибрид с каталогом или каталог. Поиск каталога
ограничен типом оборудования и ищет по марке, модели и изготовителю. Выбор модели
показывает снимок характеристик и вариант семейства; изменения сначала
сравниваются с карточкой. В гибридном режиме инженер принимает каждую
характеристику отдельно или все различия сразу. При принятии сохраняются
каталожное происхождение и значения снимка, ручные замены снимаются только с
принятых характеристик. XML-основа не изменяется.

Выбор варианта семейства ограничен перечислениями, проверенными строками таблиц,
примерами и текущим разобранным обозначением; сервер проверяет диапазоны и
зависимости, а обозначение позиции не переписывается. Характеристики, пришедшие
из каталога, в карточке только для чтения: исправить их можно в справочнике
каталога. Применение к позиции записывается в историю и поддерживает безопасную
отмену при отсутствии последующих изменений.

При выборе установки правая панель показывает обзор состава: моноблоки,
карточки блоков, вложенные позиции и теги. Выбор блока или дочерней позиции
открывает её штатную карточку.

Версия позиции растёт на единицу при любом принятом изменении: характеристики,
тип, тег, состав и адрес, ручная правка, снятие и возврат, отмена. Запись и
привязка тега идут через `server/equipmentVersion.ts`. Повторный ввоз без
изменений версию не трогает.

Создание тега и привязка из Оборудования сразу рассылают `entity:changed` для
тега и позиции. Открытые экраны Оборудования и Тегов перечитывают затронутые
списки по этому событию; повторный вход для синхронизации не нужен.

В дереве снятые позиции серые и скрыты за переключателем «Показать снятые»;
в карточке тега у снятой позиции подпись «оборудование снято».

После первичного импорта к тегу установки или позиции можно привязать XML-файл.
В серверной базе связь хранит идентификаторы проекта, тега, установки и
позиции, выбранное правило имени, ревизию и контрольную сумму. Путь и ссылки
Проводника остаются в локальной карте Windows/Electron: сервер никогда не
получает путь клиентского диска. Для установки характеристики относятся к
служебной позиции `__unit__`, поэтому сохраняют обычную версию и историю
оборудования.
Старые локальные XML-привязки переносятся только после выбора источников и
явного подтверждения. Сервер проверяет ревизию общего журнала; при отказе
переноса старые записи остаются на месте. После успешной записи новые локальные
возможности сохраняются на устройстве, затем удаляются старые записи.
Для системного источника сравниваются характеристики `__unit__` и всех
однозначно сопоставленных вложенных позиций. Новые, отсутствующие, перемещённые
и восстановленные позиции требуют отдельного решения по составу; принятие
создаёт позицию с распознанными группами и связями, снятие сохраняет запись и
её теги. Частичные решения накапливаются в одном снимке, поэтому более позднее
решение не дублирует уже созданную позицию.

При открытии привязанной карточки и затем каждые пять минут программа проверяет
локальные источники проекта с ограничением двух одновременных чтений; в дереве
и списке видны позиции с новой ревизией, отсутствующей папкой или неоднозначным
файлом. Открытая карточка проверяется отдельно, кнопку «Проверить» можно нажать
вручную. XML читается
дважды для обнаружения копирования, имя и тег в содержимом проверяются точно,
а исходные байты сверяются по SHA-256. На сервер отправляются байты выбранного
XML только для проверки и разбора; сохраняются разбор, контрольная сумма,
различия и решения, но не файл и не локальная ссылка. Повреждённый, неполный,
неоднозначный XML или другой тег не меняет оборудование.

Новые и изменённые значения можно принять по одной строке, группе или разом;
значения с совместимыми единицами сравниваются без ложного отличия от формата
числа. Удаление отсутствующего в XML параметра всегда требует отдельного
решения. Ручная характеристика помечена; заменить её можно только явным
действием. Незавершённое рассмотрение хранится за контрольной суммой и доступно
после закрытия программы. Частичные решения обновляют общий снимок ревизии;
отмена сверяет все затронутые позиции и при параллельной правке пропускает
операцию целиком, чтобы не затереть более новые данные. Переименование тега не теряет источник: программа требует проверить
новый XML и правило имени файла. Перепривязка делает прежние кандидаты
устаревшими: их нужно повторно сравнить, даже если SHA файла не изменился.

Сам факт проверки не отмечает характеристики как импортированные. Принятые
изменения обновляют импортированную ревизию; завершённая проверка с сохранением
текущих значений отмечает только просмотренную ревизию. Значения каталога
остаются в снимке привязки каталога и меняются только в программе «Каталог».

## Источник XML и ревизии

Локальная привязка источника хранит capability Windows `{rootId, relativePath}`
на компьютере пользователя, отдельно для source/element. Абсолютный путь
остаётся в Electron main. При проверке кандидат читается через файловый мост;
сервер получает байтовый снимок XML для разбора и сравнения, а изменения
пишутся в проект только после подтверждения инженером. Сканер смотрит XML в папках
ревизий в заданном порядке, сопоставляет имя по сохранённому правилу и
сверяет тег в верхнем узле установки либо в целевом блоке; изменение файла
внутри прежней ревизии определяется контрольной суммой. Пустая папка не
становится обновлением, неоднозначный или нестабильный файл требует выбора или
повторной проверки.

Папки ревизий сортируются естественно: A/B/C и 1/2/3/10; имя вроде C1
учитывается только когда оно включено в порядок конкретного источника. Слова
вроде `Backups` и `Documents` не считаются ревизиями. При первом выборе XML
пикер предлагает имя родительской папки только когда сам распознал папку
ревизии, а импорт подставляет предложение лишь при точном совпадении с тегом,
прочитанным из XML.

Кнопка «Обновления XML» открывает список всех XML-источников текущего проекта,
включая позиции с локальной ошибкой без сохранённого кандидата. Счётчик считает
позиции с ожидающим решением; число изменений в строке складывает различия
характеристик и действия по составу установки. Выбор нескольких источников
показывает предпросмотр общего корня и подпапок по точным тегам. Для одного
источника выбирается его точная папка. Подтверждение инвалидирует только
ожидающий или частичный кандидат, сохраняя историю автора; уже подтверждённые
кандидаты остаются неизменны. Источник и последний кандидат сверяются по
версиям внутри одной транзакции. Откат восстанавливает локальные ссылки только
если они не менялись после перепривязки; серверная запись устаревания сохраняется,
поэтому источники затем проверяются повторно. Кнопка последовательного обзора
открывает штатную карточку решения по одной позиции и не утверждает данные сама.

У позиции без тега источник связывается с её стабильным ID в проекте. Инженер
отдельно выбирает узел установки или компонента в XML; сервер сохраняет путь и
снимок его исходных признаков, а не придумывает ID производителя. Повторная
проверка принимает только тот же узел по тому же пути и признакам. Если узел
переместился или его признаки изменились, программа просит выбрать соответствие
заново. Имя файла закрепляется точным выбором; поиск по имени позиции или по
подстроке не выполняется.

## Выгрузка данных удалена

Прежней программы «Выгрузка данных» (`/equipment-export`) больше нет (решение
владельца): документы заполняются через дополнение Flux Office.

Постоянный ID позиции показывается в карточке и в списке, доступен поиску
независимо от наличия тега. При узкой панели действия заголовка
переносятся, сохраняя место для содержимого.

## Правая панель установки и состава

В обзоре карточки блоков сгруппированы по моноблокам; в карточке видны
наименование, марка, теги и вложенные позиции. Кнопка блока открывает карточку
этой позиции, дочерняя строка — карточку вложенной позиции. Теги установки
и блоков можно назначить или отвязать прямо из обзора.

При выборе позиции над прокручиваемыми характеристиками остаётся компактная
навигация: установка, параметры установки, блоки и элементы выбранного блока.
Иерархия берётся из состава и `parentElementId`; дочерние элементы сохраняют
порядок источника. Штатные действия карточки доступны: постоянный ID и версия,
состав, теги, характеристики, поиск, каталог, конфликты, история и источники XML.

Группы характеристик образуют компактные карточки. Примечания показаны короткой
строкой; полный набор доступен через «Все параметры». Каталог свёрнут до
строки с моделью; раскрытие показывает источник и сравнение характеристик.
Ручные значения отмечены янтарным, каталожные — голубым и доступны только
для чтения.

Панель использует общие токены Flux в обеих темах. На ширине около 1100 px
она остаётся без горизонтального переполнения; длинные подписи в навигации
сокращаются, полное имя остаётся в карточке.

Профильная проверка `scripts/fixtures/equipment-panel/check.mjs` показывает
настоящий экран на модели установки из концепта: обзор, блок и клапан при
1440×900 и 1100×900 в обеих темах, а также раскрытый каталог. После снимков
проверяет переходы блок → клапан → привод → блок → обзор и поиск параметров
с результатом, пустой выдачей и очисткой.

### Регрессия ОБР-000023: XML Веза / ACON

Первичный выбор XML из мастера не отменяется эффектом неизменившегося проекта.
Диалог наследует категорию и установки мастера; теги извлекаются также из
`cadUnitFolder` и `ptUnitName`, с исправлением раскладки по общей политике тегов.
При проверке источника различаются теги установок и компонентов САПР. Все
серверные разборы учитывают TagPolicy проекта и словарь `veza_kind_map`.
Нераспознанные виды сопоставляются через `UnknownKinds`, после сохранения
строится новый план. Запись по-прежнему требует явного подтверждения.
Регрессии: `test-equipment-sources-local` и `equipment-xml-source-ui/importer.check.mjs`
(первичное открытие с двумя стабильными чтениями и смена проекта во время чтения).
