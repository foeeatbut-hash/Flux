# Модули Flux

Назначение — запускать программы, объявленные в манифестах модулей, в общей оболочке Flux.

## Что на экране и раскладка

Модуль открывается по маршруту `/module/<id>` в обычной раме окна Flux. Манифест объявляет места запуска: «Пуск», карточку выбранной позиции оборудования и карточку тега. В карточках кнопка появляется только для объявленного места. Оформление окна следует общим правилам оболочки и поддерживает обе темы.

## Логика

PR 1 реализует этапы 1–2 плана Flux Studio. Встроенный пример находится в `modules/fixtures/equipment-inspector`: пакет содержит `manifest`, `form` и `logic`. До PR 2 используется только встроенная фикстура; загрузчика выпусков из базы пока нет.

Договор v1 предоставляет только чтение: текущий проект, позицию оборудования с параметрами, тегами и составом, тег, спецификацию (строки Тегов) и минимальные данные каталога (семейства). Запись во Flux из модуля не предусмотрена. События `opened`, `project-changed` и `changed` сообщают об открытии, смене проекта и изменении данных; модуль перечитывает данные через договор.

Содержимое загружается по протоколу `flux-module://` в iframe с непрозрачным источником и `sandbox="allow-scripts"`. CSP запрещает сеть и `eval`. Схемы сообщений находятся в `modules/schemas.ts` (`messageSchemas`); расчёт выполняется в Worker с пределом времени 30 секунд.

## Проверки

Плановые наборы: `scripts/test-modules-contract.ts` проверяет договор и обработку сообщений на уровне контрактов; `scripts/test-modules-native.ts` предназначен для проверки нативного слоя и изоляции. Проверки API с фикстурой не подтверждают работу с настоящей базой данных. Результаты запусков, Windows и CI фиксируются после итоговой проверки.
