# Проводник Windows

Проводник показывает места Windows и локальные черновики Flux, поддерживает поиск, вкладки, восемь видов списка, операции с файлами, свойства и восстановление из корзины.

## Проверка интерфейса

`scripts/test-windows-explorer-ui.ts` открывает отдельный Vite fixture на `127.0.0.1:5174`. Fixture подменяет файловый bridge детерминированными корнями, файлами, метаданными, быстрым доступом, облачным местом и потоковыми событиями поиска. Сценарии проверяют навигацию, вкладки, поиск и отмену, сохранение вида, создание, выделение, клавиши, свойства, глубокие ссылки и длинный список с виртуализацией. `scripts/test-explorer-contents-ui.ts` проверяет содержимое, виды и столбцы; `scripts/test-explorer-operation-ui.ts` проверяет работу hook с мостом-заглушкой.

Итоговые UI-наборы: основной 128/128, содержимое 18/18, без ошибок браузера; светлая и тёмная темы сняты на 1280 и 1024 пикселях, проверены размеры и отсутствие глобального переполнения. Проверены сочетания при русской раскладке, сохранение прокрутки и повторный Home.

Операционный fixture проверен по всем 15 сценариям, включая отказ fileHash при вырезании и частичное удаление Flux при `error` response и исключении; `scripts/test-explorer-operations.ts` прошёл 9/9 чистых проверок. Это результаты для UI и логики на подменённом bridge, не для системных операций Windows.

TypeScript, сборки приложения и Electron и 9 итоговых наборов затронутой области прошли; portable FS-набор выполнил 26 проверок. Общерепозиторный прогон не запускался: отсутствует API-сервер, поэтому несвязанные серверные наборы здесь не дают проверяемого результата.

Fixtures проверяют связь компонентов с тестовым контрактом bridge. Они не запускают настоящий Windows Explorer и не подтверждают работу Windows shell, NTFS, системной корзины или нативного перетаскивания. `scripts/test-windows-files-native.ts` покрывает эти вызовы и запускается в `.github/workflows/verify-windows-shell.yml`; в текущем окружении Windows-native проверки `NOT_RUN`. Сетевой диск компании, два компьютера на общей папке и реальные DPI остаются отдельной приёмкой владельца.

Запуск браузера выполняется только в UI-окружении с Chromium и Vite fixture. При обычной проверке кода можно проверить состав программ командой `node --import tsx scripts/verify-programs.ts --list`.
