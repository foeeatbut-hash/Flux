# Проводник Windows

Проводник показывает места Windows и локальные черновики Flux, поддерживает поиск, вкладки, восемь видов списка, операции с файлами, свойства и восстановление из корзины.

## Значки

Все значки Проводника — значки Flux: папка, диск, облако, сеть, этот компьютер
и лист файла с полосой формата (`WindowsFileIcon`, `PlaceIcon`,
`lib/fileBadge.ts`). Системные значки Windows (`getIcon`, `placeIcon`) не
запрашиваются. Формат, который Flux не открывает (`canOpenInFlux`), рисуется
«закрытым» листом с замком и серой полосой. Размеры по виду: «мелкие», «список»,
«таблица» — 16; «содержимое» — 32; «плитки» и «средние» — 48; «крупные» — 96;
«огромные» — 256 (`explorerIconSize`); панель навигации, меню и вкладки — 16;
окно сведений — 48. Миниатюры содержимого (снимок, страница PDF) берутся только
при `thumbnailOnly` и только для значков от 32 px.

## Контекстное меню Windows

Нативное контекстное меню открывается с отдельным токеном. Если меню закрывается при выборе команды, закрытие откладывается до завершения вызова и затем освобождает этот токен. Ответ на устаревший запрос меню сразу освобождает полученный токен и не заменяет текущее меню. На Главной показываются закреплённые места быстрого доступа, а при пустом быстром доступе — корни; «Быстрый доступ», «Корзина» и общее место используют свои значки Flux.

## Проверка интерфейса

`scripts/test-windows-explorer-ui.ts` открывает отдельный Vite fixture на `127.0.0.1:5174`. Fixture подменяет файловый bridge детерминированными корнями, файлами, метаданными, быстрым доступом, облачным местом и потоковыми событиями поиска. Сценарии проверяют навигацию, вкладки, поиск и отмену, сохранение вида, создание, выделение, клавиши, свойства, глубокие ссылки и длинный список с виртуализацией. `scripts/test-explorer-folder-errors-ui.ts` отдельно проверяет отказ корня, частичный отказ объектов и сохранение предыдущих строк/выделения при ошибке обновления в светлой и тёмной темах. `scripts/test-explorer-contents-ui.ts` проверяет содержимое, виды и столбцы; `scripts/test-explorer-operation-ui.ts` проверяет работу hook с мостом-заглушкой.

Итоговые UI-наборы: основной 128/128, содержимое 18/18, без ошибок браузера; светлая и тёмная темы сняты на 1280 и 1024 пикселях, проверены размеры и отсутствие глобального переполнения. Проверены сочетания при русской раскладке, сохранение прокрутки и повторный Home.

Операционный fixture проверен по всем 15 сценариям, включая отказ fileHash при вырезании и частичное удаление Flux при `error` response и исключении; `scripts/test-explorer-operations.ts` прошёл 9/9 чистых проверок. Это результаты для UI и логики на подменённом bridge, не для системных операций Windows.

TypeScript, сборки приложения и Electron и 9 итоговых наборов затронутой области прошли; portable FS-набор выполнил 26 проверок. Общерепозиторный прогон не запускался: отсутствует API-сервер, поэтому несвязанные серверные наборы здесь не дают проверяемого результата.

Fixtures проверяют связь компонентов с тестовым контрактом bridge. Они не запускают настоящий Windows Explorer и не подтверждают работу Windows shell, NTFS, системной корзины или нативного перетаскивания. `scripts/test-windows-files-native.ts` покрывает эти вызовы и запускается в `.github/workflows/verify-windows-shell.yml`; в текущем окружении Windows-native проверки `NOT_RUN`. Сетевой диск компании, два компьютера на общей папке и реальные DPI остаются отдельной приёмкой владельца.

При чтении списка отдельные записи с отказом ACL пропускаются с числом недоступных объектов; отказ у самой папки остаётся ошибкой и не отображается как пустой список. Ошибка обновления сохраняет последний успешно прочитанный список. Метки томов выводятся PowerShell в UTF-8, иначе русские имена портятся на OEM-кодировках Windows; нативный набор проверяет это подставным ответом CIM без изменения дисков. Диагностика файлового моста хранит только разрешённое действие, признак корневого запроса и число записей, без пути и идентификатора корня.

Для сетевой папки мост сначала отдаёт имена, а свойства догружает пакетами; события патча обновляют строки на месте. Пока inode не проверен, запись имеет отдельный стабильный `uiKey` для React и выбора. Канонический `fileId` остаётся идентичностью inode: hydration никогда не переписывает уже существующую identity, а сохраняет соответствие пути → канонический ID. Поэтому hard links разделяют метаданные и не порождают второй значок, а проект, история и позиция рабочего стола не теряются. Последующие списки используют сохранённый alias. Короткий кэш списка сверяет время изменения каталога; значки кэшируются по пути, времени и размеру.

Сведения о файле, свойства оболочки и миниатюры выполняются в отдельном последовательном STA worker. COM-меню остаётся в своём worker; зависший read-only вызов завершается таймаутом или отменой только своего процесса и не блокирует другие команды. У отменяемой общей миниатюры запрос остаётся активен, пока у него есть подписчики; уход одного окна не отменяет работу для другого. Защищённый объект пропускается с понятным сообщением без автоматического повтора.

Вызовы `/api/office/files/:id/meta` дедуплицируются и кэшируются общим модулем вне компонентов Flux Office. Ключ включает сервер, пользователя, проект и сессию. Сохранение файла, смена сессии и переход к другой идентичности не позволяют повторно использовать чужие метаданные; ошибки загрузки не кэшируются.

Для этой доработки: names-first и сохранение канонической идентичности проверяются `scripts/test-windows-network-list.ts`; задержка свойств задана тестом, так что начальный список обязан завершиться до её снятия. Отмена очереди и изолированного worker проверяется `scripts/test-windows-files-bridge.ts`, scoped cache — `scripts/test-file-metadata-cache.ts`; UI рамочного выделения и Ctrl+A проверяется Windows Explorer fixture. Эти фикстуры не заменяют проверку на сетевом томе и Windows COM helper.

Папки Windows можно привязать к проекту из контекстного меню или панели команд. **Привязка общая:** один журнал на весь Flux, её видят все, кому виден проект, и она действует на любом компьютере. Менять (привязать, сменить проект, снять, отменить) могут администратор и обладатель права `project.manage` («Управление проектами»); остальные только видят результат — у них пункта «Привязать к проекту» и кнопки «Привязать папку» нет, а сервер на запись отвечает 403. Привязка скрытого от человека проекта ему не показывается и не стирается.

**Идентичность папки — сетевой путь, а не rootId и не буква диска.** Main-процесс переводит букву сетевого диска в `\\сервер\ресурс` (WMI `Win32_LogicalDisk.ProviderName`, запасной путь — разбор `net use Z:`), приводит путь к единому виду (нижний регистр, `/`, без концевых слэшей, NFC) и отдаёт странице только sha256 — «ключ места». Команда моста `locationKeys` возвращает для папки цепочку ключей [сама папка, родитель, …, корень ресурса]; ключи считаются по строкам пути без обращений к диску (одно обращение к Windows на букву диска, с кэшем), поэтому открытие корня не порождает опросов SMB. Привязка наследуется вложенными папками и новыми файлами по ближайшему ключу цепочки; пока в журнале нет привязок, мост ключей не вызывается совсем. Абсолютный путь из main не выходит.

**Локальные папки не привязываются:** привязка, действующая на одном компьютере, выглядела бы общей и сбивала бы с толку; окно сообщает, что нужна папка на сетевом ресурсе. Ограничения: путь к ресурсу должен совпадать у всех (`\\srv\share` и `\\srv.domain\share` или IP — разные ключи); переименование или перенос привязанной папки отвязывает её, привязку нужно сделать заново. В журнале хранятся ключ, проект, имя папки (без пути), автор и время; CAS-ревизия и отмена (обрезаются по размеру) сохранены. Старые журналы «по пользователю и устройству» не читаются: функция не выходила в релиз. Ручные project ID файла сохраняют приоритет над наследованием. Операция не перемещает файлы и не меняет права проекта. Исторический архив FileNode открывается из панели навигации без переноса данных. Перевод буквы диска в UNC проверяется только на Windows; в тестах разбор вывода идёт на образцах, а вызовы PowerShell/`net use` замещены.

Обычный выбор импорта использует компактное окно Проводника и настройку системного окна; отмена и списки в окне изолированы от вкладок главного Проводника. Системный и Flux-пути сохраняют MIME и время изменения, а нативные импорты используют ограниченные по размеру ranged tickets. Playwright проверяет hard-link aliases с разными путями, MIME-фильтр, большие файлы, отмену и отсутствие ошибок браузера. `scripts/test-windows-explorer-ui.ts` прошёл 136/136, включая точную проверку сохранения прокрутки после обновления; сравнение с task03 baseline подтвердило исходный эффект и исправление сохранением identity строк. Это эмуляция bridge, не проверка настоящей Windows.

Запуск браузера выполняется только в UI-окружении с Chromium и Vite fixture. При обычной проверке кода можно проверить состав программ командой `node --import tsx scripts/verify-programs.ts --list`.
