# Справочник

Назначение — вести списки значений, из которых собираются коды тегов, и
условные обозначения, по которым читаются бланки.

## Что на экране

- Создание тегов: доп. параметры (категории и варианты), маркировка,
  пресеты подбора (списки для вкладки «Подбор» в Тегах).
- Разбор бланков: условные обозначения (символ + регистр + единица).
- Справочники проекта, загруженные из Excel: таблица кодов и
  наименований.
- Загрузка базы из Excel.

## Раскладка

- Шапка: «Справочник» · справа «Загрузить базу из Excel».
- Слева боковой список в три группы по назначению: «Создание тегов»,
  «Разбор бланков», «Справочники проекта» (со счётчиком записей).
- Справа лист выбранного: заголовок 15/600, пояснение, ниже две колонки
  «категории → варианты» или таблица.

## Что было смешано

- Шапка была крупнее всех остальных в программе: 24 px жирным, отступ
  24 px, подзаголовок.
- «Обозначения» стояли в группе «Создание тегов», хотя ими пользуется разбор
  бланков Оборудования. Переехали в свою группу «Разбор бланков».
- Выбранный пункт отмечался зелёной полосой слева.
- Заголовки листов — моноширинным жирным; счётчики «Всего: N» — зелёными
  плашками.

## Найдено и исправлено

- Редактор пресетов подбора был недостижим: пункта в боковом списке не
  было, хотя «Подбор» в Тегах читает его списки. Возвращён как «Пресеты
  подбора» (решение владельца). Его заголовок говорил «для «Экспорт и
  импорт»» — на деле списки нужны «Подбору».

## Что осталось (записано, не менялось)

- «Маркировка» больше нигде не читается: конструктор марки из тегов убран.
  Редактор оставлен до решения владельца.

## Исключения из общих правил

Нет.

## Логика

Дополнительные поля тегов связаны с категорией по постоянному ID, подпись берётся из справочника. Переименование переносит прежнее значение из ключа названия в ключ ID в транзакции, не перезаписывая уже заданное значение по ID. Обмен отображает названия полей, сохраняя их идентичность. Договор проектных ID описан в [Постоянных идентификаторах](../../project-identities.md).

### Сверка версии при записи

Экран на общем месте отказов (`shell.md`, «Отказ записи…»).

- Всякая запись пункта (экран и три хука: доп. параметры, маркировка,
  пресеты) идёт через `src/components/dictionary/dictWrite.ts`; прямой `fetch`
  к пунктам роняет `test-dict-version-client`. Записи одного пункта идут по
  очереди, чтобы второй щелчок не спорил с первой своей записью.
- Правила перечня — `changeRules.ts`: код, название, родитель; у категорий со
  служебным кодом вместо кода показывается «Порядок».
- Отказ правки — `ConflictNotice` над содержимым экрана, строка правки
  остаётся открытой с набранным; отказы удаления и создания — окном. Список
  меняется только после принятой записи (оптимистичного обновления нет).
- Открытая запись — пункт, который правят в строке. Удаление пункта уносит
  потомков; открытый у другого потомок удаление запрещает.
- Перестановка двух категорий — два запроса; отказ любого показан, справочник
  перечитан.
- Шаблон тегов: `saveTagTemplate` — `PUT` с `expectedVersion`; с экрана не
  вызывается.
- Проверки: `test-project-dict-version-routes`, `test-dict-version-client`,
  `test-dict-version-ui` (настоящая служба, двое, обе темы).
