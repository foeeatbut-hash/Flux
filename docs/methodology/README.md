# Методология Flux

Единые правила, по которым делается программа. Нужны затем, чтобы
двадцать разделов выглядели и вели себя как одна программа, а не как
двадцать отдельных, и чтобы следующий экран не приходилось придумывать
заново.

Методология обязательна для любого нового экрана и для любой правки
существующего. Если правило мешает, его меняют здесь, с причиной, а не
обходят на месте: иначе через полгода правил снова будет двадцать.

| Часть | О чём | Состояние |
|---|---|---|
| [01 — Дизайн](01-design.md) | Меры, шрифт, цвет, поверхности, компоненты, запреты, проверка | действует |
| [02 — Логика](02-logic.md) | Данные, запись, права, ошибки, обновления в реальном времени | заготовка |
| [03 — Программы](03-programs/README.md) | Страница на каждую программу: раскладка, особенности, исключения; позже — её логика | заполняется по мере перевода |
| [04 — Проверки](04-testing.md) | Каждое действие и связь, доказательства результата, интерфейс и выпуск | действует; паспорта существующих программ внедряются поэтапно |

## Как применять

- **Новый экран** делается по методологии целиком, без исключений.
- **Старый экран** переводится по методологии целиком, когда правка его и
  так перекраивает (новая панель, новая таблица, перестановка блоков) или
  когда об этом просит владелец. Мелкая правка в старом экране — исправление,
  новое поле, новая кнопка — делается по правилам методологии в пределах
  того, что трогается, а остальной экран не переделывается: иначе каждая
  мелочь превращается в переделку раздела. Такой экран, если его ещё нет в
  списке «С чего начинать» в [01-design.md](01-design.md#с-чего-начинать),
  туда дописывается — переводят его отдельным проходом.
- **Исключение** возможно, но записывается в конце нужной части: где, почему и
  до какого времени. Исключение без записи — это дефект.
- **Макеты** рисуются на стендах `docs/stand/design/*.html`: там же лежит
  образец для каждого типового экрана, и программу при этом трогать не нужно.

## Откуда взялось

Методологию написали после разбора всех разделов в сентябре 2026. Замеры
показали, что старые экраны одновременно мелкие и рыхлые:
- основной текст 11–12 px;
- строка журнала 78 px, строка сотрудника 51 px;
- жирным набрано до 61 % текста экрана;
- заглавными — до 36 %;
- зелёный встречается в разметке 2612 раз.

Новые экраны (Проводник, Каталог, Конструктор) выглядели ровнее — за основу
взяты они и то, как устроены популярные рабочие программы:
- Linear;
- Windows 11 (Fluent 2);
- GitHub (Primer);
- IBM Carbon;
- JetBrains (Islands);
- Figma (UI3).
