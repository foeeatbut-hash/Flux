# Постоянные идентификаторы проекта

## Решение владельца

Вместо UUID для связей Справочника, Тегов, Оборудования и E3Flux используются постоянные ID с привязкой к проекту. Владелец выбрал полную замену существующих проектных идентификаторов, а не второе отображаемое обозначение. Сборка программы пока не требуется.

Проект получает `PRJ-000001`. Его сущности получают собственные последовательности: `PRJ-000001-EQ-000001` для позиции оборудования, `TAG` для тега, `SYS` для установки, `MB` для моноблока, `DICT` для справочника, `FLD` для категории дополнительного поля и `DI` для остальных записей справочника. Счётчики общие для сотрудников одной базы. Независимые базы не координируют свои номера: импорт другой базы требует сопоставления, а не объединения по одному тексту ID.

Тег, название, адрес в расчёте и порядковый номер XML не определяют личность позиции. Назначение или переименование тега не меняет ID. Дочерние позиции связаны с владельцем по `parentElementId`. Существующие бизнес-коды опубликованных моделей Каталога сохраняются; выбранная модель применяется к конкретной позиции по её ID. ID пользователей, сессий и переписки не входят в эту замену связей инженерных программ.

## Поля справочника

`Tag.metadata.dynamicFields` хранит значения по ID категории DictionaryItem. Подпись берётся из справочника при отображении и выгрузке. Для прежних данных поддерживается чтение по названию. Переименование категории переносит прежнее значение в ключ ID, сохраняя исходные данные; уже заданное значение по ID имеет приоритет. Запись защищена проверкой прежнего значения и транзакцией.

## Переход существующего проекта

Владелец открывает «Настройки → База данных → ID проектов и оборудования». Предпросмотр не изменяет базу: он показывает новые ID, число ссылок и причины, мешающие переносу. Применение проверяет, что план не устарел, и переносит первичные ключи, внешние ссылки и поддержанные структурированные ссылки одной транзакцией. История миграции сохраняет соответствие прежних и новых ID для проверяемого отката; это журнал, а не дополнительные рабочие идентификаторы.

Неподдержанный формат ссылки блокирует весь перенос. Тексты документов, писем и характеристик не подвергаются поиску с заменой. При отмене проверяется актуальность данных; более новые изменения не затираются. Локальные ссылки на XML обновляются по журналу на каждом компьютере, сохраняя capability Проводника и путь файла.

Если проект уже связан с внешним E3, его `FLUX_BLOCK` и другие атрибуты связи находятся также в файле E3. Замена только базы Flux разорвала бы эти связи. Предпросмотр показывает это препятствие и таблицу соответствий; применение блокируется до согласованного переноса внешних связей. `FLUX_PROJECT` — самостоятельный ключ связи с проектом E3, его не заменяют по догадке.

## XML без тега

Источнику нужен проект и конкретная позиция. Для позиции без тега пользователь явно выбирает целевой узел XML; сохраняется адрес выбора и отпечаток его исходных признаков. Это не выдуманный постоянный ID поставщика. Если по тому же адресу оказался другой узел, нужна повторная проверка выбора. Парсер выдаёт план; изменение инженерных данных остаётся отдельным явным применением. Двусмысленное сопоставление не создаёт автоматически второй экземпляр и не заменяет прежнюю позицию.
