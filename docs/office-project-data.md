# Данные проекта в файлах Flux Office

Документ и Таблица Flux Office правят настоящие `.docx` и `.xlsx`. Шифр проекта, марка тега, расход установки, ревизия строки ВДР и подписи «Разработал / Проверил / Утвердил» попадают в файл **полем**, а не текстом. Поле помнит, откуда взялось значение, и «Обновить поля» подставляет сегодняшнее по всему файлу.

## Как поле держится в файле

Разведка на редакторах GenOffice проверяла одно: переживает ли якорь цикл «вставить → поправить абзац → сохранить → разобрать файл».

| Где | Якорь | Итог разведки |
|---|---|---|
| Документ | поле Word `DOCPROPERTY "flux:<ключ>"`, видимый текст — результат поля | переживает правку абзаца и сохранение |
| Документ | закладка `w:bookmarkStart` | **теряется** при правке абзаца |
| Документ | элемент управления `w:sdt` с `w:tag` | **теряется** при правке абзаца |
| Таблица | определённое имя `FLUX_<ключ>` на ячейку | движок хранит имена и пишет их обратно, в том числе новые |

Отсюда выбор: в Документе — поле DOCPROPERTY, в Таблице — определённое имя. Договор ключа один на окно, сервер и проверки: `office/fieldKeys.ts`.

## Как поле вставляется

- **Документ.** Вставить готовое поле Word редактор GenOffice не умеет. Поэтому панель вставляет в место курсора метку `{{ключ}}` — обычный текст, который переживает любую правку. «Обновить поля» превращает метку в поле и подставляет значение (`fillDocxMarkers` в `server/officeFields.ts`). Метку можно набрать и руками — например, в шаблоне Word: «Шифр {{project.code}}».
- **Таблица.** Значение ставится в выделенную ячейку, и на неё сразу вешается имя `FLUX_<ключ>`. Это делает сам редактор через фасад Univer (`tools/genoffice/inject/sheets-collab.ts`, событие `flux:insert-field`).

## Обновить поля

`POST /api/project-data/files/:id/update` (`server/routes/projectData.ts`):

1. Метки `{{…}}` превращаются в поля (только Документ).
2. Значения полей пересчитываются по ключам (`resolveKeys` в `server/projectFields.ts`).
3. В файле меняется только результат поля или ячейка имени. Остальной XML и остальные части файла остаются байт в байт; если ни одно значение не изменилось, файл не переписывается вовсе.
4. Запись идёт через общее ядро `writeOfficeFile`: право на запись, сверка версии, откат в `FileVersion`.

Если файл открыт, сервер его не трогает — с одним исключением. Когда запрос пришёл из окна самого редактора (`fromEditor`) и в файле никого, кроме этого человека, нет, окно сначала записывает свои правки, а после обновления открывает файл заново. Если файл открыт у других, ответ 423: запись в обход чужого окна спорила бы с тем, что видит другой.

## Ключи

| Ключ | Что это |
|---|---|
| `project.code`, `project.name`, … | поля проекта |
| `doc.name`, `doc.code`, `doc.revision`, `doc.title` | файл и его строка ВДР |
| `tag[AHU-1].brand`, `tag[AHU-1].param:Группа\|Ключ` | тег и характеристики его оборудования |
| `el[П1].name`, `el[П1].param:Группа\|Ключ` | позиция оборудования |
| `vdr[<шифр>].revision` | строка ВДР |
| `sign.prepared.name`, `sign.prepared.date` | подпись; также `checked` и `approved` |
| `today`, `year` | дата |

## Умные блоки

Блок — это диапазон книги с именем `FLUX_BLOCK_<n>` плюс запись `OfficeBlock`: какой запрос к данным проекта собирать и по какому состоянию проекта блок собран (fingerprint). Маршруты уже есть:

- `GET`/`POST /api/project-data/blocks`;
- `POST …/blocks/:id/build` и `…/built`.

«Обновить поля» пересобирает и блоки. Кнопки создания блока в панели пока нет — это следующий шаг.
