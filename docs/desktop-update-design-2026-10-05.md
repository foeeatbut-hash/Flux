# Рабочий стол, вход и обновления Flux — поведение и проверка

Дата: 5 октября 2026. Основание: обращение №14 из Flux 1.20.8 и уточнения владельца.

Документ описывает целевое поведение и критерии проверки. В рабочем дереве реализованы локальный выход при отказе БД, сохранение документов перед выходом, изоляция окон по профилю, защита от повторного открытия закрытых и свёрнутых окон, постоянная панель Flux, использование рабочих областей мониторов с сохранением панели Windows, компактный Пуск, общие значки и перенос установочного профиля владельцем. Встроенные файловые инструменты убраны из списков самостоятельных программ; диагностический пакет включает записи API/БД и события окон. Внедрение значков разрешено владельцем отдельным сообщением.

Реализованы вложенные папки Flux и назначаемые через общую БД обновления. Подписи проверяются в локальном обработчике и главном процессе Electron; внешний адрес Flux-сервера не нужен. Перечисление дисков использует данные Windows; системная корзина сейчас открывается отдельным штатным окном Windows — встроенный просмотр и восстановление корзины внутри Flux пока не реализованы. Реальное размещение HWND на нескольких мониторах и установка portable на компьютерах компании требуют проверки на Windows. Событие запуска новой версии не подтверждает её исправную работу: автоматический откат по проверке работоспособности пока отсутствует. При недоступной БД выход прекращает локальный доступ, а отзыв сессии на других устройствах повторяется после восстановления связи; очередь повторов в текущей реализации хранится в памяти процесса. Portable с этими изменениями пока не выпущен.

Последнее ограничение владельца: стилистику и дизайн нынешних программ существенно не менять — аккуратно доработать. Сохраняются привычная палитра, шрифты, формы элементов и знакомые силуэты значков. Отступы, читаемость, плотность и недостающие действия улучшаются в существующем оформлении. Запрошенные функциональные изменения не означают разрешение на общий визуальный редизайн. Предыдущий референс с глянцевыми объёмными значками программ не утверждён; направление заменено на доработку существующих контурных значков.

## 1. Что установлено по обращению

| Наблюдение | Подтверждение | Вывод |
|---|---|---|
| Выход не выполняется | Два отдельных POST /api/logout возвращают 503 | Ошибка подтверждена. Точный отказ БД в старом пакете не виден |
| Вход старого администратора отклонён | Два POST /api/login с 403; код блокирует установочную учётную запись по идентичности | Смена пароля не снимает эту блокировку |
| Проверка прежней сессии отклонена | Один GET проверки сессии с 401 | Может быть нормальным истечением/отзывом сессии; отдельно не объявлять поломкой |
| Медленное оборудование | Запрос оборудования до 5085,8 мс | Нужна цепочка API → операции БД, чтобы отделить выборку от подготовки ответа |
| Короткие зависания | Три уникальных разрыва кадров 190–350 мс; длительные задачи 55–82 мс | Не считать отсутствие крупных зависаний доказательством плавности |
| API/БД не попали в пакет | Оба источника пустые; фильтр чтения искал traceId вместо записываемого trace | Дефект сборщика исправлен; старый пакет сам от этого не дополнится |
| Окна открываются сами | Сообщение пользователя; журнал не фиксирует причины открытия внутренних окон | Проверить повторную навигацию, обновление прав и восстановление последнего пути; причина пока гипотеза |
| Панель Flux скрывается | В коде режима всех мониторов есть таймер 900 мс | Убрать автоскрытие полностью |
| Белая полоса снизу | Снимки пользователя | Причину геометрии необходимо воспроизвести на Windows; не объявлять исправленной по чтению кода |

Журнал содержит зеркальные записи интерфейса в Electron. Пять ошибочных HTTP-запросов не следует считать десятью ошибками из-за этих копий. Часть log.error не содержит класса/кода ошибки — свободный текст заменять структурированными безопасными полями, а не включать сообщения целиком.

## 2. Единое поведение рабочего стола

### Мониторы и две панели задач

Панель Windows всегда видна при обычном окне, разворачивании на одном мониторе и покрытии всех выбранных мониторов. Старую настройку её скрытия убрать; сохранённое значение «скрывать» перестаёт применяться. Flux занимает доступную рабочую область Windows, учитывая фактическое положение системной панели на каждом мониторе. Не включать собственный режим поверх всех окон ради покрытия экрана.

Панель Flux постоянно раскрыта у нижней границы своей области. Ни таймер, ни выход мыши, ни потеря фокуса не скрывают её. Панель Windows располагается снаружи этой области. Не вычитать её высоту повторно и не рисовать белую заглушку между панелями. Если панель Windows автоматически скрывается по собственной настройке Windows, Flux не должен переопределять пользовательскую настройку ОС или накрывать её область появления.

При двух мониторах разной высоты, отрицательных координатах и размещении буквой Г область приложения состоит из действительных рабочих областей экранов. Промежутки между экранами не заполнять прямоугольной подложкой. Размеры интерфейса задавать в логических пикселях; физические координаты значков Windows переводить с учётом масштаба каждого монитора.

При отключении экрана вернуть окна на доступный экран, сохранив размеры насколько возможно. Закрытые окна не создавать; свёрнутые оставлять свёрнутыми. При повторном подключении экрана восстановление положения не должно восстанавливать закрытые окна. Смена темы, DPI, проекта, прав, списка мониторов и уведомлений не является командой открытия программы.

### Значки и рамка

Один набор размеров, отступов, контрастности и состояний для рабочего стола, Пуска, панели задач, файловых списков и диалогов выбора файла. На разных мониторах значок имеет одинаковый визуальный размер с поправкой на DPI. Не растягивать маленький PNG до крупного значка: подготовить векторные оригиналы и необходимые нативные размеры.

Рабочий стол зеркалит доступные позиции Windows; недоступность чтения координат показывать как ограничение синхронизации, не выдавать собственную сортировку за точное зеркало. Значки системных программ Flux на стол автоматически не добавлять.

Граница основного окна: тонкий контрастный контур и мягкое скругление в обычном режиме. При покрытии рабочей области исключить наружные поля, белые полосы и обрезанные углы. Состояния активного и неактивного окна различимы без яркой рамки. Фон, цвет контура и подписи работают в обеих темах и высокой контрастности.

## 3. Папка и Проводник — одна файловая программа

Уточнение владельца: отдельный значок/программа «Проводник», дублирующий папку, не нужен. Двойной щелчок по любой папке открывает единое окно Проводника в этой папке. Переход к «Этот компьютер», сетевой папке или корзине меняет место внутри той же файловой программы. В референсе не разделять папку на жёлтый файловый значок и отдельный бирюзовый «Проводник».

Допускается несколько окон разных папок, как в Windows, но это экземпляры одной программы с одинаковыми действиями, историей переходов и файловым движком. В панели задач — группа открытых папок с одним типом значка; в предпросмотре видны названия конкретных папок. Не создавать второй изолированный файловый раздел Flux.

Окно содержит вкладки папок, назад/вперёд/вверх, редактируемый адрес, поиск в текущем месте, боковую навигацию, список файлов и сведения. Переключаемые виды: значки, список, таблица. Таблица имеет имя, тип, размер, дату изменения; колонки регулируются и запоминаются. Адрес допускает локальные пути, UNC и подключённые сетевые диски. Недоступная сетевая папка не блокирует всё окно: показать её состояние и повторить подключение по команде.

«Этот компьютер»: настоящие диски Windows, свободное/общее место, подключённые сетевые диски и доступные стандартные папки. Это требует перечисления томов ОС, а не рисования заранее заданных C:, D:, E:. «Корзина»: настоящая корзина Windows, восстановление исходного пути, подтверждение окончательного удаления. Сетевые файлы могут удаляться без системной корзины — предупреждать перед таким действием. Черновики, существующие только в Flux, имеют собственное безопасное восстановление и не выдаются за файлы корзины Windows.

Редактирование, переименование, перемещение и удаление опираются на реальные права файловой системы. Программа не обещает доступ к любому файлу только потому, что он виден. Открытый/заблокированный файл, потерянное соединение SMB, исчезнувшая папка, конфликт версии и недоступный диск имеют отдельные понятные состояния без зависания интерфейса.

### Папки только в Flux и создание через правый щелчок

В меню рабочего стола и свободной области папки оставить подменю «Создать в Flux»: «Папка», «Документ», «Таблица», «Текстовый файл», «Архив». Список форматов ограничен реально поддерживаемыми редакторами. Не возвращать сюда закрепление программ или длинный список приложений. Отдельное «Создать в Windows» создаёт реальную папку/поддерживаемый файл сразу в текущем месте. Название команды прямо показывает, где появится объект; последующее сохранение содержимого не должно незаметно менять этот выбор.

Созданная только в Flux папка видна в том же окне и рядом с файлами Windows, но до явной команды не появляется в файловой системе Windows. Внутри допускаются вложенные папки, документы и архивы только Flux. Они сохраняются между перезапусками, переименовываются и перемещаются как целая структура. У такой папки та же базовая иконка папки и отметка с логотипом Flux в нижнем левом углу. Ссылки на реальные объекты Windows внутри виртуальной папки показываются как ссылки; их экспорт не означает неявное копирование или удаление чужого исходного файла.

«Сохранить в Windows» для папки сохраняет её целиком: все вложенные папки, доступные документы и архивы. Для папки, созданной в известном месте Windows, место назначения уже определено, повторного выбора пути нет. Если объект создан в виртуальном месте без родителя Windows, выбрать место один раз; последующие операции используют выбранную связь. Неподдерживаемый экспорт конкретного документа показывается до начала и не превращается в пустой файл. Документы сериализуются в корректные внешние форматы, а не переименовываются из внутренних JSON в .docx/.xlsx.

Порядок сохранения целой папки:

1. Зафиксировать состав и версии объектов, сохранить текущие правки редакторов; показать путь, число файлов и выявленные конфликты. Для обычной небольшой папки без конфликта не заставлять выбирать каждый файл.
2. Проверить права, доступное место, длины путей, недопустимые имена Windows, совпадения имён без учёта регистра, заблокированные файлы и доступность сети. Не удалять отсутствующие во Flux файлы из уже существующей папки Windows.
3. Подготовить все файлы во временном месте с проверкой формата. Где файловая система позволяет, завершить перенос готовой новой папки одним переименованием. Для существующей папки и SMB не обещать общую атомарность: вести журнал операций и возможность восстановления.
4. При ошибке или отмене сохранить исходную структуру Flux и сообщить, какие внешние файлы успели появиться. Не присваивать всей папке состояние «сохранена», если часть файлов не записана. Убирать только собственные временные данные; не удалять файлы коллег при откате.
5. После успеха установить устойчивые связи внутренних объектов с внешними файлами. Повторное сохранение не создаёт копии с новыми именами без причины. По умолчанию дальнейшая работа отражается в этих файлах, а отметка «Только Flux» исчезает у успешно опубликованных объектов; теги, ревизии и общий доступ сохраняют связь с объектом.

Для конфликтов показать «Оставить обе версии», «Заменить выбранные» и «Пропустить», применимые ко всему одинаковому классу конфликтов. Замена требует явного выбора. Обновление коллегой между предпросмотром и записью вызывает повторную проверку, а не потерю его изменений. Изменение состава папки во время экспорта отделяется от зафиксированной версии: новые правки обозначаются как ещё не сохранённые в Windows. Символьные ссылки/переходы не позволяют выйти за пределы выбранного дерева; циклы не обходятся бесконечно.

Создание архива только в Flux открывает короткое окно: имя, содержимое из текущего места и формат, который действительно поддерживается движком. Без ручного выбора всего содержимого по одному файлу: папки включаются с вложенной структурой. Для пустого архива создать корректный архив, а не файл-заглушку. Не обещать запись RAR без поддерживаемого лицензированного движка; безопасный начальный формат — ZIP. Операции создания, просмотра, изменения и извлечения не смешивать с состоянием общего доступа. «Сохранить в Windows» для папки включает готовый архив как файл, не распаковывает его автоматически.

Общий доступ к виртуальной папке распространяется по явной модели прав на вложенные объекты; запрет конкретного дочернего файла не обходится сохранением всей папки или упаковкой в архив. При отзыве общего доступа структура исчезает у получателей, а исходная папка владельца и опубликованные им файлы остаются. Уже сделанную внешнюю копию невозможно гарантированно удалить с компьютера получателя — интерфейс не должен обещать обратное.

## 4. Стиль значков для согласования

База файловых значков: узнаваемые папка, документ, компьютер и корзина, умеренная детализация без лишнего декора. Значки программ сохраняют нынешние контурные формы и нейтральную палитру; дорабатываются читаемость, согласованность линий и масштаб. Логотип Flux используется в отметке «Только Flux» и элементах бренда, не заменяет тип файла и не ставится на каждый внешний документ. Не переносить объёмное оформление файлов на все кнопки и значки программ.

| Объект | Базовый вид | Отметки |
|---|---|---|
| Папка / открытая папка в панели | Один узнаваемый значок папки | Не отдельная иконка другой программы |
| Поддерживаемый документ | Различимые символы текста, таблицы, PDF и других поддерживаемых форматов | Тип определяется фактическим форматом, а возможность открытия — проверкой редактора |
| Другой неподдерживаемый файл | Единый нейтральный значок | Подсказка: тип файла и действие открытия в Windows, если оно доступно |
| Только внутри Flux | Базовый тип документа или папки | Маленькая отметка с логотипом Flux в нижнем левом углу |
| Общий доступ | Базовый тип документа | Значок пользователей справа снизу |
| Только Flux и общий доступ | Базовый тип документа | Обе отметки одновременно |
| Этот компьютер, корзина | Понятные разные силуэты | Используют то же семейство оформления |

Отметки не закрывают W/X/PDF или основной символ формата. В малых размерах выделить для них наружный запас; при слишком маленьком режиме оставить читаемую отметку состояния в строке и подсказке. Выделение файла — подложка, а не перекрашивание его символа. Ошибка доступа и неподдерживаемый формат — разные состояния: не обозначать оба одним замком.

Последнее уточнение владельца: отметка «Только Flux» находится именно снизу слева, содержит логотип Flux и не заменяется буквой F. Общий доступ находится снизу справа. Правило одинаково для папок и файлов; обе отметки могут присутствовать одновременно.

У программ свои понятные силуэты: оборудование, теги, сотрудники, почта, сообщения, настройки, игры. Различать их формой, не только цветом. Значки на панели без подписей, но с названием при наведении/фокусе клавиатуры, доступным именем для экранного диктора и предпросмотром нескольких окон.

Детализация программ должна сохраняться в малом размере. Основа — нынешние значения реестра программ: оборудование — вентилятор, теги — бирка, сотрудники — группа людей, каталог — книги, конструктор — блоки, почта — конверт, сообщения — два прямоугольных облака, Flux Play — геймпад, настройки — шестерня. Документ, таблица, PDF и архив — встроенные файловые функции, а не отдельные программы: их символы используются у файлов, в командах создания и у действительно открытых окон. Не заменять знакомые формы новой техникой, молекулярной схемой или композицией из шара и карты. Улучшить толщину и согласованность линий, пропорции, контраст и необходимые мелкие детали, сохранив узнаваемость. Фирменные акценты не превращают все приложения в одинаковую букву F. В референсе показываются крупный силуэт и варианты 20/24/32 пикселя, включая состояние открытой программы на панели.

## 5. Пуск и панель задач Flux

Уточнение владельца: «Документ», «Таблица», «PDF» и «Архиватор» исключены из самостоятельных программ, поиска программ, закреплений Пуска/рабочего стола и постоянных кнопок панели задач. Старые закрепления этих маршрутов игнорируются. Существующие файлы и прежние ссылки продолжают открываться встроенными редакторами. Создать Word/Excel/текстовый файл/архив — команды файлового меню; PDF открывается для просмотра и редактирования. Временная кнопка реально открытого файла сохраняется на панели до закрытия окна. Блокнот этим изменением не удаляется. Группа «Flux Office» со списком отдельных редакторов в Пуске больше не нужна.

Пуск становится компактнее за счёт уменьшения пустых областей, а не нечитаемых подписей. Сохранить нынешнее спокойное оформление меню и панели: не добавлять глянцевые поверхности, декоративные градиенты и новую палитру. Поиск сверху; закреплённые программы плотной сеткой; «Все программы» открываются компактным списком с поиском. Не выводить все программы сразу огромной стеной. Недавние документы — ограниченный список и раскрытие остальных по команде; пустой блок не занимает место. Профиль и выход — небольшой постоянный подвал.

Предварительные размеры: меню 420–480 логических пикселей, ограничено доступной рабочей областью; область нажатия программы не менее 40 пикселей; значок сетки 24–28, панели задач 20–24. Проверка длинных русских названий обязательна. Сетка не обрезает «Оборудование» и «Документооборот»; при узком экране используется список. Эти размеры уточняются измерением макета, а не объявляются окончательными до визуальной проверки.

Панель: Пуск и поиск → открытые/закреплённые программы без текстовых подписей → выбор проекта → «Обновление», когда доступно → статус, время и уведомления. При нехватке места программы уходят в раскрываемую группу; выбор проекта и обязательное предупреждение обновления сохраняются. Название проекта не убирать: сотруднику важно понимать, с какими данными он работает.

Пуск и всплывающие панели появляются на том мониторе, где вызваны. На нескольких мониторах один запрос обновления и одно уведомление, без параллельных копий. Esc закрывает меню; стрелки перемещают фокус; Enter запускает; выход мыши не скрывает панель задач.

## 6. Окна не открываются без действия пользователя

Открывать/восстанавливать окно могут явный запуск, щелчок по его кнопке, переход по выбранной ссылке и подтверждённое восстановление сеанса. Обновление прав, профиля или фонового состояния не открывает окно.

Каждая команда открытия имеет источник, идентификатор и номер текущего сеанса. Повтор одной команды не создаёт дубль. Закрытие делает устаревшими отложенные переходы и ответы этого окна. Свёрнутое окно продолжает работать без восстановления поверх других. Окна и последний путь хранятся отдельно для каждого профиля; после выхода предыдущий пользователь не оставляет свои окна следующему.

В диагностике: безопасные идентификаторы окна/сеанса, действие open/close/minimize/restore/focus, источник команды, шаблон раздела, состояние до/после и номер команды. Не писать адрес конкретного документа и его содержимое. Это позволит отличить фактическую команду запуска от побочного восстановления маршрута.

## 7. Выход и старый профиль администратора

Перед выходом предложить сохранить несохранённые документы. «Отмена» сохраняет текущую сессию. Ошибка сохранения не должна молча уничтожать правки. Двойной щелчок выхода не запускает две операции.

Разделить завершение локальной работы и отзыв серверной сессии. После подтверждённого выхода очистить локальный токен, профиль, окна, подписки и доступ к данным старого сеанса. Запоздавшие ответы сети не могут снова заполнить его состояние. Отказ БД не должен навсегда удерживать пользователя внутри профиля. При этом локальное завершение не означает, что украденная копия токена уже отозвана: сохранять безопасную задачу повторного отзыва и показывать администраторам реальное состояние. Не убирать проверку сессии ради исправления выхода.

Старый установочный администратор блокируется независимо от пароля — это действующее ограничение безопасности. Для личного профиля нужен понятный вход владельца и управляемое преобразование существующей записи в обычного администратора: сохранить идентификатор, авторство документов, проекты, историю и права; убрать установочный статус только после подтверждения владельца. Не создавать ещё одну общую учётную запись и не включать прежний профиль автоматически после смены пароля. Переименование/преобразование объяснить в мастере одним действием, без технических терминов для сотрудников.

## 8. Тексты и экран входа

Для сотрудника убрать сведения о ключах, подписи выпусков, владельце как издателе, внутреннем сервере, устройстве БД и процедуре лицензирования. В интерфейсе остаётся то, что помогает выполнить действие. Правила доступа продолжают действовать и проверяться; недоступное действие объясняется простым сообщением и возможностью обратиться ответственному.

| Сейчас | Предлагаемый текст |
|---|---|
| Выпуски публикует владелец… подписанные обновления компании | Доступна новая версия. Посмотрите изменения и обновите программу |
| Администратор применяет подписанный ключ владельца | Редактирование временно недоступно. Обратитесь к ответственному |

| Объяснение серверной/лицензионной архитектуры | Убрать из обычного рабочего интерфейса |

Проверить Пуск, настройки, каталог, оборудование, теги, документы, сотрудников, игры, сообщения, уведомления, окна ошибок и подсказки. Сведения для диагностики и управления оставить в специально доступных ответственным инструментах. Не удалять понятные сообщения о недоступности действия и не выдавать отсутствие прав за пустые данные.

На входе убрать «рабочее место инженера» и год в нижнем правом углу. Показывать фактическую версию запущенного Flux из сборки; не менять её вручную строкой. При расхождении версии интерфейса и исполняемого файла диагностика фиксирует обе, сотрудник видит версию приложения. Возле названия Flux допускается компактное обозначение версии.

## 9. Обновления через общую MariaDB компании

Сохраняется выбранная архитектура: компания использует существующую MariaDB/MySQL, приложения обмениваются данными через неё. Отдельный публичный адрес HTTP-сервера не требуется. Локальный API portable — внутренняя часть программы, его диагностика нужна даже при таком подключении. Не заменять MariaDB на PostgreSQL из-за прежней путаницы в названии.

### Обычное обновление

Раздел «Обновления» убрать из настроек. Доступный выпуск включает кнопку «Обновление» рядом с проектом в панели задач. Кнопка открывает самостоятельное небольшое окно с номером версии, понятным списком изменений, размером загрузки, «Обновить» и «Позже»/закрыть. Старые внутренние ссылки на настройки обновлений ведут в это окно, а не в исчезнувшую страницу.

Напоминание раз в десять минут с момента последнего показанного напоминания. Закрытие окна не сбрасывает таймер; разные мониторы и окна не плодят уведомления. При загрузке, установке и ошибке соединения не спамить тем же сообщением; показать текущее состояние. Проверка наличия выпуска запускается один раз на приложение и повторяется с ограниченной частотой, без нового набора IPC-подписок при каждом открытии настроек.

Проверка подписи и контрольной суммы остаётся внутри механизма обновления. Пользователь не должен разбираться в подписи, но приложение обязано отклонить изменённый файл, подмену выпуска и откат версии. Запись в БД сама по себе не делает чужой бинарник разрешённым обновлением.

### Сотрудники и устройства

В «Сотрудниках» показать версию и состояние обновления. Один сотрудник может пользоваться несколькими компьютерами: строка показывает «разные версии», раскрытие — конкретные устройства и время последней связи. Версия не известна — отдельное состояние, а не «актуальная». Выход сотрудника не удаляет историю устройства.

Отмечаются сотрудники/устройства с устаревшей версией. «Выбрать всех устаревших» применяется ко всему выбранному набору, включая следующие страницы, и показывает точное число; фильтр учитывается явно. Для неактивных/offline устройств показывается отдельное количество. Администратор выбирает выпуск, сотрудников, таймер; по умолчанию десять минут, варианты 5/10/15/30 и ограниченное произвольное значение. Перед запуском — понятное подтверждение версии, количества и времени.

Задание хранится в общей БД с устойчивым идентификатором, точными целевыми устройствами, сроком, инициатором и статусом. Каждый клиент подтверждает получение, скачивание и фактически запущенную новую версию. Повторное получение одного задания не запускает вторую установку. Смена проекта не меняет срок. Версии сравнивать корректно, например 1.20.10 новее 1.20.9.

### Принудительное обновление без потери работы

Сотрудник видит: «Программа обновится через 10 минут. Завершите работу и сохраните документы» и «Обновить сейчас». Загрузка и проверка идут заранее. Отсчёт опирается на сохранённый срок, не начинается заново после перезапуска, сна или закрытия окна уведомления. Смена системных часов не должна отменять уже полученный отсчёт.

В срок проверить готовность файла, сохранить документы и дождаться подтверждения сохранения каждым редактором. Если файл занят, сеть недоступна или запись конфликтует, сделать защищённую локальную копию восстановления и сообщить о задержке. Если правки нельзя надёжно сохранить даже в копию, остановить автоматический перезапуск и передать причину администратору. Обязательное обновление не означает безусловное завершение процесса с потерей данных.

После сохранения кратко остановить новые изменения, заменить portable атомарно, перезапустить один экземпляр, проверить запущенную версию и отправить подтверждение. При отказе запуска сохранить предыдущий исполняемый файл для отката, не создавать цикл аварийных перезапусков. Открытые сетевые документы не перезаписывать поверх более свежей версии коллеги. Живой игровой сеанс имеет корректное отключение/повторное присоединение; длительные импорты завершаются или останавливаются в безопасной точке.

### Состояния задания и спорные случаи

| Ситуация | Поведение |
|---|---|
| Устройство выключено | Задание ждёт; при следующем входе применяется оставшийся срок или уже наступившее требование |
| БД недоступна | Использовать ранее проверенное задание, если файл готов; получение нового задания не симулировать |
| Скачать к сроку не удалось | Не перезапускать старую версию под видом новой; показать ошибку и повторить с ограничением |
| Выпуск отозван | Остановить установку этого выпуска; уведомить ответственного |
| Уже установлена более новая версия | Не выполнять понижение |
| Две команды на одно устройство | Одно действующее задание; новая команда явно заменяет или отменяет предыдущую |
| Администратор отменил | Клиент получает подтверждённую отмену; состояние остаётся в истории |
| Новый таймер | Явное переназначение с историей, а не скрытое продление |
| Диск заполнен/нет прав на замену EXE | Отказ с безопасным кодом, сохранённая работа, повтор после устранения причины |
| Сотрудник нажал «Позже» | Закрыть добровольное окно; обязательный срок продолжает действовать |
| Программа закрыта пользователем | ОС не блокировать; сохранённое задание проверить при следующем запуске |
| Один сотрудник, два компьютера | Независимые подтверждения и результат установки на каждом устройстве |

Статусы для администратора: запланировано, доставлено, загрузка, проверка, сохранение, перезапуск, обновлено, offline, задержано, ошибка, отменено. Причины ошибки понятны и содержат ссылку на обращение/диагностику. Не считать запись выбранной версии в профиле доказательством установки: подтверждать версию реально запущенного файла. Такое сообщение клиента не является абсолютной защитой от владельца модифицированного компьютера.

### Защита задания в архитектуре с прямой БД

Сохранить разделение прав сотрудников, администраторов и владельца. Обновление принимает только разрешённый проверенный выпуск. Чтобы изменение строки БД не позволяло навязать расписание, команды владельца подписываются; администратор получает ограниченное полномочие на назначение обновлений с проверкой на клиенте. Приватный ключ владельца остаётся в программе владельца, не передаётся сотрудникам и не записывается в БД. Проверяется цель устройства, версия, хэш файла, срок и автор полномочия. Для отмены и замены также нужна проверяемая команда. Эти детали не показываются обычному сотруднику.

## 10. Диагностика: что исправлено и что расширить

Уже исправлено в рабочем дереве:

- Чтение отбирает data.trace, как записывают API и БД.
- Перед сбором серверных источников очередь сбрасывается на диск.
- Пустой список разрешённых запросов возвращает пустой результат, а не весь журнал.
- Сервер и БД имеют собственные контрольные суммы, размеры UTF-8 и границы времени.
- Ошибка обработчика выхода содержит безопасный класс, код, место и связь с запросом.
- Регрессионные проверки включают реальный обработчик выхода с искусственным отказом, фильтрацию разных сотрудников, отсутствие токена/текста драйвера и границы размера.

Следующее расширение: причины открытия/закрытия внутренних окон, этапы сохранения документов, применённые рабочие области мониторов, жизненный цикл задания обновления и попытки повторного отзыва сессии. События имеют общую метку действия; исходные и зеркальные записи не считать независимыми ошибками.

Проверка существующей реализации папок: виртуальное дерево в БД и рекурсивное создание ZIP/7z уже существуют. Сохранение в Windows сейчас рассчитано на один файл; обработчик пропускает папки. Рекурсивный перенос дерева папки в Windows — новая работа, а не переименование существующей кнопки. Переиспользовать проверенный обход архивирования и проверки доступа, сохраняя отдельные правила конфликтов файловой системы.

Безопасные поля: версия, ОС/архитектура, шаблон раздела/маршрута, фаза, время, код, модель и тип операции БД, число строк, идентификаторы связи. Не включать SQL, значения параметров, строку подключения, пароли, ключи, токены, личные пути, текст файлов и сообщений. Очереди, размер и срок хранения ограничены; сбой записи журнала не ломает работу приложения. Отсутствующий/усечённый источник обозначается явно. По пустому источнику нельзя заключать «ошибок нет».

Диагностика по сотруднику не должна выгружать общий серверный журнал. Принадлежность запроса доказывается сервером из авторизованной сессии, а не присланным пользователем идентификатором. Ошибки до авторизации требуют отдельного безопасного контекста локальной установки и проверки границ доступа — не включать весь журнал ради полноты.

## 11. План внедрения и проверка

1. Диагностика и воспроизведение выхода/самопроизвольных окон; исправления жизненного цикла сессии и окна.
2. Постоянные панели задач, рабочие области мониторов и рамка; проверка на Windows с реальными экранами.
3. Согласованные значки, компактный Пуск, подписи и версия; единый Проводник и реальные системные места.
4. Окно обновления, уведомления и версии устройств.
5. Назначение обновления через сотрудников, защищённые задания, сохранение и восстановление после ошибок.

Для каждого этапа отдельный проверяемый результат. Нельзя объявлять выполненной проверку на 1000 взаимодействий, не выполняв её. Матрица ниже задаёт сочетания, а обязательные рискованные последовательности проверяются полностью; остальные сочетания выбираются попарно с дополнительными длинными сценариями.

| Измерение | Варианты |
|---|---|
| Экраны | 1/2/3; равные и разные разрешения; отрицательные координаты; размещение Г; hotplug |
| Масштаб | 100/125/150/200%; разные DPI одновременно; переход окна между экранами |
| Панель Windows | Нижняя/боковая; на одном/всех экранах; собственное автоскрытие ОС |
| Окно Flux | Обычное/один экран/все экраны; активное/неактивное; свёрнутое/закрытое |
| Профиль | Сотрудник/администратор/владелец; истекшая/отозванная сессия; смена прав |
| Файлы | Word/Excel/PDF/неподдерживаемый; папка; ярлык; только Flux; общий доступ; оба статуса |
| Хранилище | Локальное/UNC/сетевой диск/отключённый диск; read-only; блокировка; конфликт |
| Работа | Без изменений/несохранённые изменения/сохранение/импорт/игра; несколько окон |
| Сеть и БД | Норма/задержка/разрыв/ошибка записи/восстановление; два клиента одновременно |
| Обновление | Нет/есть/получено/скачивается/проверяется/готово/ошибка/отозвано/уже новее |
| Управление | Мышь/клавиатура; длинные подписи; тёмная/светлая/контрастная тема |

Обязательные сценарии без сокращения:

- Закрыть окно → сменить проект/права/DPI/получить уведомление → окно не открылось снова.
- Свернуть окно → получить ответ сети/обновление профиля → окно остаётся свёрнутым.
- Выход при исправной БД и при 503 → подтверждённый выход завершает локальный доступ; никакая поздняя загрузка не возвращает профиль.
- Выход с несохранёнными документами → сохранить/отменить/ошибка сохранения; проверить отсутствие потери работы.
- Сотрудник А выходит, Б входит → окна и документы А не восстановились у Б.
- Старый установочный администратор после смены пароля → блокировка понятна; преобразование владельцем сохраняет авторство и данные.
- Два экрана с разным DPI → обе панели видны, белой полосы нет, значки читаемы; отключение экрана не возвращает закрытые окна.
- Папка/Этот компьютер/корзина/UNC → единый Проводник; реальные данные и права; никаких дублирующих файловых программ.
- Создать в Flux папку → вложенные папки, документы и архив → перезапуск → структура сохранена, в Windows ничего не создано самопроизвольно.
- Сохранить целую папку в Windows → дерево, форматы, имена и связи совпали; повторное сохранение не создало дублей.
- Сохранение целой папки + конфликт/ошибка сети/отмена/редактирование во время экспорта → исходные данные не потеряны, частичный результат объяснён, чужие файлы не удалены.
- Общая папка с запрещённым дочерним объектом → сохранение/создание архива не обходят права.
- Напоминание обновления на нескольких мониторах → одна запись раз в десять минут; закрытие диалога не запускает частый повтор.
- 200 сотрудников, страницы/фильтры/несколько ПК → выбор старых версий точен, адресаты и результат видны.
- Назначенное обновление + сон/закрытие/перезапуск/сдвиг часов → срок не сбрасывается незаметно.
- Срок обновления + несохранённый Word/Excel/PDF + недоступная сеть/полный диск → данные сохранены либо перезапуск заблокирован с причиной.
- Подменённый файл/недействительная команда/отозванный выпуск → установка отклонена.
- Ошибка запуска новой версии → восстановление прежней, без цикла рестартов; администратор видит реальный результат.
- Пакет обращения → API/БД связаны с действиями автора; чужие записи и секреты отсутствуют; потерянные источники отмечены.

Текущая проверка диагностики: 22 регрессионных случая экспорта, существующие проверки политики/очистки/ротации, проверки группировки инцидентов, 17 проверок сессий и TypeScript прошли. Проверки расположения панелей на Windows, нового Пуска, значков и обновлений ещё не выполнялись: эти части пока представлены проектом, а не реализованным поведением.


## Проверено при реализации

- Файловый движок: 97 проверок; вложенная публикация, метаданные, циклы, частичный отказ и отсутствие замены чужих файлов.
- Подписанные задания обновлений: 35 проверок; реальный обработчик маршрутов с изолированным транзакционным стендом, конфликт головы, отмена, повреждение подписи и отказ защищённого хранения.
- Сохранение и повтор обновления: 11 проверок реального хранилища интерфейса; отмена и исключение не вызывают установку.
- Выход и окна: 13 проверок жизненного цикла, 19 проверок сессий и отдельная проверка окон Electron с имитацией нативных объектов.
- Панель обновлений сотрудников: 12 браузерных сценариев, включая 27 сотрудников, страницы, фильтр после массового выбора, отмену и отказ связи. Светлая и тёмная темы, ширина 768 px.
- Проводник: сохранён прежний набор браузерных проверок навигации, свойств, запоздалых запросов и общего доступа; добавлены диски, вложенные черновики и публикация. Светлая/тёмная темы, ширины 600–1440 px.
- Программа владельца: все четыре изолированных набора npm test и сборка; добавлена проверка разрешения на назначения обновлений.

Браузерные файловые мосты и транзакционный стенд имитируют ОС/БД. Они не подтверждают доступ к корпоративной MariaDB, поведение реальных мониторов Windows или успешную замену portable-файла на компьютере сотрудника. Полный исторический набор live-проверок не запускался: ему нужны отдельные тестовые учётные записи. Корпоративные пароли в тестах не использовались.
