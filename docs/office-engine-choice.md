# Движок редакторов Flux Office: GenOffice или CasualOffice

Сравнение 24.09.2026 по заданию владельца: «перед внедрением нового офиса
сравни GenOffice и CasualOffice, что лучше, то и внедряй». Оценка сделана
не по описаниям, а по исходникам обоих и по проверке на настоящих
документах из загрузок. Это два бланка ПДХ в Word, два опросных листа
3700 в Word и бланк ПДХ в Excel.

## Итог

**Внедряем GenOffice** (`genspark-ai/genoffice`, Apache-2.0).

Решает сохранность файлов. Для Flux документ — это бланк со штампом,
колонтитулами, элементами управления и печатными настройками, который
дальше уходит заказчику. GenOffice переписывает только то, что изменил
человек, а остальное оставляет байт в байт. CasualOffice перестраивает
файл целиком из своей модели и при этом теряет данные, даже когда ничего
не правили.

## Проверка на документах Flux

### Excel: бланк ПДХ, 146 частей в файле

Правка — одна ячейка.

| | GenOffice (xlsx-gateway) | Casual Sheets (exceljs) |
|---|---|---|
| Частей потеряно | 0 (намеренно убран `calcChain.xml` — Excel строит его заново) | **54** |
| Что потеряно | — | элементы ActiveX (5 шт. с данными и связями), рисунки VML (5), параметры печати (17), связи 6 листов, 5 листов переписаны под другими номерами |
| Не изменилось байт в байт | 141 из 146 | 29 из 146 |
| Изменено | `workbook.xml`, `sheet1.xml`, связи, типы содержимого | почти всё |

### Word: четыре документа

Casual Docs — без единой правки. GenOffice — со вставкой абзаца в начало.

| Документ | GenOffice: потеряно / изменено | Casual Docs: потеряно / изменено |
|---|---|---|
| ПДХ …E020028 (33 части) | 0 / только тело и дата сохранения | 0 частей, но переписаны тело, колонтитулы и связи |
| ПДХ …E020020 (36 частей) | 0 / только тело и дата | переписаны тело, 6 колонтитулов, связи |
| 3700B03AS001A (22 части) | 0 / только тело и дата | переписаны тело, 4 колонтитула, связи |
| 3700A01HU001A (25 частей) | 0 / только тело и дата | переписаны тело, 4 колонтитула, связи |

Что именно Casual Docs сделал с документом 3700B03AS001A без правок:

- **тело документа:**
  - 144 789 → 90 417 байт;
  - потеряно 23 фрагмента текста (`w:t`) из 581;
  - потеряно 13 закладок из 17;
  - снято оформление таблиц (`tblLook` 11 → 0) и 4 выделения цветом;
- **нижний колонтитул** — место штампа:
  - потеряно 7 фрагментов текста из 16;
  - потеряно 4 цвета из 5.

Проверочные скрипты:

- `scratchpad/cmpoff/rt.cjs` — Excel через exceljs;
- `…/genoffice/packages/xlsx-gateway/rt-go.ts` — Excel через GenOffice;
- `…/docx-engine/rt-docx.ts` — Word через GenOffice;
- `…/casual/rt-casual.mjs` и `sz.mjs` — Word через Casual Docs.

## Остальные критерии

| | GenOffice | CasualOffice |
|---|---|---|
| Сохранение файла | правка по месту: меняются только тронутые части, перед записью сверяется хеш файла на диске (чужая правка не затирается) | модель документа → новый файл |
| Word | свой движок `docx-engine`: разбор с привязкой к месту в файле, сохранение правкой абзацев; понимает элементы управления (`sdt`) — на них лягут привязки Flux | `@eigenpal/docx-core` под обёрткой; при сохранении теряет текст (выше) |
| Excel | Univer для показа + свой движок на Rust для больших файлов (окно ячеек, потоковое чтение) + `xlsx-gateway` для записи | Univer + exceljs для ввода и вывода |
| PDF | правка текста внутри страницы через PDFium, перевод PDF → Word на месте | `@casualoffice/pdf` в npm нет (версия 0.0.0 только в исходниках) |
| Совместная работа | **нет** — редактор одного человека | есть: Yjs и Hocuspocus |
| Встраивание | нет пакетов npm: код переносится в Flux, мост к файлам (сейчас IPC Electron) пишется под Flux | готовые React-компоненты из npm |
| Без интернета | всё на машине; ИИ отключается | Docs тянет `@huggingface/transformers` и `@mlc-ai/web-llm` (нейросети в браузере) |
| Размер | Univer, tiptap, движок Rust (сборка под Windows x64 в CI) | 538 МБ `node_modules` у одного Docs |
| Живость | коммиты идут ежедневно (последний — 24.09, №539) | Docs 1.4.2 и Sheets 0.20.0 не обновлялись с 10–12 июля |
| Лицензия | Apache-2.0; каталог `ee/` (закрытая лицензия) пуст и в Flux не берётся | MIT (Docs), Apache-2.0 (Sheets) |

## Что это значит для внедрения

- **Совместную правку GenOffice не даёт.** Для Flux это меньшая потеря, чем
  кажется. По спецификации зеркала файлов (`Flux_File_Mirror_Architecture_RU`)
  документ — настоящий файл на диске или на сетевом ресурсе. Одновременная
  правка там — отдельный этап после журнала и восстановления. Порядок такой:
  1. блокировка «файл открыт Ивановым» и защита от чужой записи — по хешу, это уже есть у GenOffice;
  2. присутствие «кто смотрит» — через сокет Flux;
  3. совместная правка — позже и отдельно.
- **Переносится код, а не пакет.**
  - Из GenOffice во Flux берутся движки `docx-engine`, `xlsx-gateway`,
    `pptx-*`, `pdf2docx` и отрисовка редакторов.
  - Мост к файлам (сейчас `preload` → `ipcMain`) переписывается на
    Electron Flux и на сервер Flux для режима браузера.
  - Функции ИИ и вход через Genspark отключаются: ничего не должно уходить
    с машины без решения владельца.
- **Движок Excel на Rust** собирается в GitHub Actions под Windows x64 вместе со сборкой Flux.
- **Привязки Flux** (теги, поля проекта, подписи, реквизиты ВДР):
  - в Word — элементы управления `sdt`, их GenOffice уже читает;
  - в Excel — именованные диапазоны (`xlsx-defined-names`).

  Те же привязки потом читают плагины Word и Excel — из задания про зеркало.
- **Из пакета CasualOffice** остаётся годным серверная часть: хранение версий,
  токены и журнал из `office-router`. Редакторы оттуда не берём.

## Что проверить до переключения

- Все бланки из `fixtures/` и шаблоны ВДР: открыть, изменить одно поле, сохранить, открыть в Word и Excel — без предупреждения «файл повреждён».
- Большие ведомости Excel (десятки тысяч строк) — время открытия и память.
- Метафайлы EMF в Word — GenOffice их не рисует в node (`converter returned null`). В окне они показываются через свой преобразователь, это проверяется в Electron.
- Режим браузера (без Electron) — мост к файлам через сервер Flux.
