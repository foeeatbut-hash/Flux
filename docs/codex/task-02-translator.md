# Codex 02. Переводчик Flux Office: режимы размещения и устаревшие переводы

## Зачем

Кнопка «Переводчик» в ленте «Flux» открывает `TextTranslationPanel`, а
«Английская версия» — перевод файла проекта. ТЗ §15–16 требует больше: выбор,
куда и как ставить перевод, и выявление устаревших переводов.

## Что сделать

1. Аудит существующего: `src/components/office/TextTranslationPanel.tsx`,
   движок и память переводов, глоссарии, `FileEnglishVersion`, серверные
   маршруты перевода. Не создавать второй механизм — расширять существующий.
   Итог — короткая таблица «требование ТЗ §15–16 → есть / частично / нет» в
   `docs/codex/task-02-audit.md`.
2. Режимы размещения (ТЗ §15):
   - Excel: новый лист, новый файл, соседний столбец, строка под оригиналом,
     в той же ячейке через разделитель, замена с резервной копией;
   - Word: новый DOCX, новая страница, после абзаца, внутри строки/таблицы,
     замена.
   Настройки: весь документ / лист / выделение / шапка; направление; разделитель
   (перенос строки, `/`, `—`, `|`, свой); порядок оригинал→перевод или наоборот.
   Предпросмотр и подтверждение непроверенных сегментов.
3. Защищать при переводе: теги, числа, формулы, обозначения, единицы, ссылки,
   коды, форматирование и **параметры Flux** (плашки/поля в шапке переводятся
   только как отображаемая подпись, источник и fieldKey не меняются — ТЗ §16).
4. Устаревшие переводы: перевод связан с оригиналом; после изменения оригинала
   или ревизии источника такие сегменты помечаются; повторный перевод не
   дублирует уже вставленный.
5. Никаких облачных запросов по умолчанию — только существующий офлайн-движок
   и память переводов.
6. Тесты: модульные на каждый режим размещения и на защиту токенов; живой — по
   образцу существующих тестов перевода (найти через `rg -l translat scripts`).
