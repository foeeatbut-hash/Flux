# Codex 05. Авторевизии XML оборудования и окно «Обновления XML»

Источник — `docs/codex/inputs/tz-explorer-xml.txt`, пункты 7–8. ТЗ Flux Office
v10 §1 требует в «Оборудовании» сохранить импорт XML, ревизии и теги (убрана
только самостоятельная выгрузка) — это задание их развивает.

## Что сделать

1. Авторевизии: папки ревизий вида A/B/C или 1/2/3/10 (сортировка 10 после 3),
   имя родительской папки = тег. Новая ревизия в папке → уведомление,
   сравнение было/стало, жёлтая подсветка изменённых значений до утверждения
   инженером. Новая ревизия не затирает утверждённое и ручные правки; история
   ревизий сохраняется. Запись — по `.claude/skills/flux-data-safety` (план и
   предпросмотр вместо прямой записи, откат).
2. Кнопка «Обновления XML» со счётчиком: таблица — тег, текущая и новая
   ревизия, число изменений, статус; выбор отдельных позиций или всех; цвета
   статусов синий (новое) / жёлтый (ждёт утверждения) / красный (конфликт или
   ошибка); перепривязка папки XML для одной позиции и массово.
3. Учитывать нескольких сотрудников и сетевые папки (не блокировать интерфейс,
   см. задание 03).

Сначала найти существующий импорт XML и ревизии оборудования
(`rg -l "xml" server/routes src/screens/Equipment*`, `docs/methodology/03-programs/equipment.md`)
и расширять его, не создавая второй механизм.

## Не трогать

Flux Office (`tools/genoffice/**`, `src/components/office/**`,
`scripts/officeNative*`, `scripts/test-office-*`).

## Проверки перед PR

tsc; наборы оборудования и импорта XML; новые — на порядок ревизий (A/B/C,
1/2/3/10), сохранение ручных правок, утверждение, массовую перепривязку;
`check:coverage`, `test-architecture`.

## Готово, когда

Новая ревизия в папке распознаётся, сравнивается и ждёт утверждения, ручное не
затирается, окно «Обновления XML» работает с выбором и перепривязкой; тесты
зелёные.
