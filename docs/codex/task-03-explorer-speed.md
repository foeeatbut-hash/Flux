# Codex 03. Проводник: скорость, сеть, рабочий стол, рамочное выделение

Источник — ТЗ владельца `docs/codex/inputs/tz-explorer-xml.txt`, пункты 1, 2, 4
и общие требования. Главное условие владельца: **дизайн не менять** — чинить и
аккуратно добавлять.

## Факты из диагностики (обращение ОБР-000018, Flux 1.20.14, 13.10.2026)

- `windows-files:invoke`: NATIVE_HELPER_FAILED ×11, NATIVE_TIMEOUT ×2–5
  (один вызов 20,7 с), EPERM ×6.
- Сразу после таймаута — пачка успешных вызовов по 3,7–19 с: вызовы копятся в
  одной очереди нативного помощника Windows.
- `/api/office/files/:id/meta` — 278 вызовов за минуты (лишние повторы),
  `/api/office/files/:id` p95 910 мс; `/api/updates/:id` — таймаут 15 с.

## Что сделать

1. Сетевые папки: сначала мгновенно показать список имён, потом догружать
   свойства и значки порциями; не держать один общий канал к помощнику для
   всего — длинный вызов не должен блокировать короткие (отдельная очередь или
   параллельность с ограничением, отмена устаревших запросов при уходе из
   папки). Кэш списка и значков с проверкой изменения.
2. Убрать причины NATIVE_TIMEOUT / NATIVE_HELPER_FAILED / EPERM: найти по коду
   (`electron/` — мост windows-files и нативный помощник) и по логам; EPERM на
   защищённых системных путях — понятное сообщение без повторов, а не ошибка.
3. Недоступная сеть не блокирует программу и другие окна.
4. Убрать лишние повторные обращения к `/api/office/files/:id/meta`
   (найти, кто опрашивает, — кэш/дедупликация).
5. Рабочий стол: без мигания значков при обновлении — точечное обновление
   изменённых, без дублей, позиции сохраняются.
6. Рамочное выделение мышью в Проводнике и на рабочем столе, как в Windows,
   вместе с Ctrl/Shift и Ctrl+A.
