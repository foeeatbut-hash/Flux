# Codex 07. Оборудование: один импорт документов и привязка папки к файлу

Замечания владельца после сборки 1.20.15 (15.10.2026):

- «Не работает привязка документов при загрузке в оборудование: не
  закрепляет за файлом и оборудованием путь папки и не определяет новую
  ревизию при обновлении».
- «Зачем сейчас „Импорт XML установки“ и „Импорт из документов“? Это же по
  сути одно и то же».

Если владелец приложил журналы, они лежат в `docs/codex/inputs/logs-*`.

## Что известно (разведка руководителя по коду)

- Две кнопки — `src/screens/Equipment.tsx` (~647–649).
  - «Импорт XML установки» открывает `EquipmentSourceImportDialog.tsx`: выбор
    XML, проверка, план, `/equipment/source-import/apply` и привязка папки
    `saveEquipmentSourceBinding` (`src/lib/equipmentSourcesLocal.ts` ~89).
  - «Импорт из документов» открывает `DocImportWizard.tsx`: PDF, Excel, Word,
    XML и изображения, разбор через `/api/equipment/parse-calc`. Там
    `ImportFileChooser onFiles` получает `File` без ссылки на место в
    Проводнике, и привязка не создаётся вовсе. Это главная причина жалобы.
- Привязка хранится в `localStorage` отдельно для каждого устройства и
  пользователя. Сервер папку не знает, есть только маршрут `rebind-folder` в
  `server/routes/equipmentXmlSources.ts`. Значит, на другом компьютере и у
  коллег ревизии не находятся.
- `ImportFileChooser.tsx` (~192): из окна Проводника `onWindowsFile(ref, stat)`
  вызывается без третьего аргумента. Поэтому `sourceFolder` и `suggestedTag`
  всегда пусты, и срабатывает запасной `sourceFolderFor` (~250–255).
- Образец общей привязки по сетевому пути уже есть: привязка папок к проекту
  (`server/routes/projectFolderBindings.ts`, `electron/filesystem/network.ts`,
  действие моста `locationKeys`). Папка там узнаётся по UNC: буква диска
  переводится в `\\сервер\папка`, наружу уходит только sha256.

## Что сделать

1. Одна кнопка «Загрузить документы» вместо двух. По типу файла:
   - XML установки (CAD-экспорт, `looksLikeCadExport`) идёт по пути
     источника XML с привязкой и ревизиями;
   - бланки и расчёты (PDF, Excel, Word, прочий XML) идут на разбор.

   Один мастер, общий предпросмотр и план перед записью
   (`.claude/skills/flux-data-safety`). Старые две кнопки убрать.
2. При загрузке из Проводника или с диска (системный и Flux-выбор,
   перетаскивание) за файлом и оборудованием закрепляется:
   - папка-источник;
   - правило имени;
   - текущая ревизия.

   `ImportFileChooser` должен передавать `sourceFolder`/`suggestedTag` во всех
   режимах. Это касается и документов-бланков, а не только XML: новая ревизия
   бланка в той же папке тоже должна находиться.
3. Привязка общая (серверная): по UNC-ключу папки, как у привязки к проекту,
   видна всем, кто видит проект; права записи — `equipment.manage`. Старые
   локальные привязки при первом открытии перенести на сервер с
   подтверждением, без потерь.
4. Обнаружение новой ревизии при обновлении папки:
   - уведомление;
   - окно «Обновления XML» со счётчиком (уже есть, расширить на документы);
   - утверждение;
   - ручные правки не затираются.

   Работать должно для обоих типов.
5. Обновить `docs/methodology/03-programs/equipment.md`.

## Правила, на которых уже обжигались

- В preload нет `node:*`, через мост идут только клонируемые данные.
- Колбэки, вызываемые позже (`ref.open()`), читают актуальное состояние
  через latest-ref.
- Журнал (ledger) в одной записи AppSetting ограничен 256 КБ: старую историю
  отмены обрезать, а не отказывать.
- Наружу из main не уходят абсолютные пути.
