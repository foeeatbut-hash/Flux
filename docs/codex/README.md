# Обмен заданиями с Codex

Руководитель (Claude Code) пишет задания сюда, Codex их выполняет, руководитель
проверяет и сливает. Владелец передаёт Codex только номер задания.

## Порядок для Codex

1. Перед началом: `git fetch origin` и работа от свежей рабочей ветки
   `claude/custom-table-builder-design-38h1b8` (не от `main`: там нет текущей
   работы над Flux Office).
2. Своя ветка: `codex/<номер>-<кратко>`, например `codex/01-sources`.
3. Делать ровно то, что в задании, и не трогать файлы из раздела «Не трогать»:
   их параллельно правит Claude Code, и любая правка там даст конфликт.
4. Перед PR прогнать проверки из задания и записать итог каждой в тело PR
   (команда → прошло / сколько провалов и каких). Не заявлять готовность без
   прогона.
5. PR открывать в ветку `claude/custom-table-builder-design-38h1b8`, черновиком.
   Заголовок — «Codex NN: <суть>». В теле: что сделано, чем проверено, что
   осталось и что спорно.
6. В конце задания отметить его статус в этом файле (таблица ниже) в своём PR.
7. Замечания руководителя приходят комментариями в PR — исправлять в той же
   ветке.

Правила проекта для Codex — `AGENTS.md`. Решения владельца по Flux Office —
`docs/methodology/03-programs/office.md` (раздел «Решения владельца») и ТЗ
`docs/office-spec/flux-office-tz-v10.md`; при расхождении действует раздел
«Решения владельца».

## Порядок для руководителя

Проверка PR: локально тесты из задания и живой прогон затронутой области;
замечания — комментарием в PR; после исправлений — слияние в рабочую ветку и
общий прогон.
