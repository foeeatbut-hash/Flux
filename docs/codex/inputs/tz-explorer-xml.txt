# ТЗ — Доработка проводника, рабочего стола и XML оборудования Flux

**Главное условие:** текущий проводник уже хорошо сделан. Не нужно кардинально менять дизайн, расположение панелей, кнопок и существующую логику. Наша задача — устранить ошибки, повысить производительность и аккуратно внедрить новые функции.

## 1. Производительность и ошибки проводника

- Исправить медленное открытие сетевых папок. Сейчас некоторые папки даже с 2 файлами открываются около 20 секунд.
- Оптимизировать чтение содержимого: сначала показывать список файлов, затем подгружать дополнительные свойства и значки.
- Устранить причины ошибок `NATIVE_TIMEOUT`, `NATIVE_HELPER_FAILED`, `EPERM` и других зафиксированных сбоев.
- Уменьшить количество повторных обращений к сети, дискам и нативному помощнику Windows.
- Реализовать нормальное кэширование и обновление папок, чтобы интерфейс не зависал.
- При отсутствии сети корректно отображать недоступность папки, не блокируя остальную программу.

## 2. Рабочий стол Flux

- Исправить медленное обновление и постоянное мигание значков.
- При изменении одного файла обновлять только соответствующий элемент, а не весь рабочий стол.
- Сохранять положение значков, выделение и настройки отображения.
- Исключить появление дубликатов.
- Обеспечить быструю синхронизацию с изменениями файлов Windows.

## 3. Ярлыки и значки

Нужно разработать единую систему значков для всего Flux: проводника, рабочего стола, Flux Office и других модулей.

**Основные правила:**

- Папка должна выглядеть как настоящая папка, а не как диск.
- Для Word, Excel, PDF, XML, IFC, DWG, архивов, изображений и других основных форматов — понятные значки в едином стиле Flux.
- Для встроенных приложений Flux — индивидуальные значки.
- Для неподдерживаемых внешних приложений — единый нейтральный значок.
- **Слева снизу** — маленькая фирменная метка Flux для объектов, существующих только внутри программы.
- **Справа снизу** — маленькая метка общего доступа в виде двух человек.
- Обе метки могут отображаться одновременно.
- Значки должны одинаково выглядеть во всех разделах Flux, включая светлую и тёмную темы.

**Сначала подготовить визуальные варианты значков для согласования. После утверждения внедрять их во всю программу.**

## 4. Исправление выделения файлов

Сейчас при выделении мышью иногда выделяется текст названий вместо самих файлов.

Нужно сделать нормальное рамочное выделение, как в Windows:

- Зажимаем ЛКМ на пустом месте.
- Перетаскиваем курсор.
- Появляется рамка, выбирающая файлы и папки.
- Поддерживаются Ctrl, Shift, Ctrl+A и остальные привычные действия.
- Корректно работают выделение, прокрутка и перетаскивание файлов.

## 5. «Документы проекта» и привязка папок

- Убрать отдельный дублирующий раздел «Документы проекта» из интерфейса проводника.
- Добавить в контекстное меню папки **«Привязать к проекту»**.
- При привязке папки все вложенные файлы и подпапки автоматически наследуют принадлежность к выбранному проекту.
- Новые файлы, которые появятся в этой папке позже, также наследуют привязку.
- Предусмотреть смену и удаление привязки.
- Не менять физическое расположение файлов и права Windows без необходимости.

## 6. Единое окно выбора файлов

Во всех модулях Flux при выборе файлов и папок по умолчанию должен открываться **существующий проводник Flux**, а не стандартное окно Windows.

При этом в настройках оставить возможность переключиться на системное окно Windows.

Не нужно разрабатывать отдельный новый интерфейс выбора — использовать текущий проводник в компактном диалоговом режиме.

## 7. Автоматические ревизии XML оборудования

Необходимо доработать существующую систему XML-источников оборудования.

Пример расположения:

```text
Оборудование/
  3700-B08-AHU-001/
    A/
      3700-B08-AHU-001.xml
    B/
      3700-B08-AHU-001.xml
    C/
      3700-B08-AHU-001.xml
```

Также поддерживать числовые ревизии: `1`, `2`, `3`, `10` и т. д.

**Логика работы:**

1. При первой загрузке XML Flux запоминает родительскую папку оборудования, название которой соответствует тегу.
2. При появлении новой папки ревизии Flux автоматически обнаруживает новый XML.
3. Программа проверяет соответствие тега, корректность XML и наличие реальных изменений.
4. У позиции появляется уведомление о новой ревизии.
5. Пользователь может сравнить старые и новые характеристики.
6. После загрузки изменённые значения подсвечиваются **жёлтым цветом**.
7. Жёлтая подсветка сохраняется, пока инженер не проверит и не утвердит изменения.
8. После утверждения подсветка исчезает, новая ревизия становится действующей.
9. Предыдущие характеристики и история сохраняются.

**Важно:** новая ревизия не должна автоматически перезаписывать утверждённые или вручную изменённые характеристики.

## 8. Массовые обновления XML

Добавить в модуль «Оборудование» компактную кнопку **«Обновления XML»** со счётчиком.

При открытии показывать список оборудования:

- Тег.
- Текущая ревизия.
- Новая ревизия.
- Количество изменений.
- Статус проверки.

Пользователь должен иметь возможность выбрать отдельные позиции или все сразу, загрузить новые XML, просмотреть изменения и утвердить их.

Цветовая индикация:

- **Синий** — обнаружена новая ревизия.
- **Жёлтый** — загруженные изменения требуют проверки.
- **Красный** — ошибка или конфликт.
- **Без подсветки** — изменения утверждены.

Добавить перепривязку папки XML как для одной позиции, так и массово, например при переносе всего каталога оборудования на другой сетевой диск.

## 9. Общие требования

- Не переделывать существующий дизайн проводника и оборудования.
- Не удалять работающие функции.
- Не создавать дублирующие системы.
- Не усложнять интерфейс лишними настройками и кнопками.
- Сохранить все документы, теги, характеристики, историю и связи между модулями.
- Учесть работу нескольких сотрудников и сетевых ресурсов.
- Проверить реальные функции в собранной Windows-программе, а не только в среде разработки.
- После исправлений проверить отсутствие новых ошибок и ухудшения производительности.

**Итоговая идея:** оставить существующий Flux визуально привычным, но сделать проводник быстрее и стабильнее, внедрить красивые единые значки, исправить рабочий стол, добавить проектные привязки и полноценное автоматическое отслеживание ревизий XML оборудования.

**Перед заменой значков обязательно показать их варианты на утверждение. Остальные улучшения должны максимально органично вписываться в текущий интерфейс.**
