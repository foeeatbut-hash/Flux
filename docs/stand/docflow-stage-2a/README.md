## Находка вне задачи

У общего WindowDialog при сжатии уже открытого окна с 1440 до 1024 остаётся
прежняя координата x=344: предпросмотр выходит вправо на 88 px. Новое
открытие на 1024 помещается (x=136, ширина 768). Общий компонент не менялся.

## Шаг 2: комплекты и строки

`test-docflow-kits` проверяет структуру, совместимость со старым `types`,
перенос и различия. Нормализация, перенос и проверка неизвестных полей по
отдельности ломались мутациями — каждая дала код 1.

`test-docflow-kit-rows` — 61 проверка настоящего Express/SQLite: права всех
адресов, чужие ссылки, предварительный план, повтор и гонка авторов,
SQL-уникальность, ручная строка, безопасная атомарная отмена, стадии,
единицы, условия, должность, рабочие дни, перенос и отмена настроек.
Счётчик наличия проверен как 0→1→0 (строка без файла → файл → потерян).
Имя проверяется тем же `itemContext → rowForCheck → checkName`, что связь
файла. При неизвестной установке каждый тег остаётся отдельной пропущенной
строкой плана. В трёхпровайдерную проверку добавлены строки, гонка, повтор,
уникальность и отмена; SQLite/MariaDB/PostgreSQL прошли.

| Мутация реализации | Красный результат API-набора |
|---|---|
| Обход `docflowScope.actorMay` | «без просмотра список тегов закрыт» |
| Удаление сверки fingerprint предпросмотра | «устаревший план не применяется» |
| Удаление SQL-индекса project/unit/scope/type | `Missing expected rejection` при прямом создании дубля |
| Удаление CAS updatedAt при отмене | «отмена не затирает последующую правку и атомарна» |
| Код проекта вместо поля реестра в имени | несовпадение имени при проверке связи |
| Подсчёт строки вместо файла | строка без файла ошибочно попала в наличие |
| Отсутствие проверки lostAt | потерянный файл ошибочно попал в наличие |
| Один ключ для тегов без установки | разные теги ошибочно объединены |

Новые UI-наборы проверяют редактор комплекта и создание строк по тегу:
предложение/«Позже», план без записи, применение и повтор, отмену, отказ,
ожидание и переход к ручной строке. Продуктовые мутации: снятие kitsBad
блокировки сохранения и kitApply из preview до подтверждения. Оба набора
падали на соответствующих инвариантах, после восстановления зелёные.

Снимки `kits-*` и замеры `kits-measurements.json` — настройки, «По тегам»,
план и карточка, обе темы на 1440/1024. В счётчике «есть» учитывается файл,
поэтому создание одной строки само по себе его не увеличивает.
