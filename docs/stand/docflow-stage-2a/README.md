`test-docflow-kit-rows` — 61 проверка настоящего Express/SQLite: права всех
адресов, чужие ссылки, предварительный план, повтор и гонка авторов,
SQL-уникальность, ручная строка, безопасная атомарная отмена, стадии,
единицы, условия, должность, рабочие дни, перенос и отмена настроек.
Счётчик наличия проверен как 0→1→0 (строка без файла → файл → потерян).
Имя проверяется тем же `itemContext → rowForCheck → checkName`, что связь
файла. При неизвестной установке каждый тег остаётся отдельной пропущенной
строкой плана. В трёхпровайдерную проверку добавлены строки, гонка, повтор,
уникальность и отмена; SQLite/MariaDB/PostgreSQL прошли.

## Создание файлов: проверки API

`test-docflow-create-files.ts` — 105 проверок на настоящем Express и временной
SQLite. Семь маршрутов проверяют просмотр и право файлов независимо от правки;
план не создаёт связей, резервы защищают ревизию и путь, повтор и отмена
сохраняют историю. Последний пакет доступен только автору; предварительная
отмена не снимает резерв и повторно сверяет занятость пути без учёта регистра.

Для проверки атомарности тест внедряет ошибку второй вставки после успешной
первой в общей транзакции. После HTTP 500 обе связи отсутствуют, версии обеих
строк не изменены, план и резервы сохранены. Без общей транзакции тест обнаружил
первую оставшуюся связь: 1 вместо 0.

| Контрольная мутация | Ожидаемый отказ теста |
|---|---|
| Обход проверки права файлов | «нет права файлов: plan» |
| Замена правила файлов правом редактирования в таблице маршрутов | «таблица прав plan: files + view» |
| Включение ID строки в ключ резерва пути | «резерв того же пути для другого item заблокирован» |

| Удаление проверки версии строки при отмене | «последующая правка changed-row запрещает отмену» |

## Итоговые ограничения проверки

Итоговый локальный набор изменённой области: 18 наборов, 17 прошли.
`test-handbook.ts` обнаруживает отсутствующие статьи `/store` и
`/module-requests`. Та же ошибка подтверждена с исходными
`docflowArticles.ts` и `names.ts` из `origin/main` bd356ee5; файлы этапа 2а
после проверки восстановлены. Это находка вне задачи, статьи Store здесь
не добавлялись. Проверки новых имён и статей ДО проходят в том же наборе.

Полный локальный `npm run check` не запускался: текущий runner наследует
одно окружение для всех наборов, хотя собственный сервер Guide требует
отсутствия общего FLUX_API, а другим API-наборам нужен общий сервер.
Инфраструктура runner в этом PR не менялась. Выполнены целевые API/файловые
наборы, UI на отдельных стабильных Vite, типы, сборки, паспорта; итоговые
платформенные результаты берутся из CI текущего SHA.

Собственный сбой промежуточного CI исправлен выбором точных имён файлов
в CLI-шаге: подстрока `docflow-kits` захватывала UI до запуска Vite.
Исправленный шаг локально выполнил 15 API/файловых наборов без Vite,
15/15; UI сохранены в отдельном шаге workflow. Новые проверки пустых
форматов и реального файлового моста добавлены также в Windows workflow.

Ручная Windows-проверка владельцем остаётся: создание файлов в сетевых
папках, переименование и окно выбора файла. Подставной UI-мост её не заменяет.

Регрессия Проводника учитывает текущую ревизию: файл B не показывается как
файл строки с ревизией C, возврат B остаётся ссылкой, а файл текущей A
другой строки открывается. Изолированное отключение фильтра ревизии вызвало
падение этой проверки; повтор на исходном коде — 26/26.

Совместимость прежнего ВДР и размер проекта дополнительно проверены тем же
`scripts/test-docflow-kit-rows.ts`. До исправления универсальные ручные строки
«All items» / «Все позиции» исчезали из карточки, собственный Vendor Document
Register показывался среди документов, а проектный комплект предлагал создать
дубль универсальной строки. Проект с 501 тегом и проект с 5001 строкой
отклонялись; после снятия лимитов второй случай выявил ещё предел числа
параметров SQLite. После исправления ручная строка видна и повторно используется,
служебный реестр скрыт, оба больших проекта открываются, а выбранный тег
большого проекта доступен для плана. Выборки ссылок читаются пакетами; пределы
размера отдельного плана сохранены. Итог: 68/68 проверок API; временные логи
до и после — `/tmp/flux-kit-legacy-red.log` и `/tmp/flux-kit-legacy-final.log`.
