# Проводник Windows и Flux: проект следующего этапа

Статус: исходный функциональный проект. Реализованный локальный контур и его
ограничения описаны в [инструкции](windows-files-usage.md). Старый проектный
архив сохраняется; автоматический перенос его документов на диск не выполняется.

Следующий этап — Проводник как Проводник Windows 11 и отказ от отдельного
хранилища Flux: [explorer-windows11.md](explorer-windows11.md).

## Что видит человек

Рабочий стол Flux показывает настоящий рабочий стол текущего пользователя
Windows и ярлыки программ Flux. Проводник показывает подключённые папки
Windows с той же вложенностью, именами, расширениями и обычными действиями.
Поверх этого добавляются теги, проект, ревизия, ответственный и история Flux.
Нет второй копии всех файлов: изменение обычного файла записывается в его
исходный путь Windows.

В одной папке могут быть обычные файлы Windows и черновики Flux. Черновик
виден только в Flux, имеет спокойную подпись «Только в Flux» и хранится локально на компьютере
в защищённой папке данных Flux вместе с содержимым. Его родитель — уже открытая папка Windows. Поэтому
«Отобразить в Windows» публикует файл именно туда, без выбора пути.

## Основные действия

| Действие | Поведение |
| --- | --- |
| Открыть Word, Excel, PDF, Markdown | Открыть соответствующий редактор Flux; неподдерживаемое — штатной программой Windows |
| Создать → Файл Windows | Создать в текущей папке и сразу показать в обоих проводниках |
| Создать → Черновик Flux | Создать только в Flux, запомнить текущую папку как место будущей публикации |
| Отобразить в Windows | Сохранить черновик в запомненную папку; превратить в обычный связанный файл |
| Показать в Проводнике Windows | Открыть родительскую папку с выделением файла |
| Открыть обычной программой | Передать исходный путь Windows; не выгружать временную копию |
| Назначить тег / ревизию | Сохранить свойства в Flux без изменения расширения или содержимого файла |
| Переименовать / переместить | Изменить путь Windows и сохранить связь с историей Flux |
| Скопировать | Создать новый файл с новой идентичностью; отдельно выбрать перенос тегов |
| Удалить обычный файл | Переместить в корзину Windows; историю Flux оставить доступной |
| Удалить черновик | Переместить в корзину Flux; папку Windows не трогать |

Создание предлагает два понятных пункта рядом. Последний выбор запоминается
для пользователя, но место хранения всегда видно перед созданием. Для
папок доступны те же варианты. Черновая папка публикуется со всем деревом
сначала после предварительной проверки, затем атомарно настолько, насколько
это позволяет файловая система. Частичный результат показывается списком,
с возможностью продолжить оставшиеся операции.

## Пример с десятью файлами

В Windows есть `Рабочий стол/Проект/` с десятью файлами. Flux показывает все
десять. В этой папке человек создаёт документ «Только в Flux», правит,
закрывает и возвращается позже. Windows всё ещё показывает десять файлов.
Команда «Отобразить в Windows» создаёт одиннадцатый файл в `Проект/`; в Flux
остаётся одна карточка этого документа с прежними тегами и ревизиями.
Повторное нажатие не создаёт дубль. Последующие сохранения меняют этот
исходный файл. Публикация записывается в историю.

## Связь с проектами и свойства

У физического файла есть отдельная стабильная запись Flux. Путь служит
местом расположения, а не идентификатором: переименование не теряет теги.
На NTFS используется идентификатор файла вместе с томом; на сетевых дисках
и других файловых системах — сохранённый путь и подтверждаемое сопоставление
по размеру, хешу и времени. Сходное имя никогда не объединяет документы
автоматически. Неоднозначная связь показывается пользователю.

Файл можно связать с несколькими проектами, но теги выбираются в явном
контексте проекта. В карточке сразу видно, какой проект открыт. Доступ к
свойствам другого проекта проверяется отдельно от доступа Windows к байтам.
Личный рабочий стол принадлежит человеку и его устройству: сервер коллеги
не может читать его пути. Общая папка подключается отдельно через UNC и права
Windows. Одинаковое имя пользователя на двух компьютерах не делает их
рабочие столы одной папкой.

## Редактирование и изменения извне

При открытии запоминаются исходный хеш и время изменения. Сохранение сначала
пишет временный файл рядом, проверяет результат, затем заменяет исходный.
Перед заменой повторно проверяется исходная версия. Если Word или другой
участник уже изменил файл, появляются варианты «Открыть свежую версию» и
«Сохранить мою копию»; молчаливой перезаписи нет. При занятом файле изменения
остаются в восстановимом черновике Flux.

Наблюдатель папок отражает создание, удаление и перемещение из Windows.
Повторные уведомления сворачиваются; собственная запись не образует цикл.
Наблюдатель дополняется сверкой при возвращении в папку и после сна: события
могут теряться. Отключённый сетевой диск означает «Временно недоступен»,
а не удаление всего дерева. OneDrive placeholders скачиваются только при
открытии, не во время просмотра всей папки.

## Конфликты и границы

* Совпадение имени при публикации: сохранить под свободным именем, заменить
  после просмотра конфликта или отменить. По умолчанию — свободное имя.
* Родитель удалён или перенесён: попытаться найти его по идентичности;
  если не найден — показать проблему и выбрать новую папку один раз.
* Нет прав, место закончилось, антивирус заблокировал запись: черновик остаётся
  в Flux; ошибка сообщает конкретную причину и повторяемое действие.
* Недопустимые имена Windows, длинные пути, регистр, зарезервированные имена
  и завершающие точки проверяются до записи, без незаметного переименования.
* Ярлыки отображаются как ярлыки; переход показывает настоящий адрес назначения.
  Символьные ссылки и junction не обходятся рекурсивно автоматически, чтобы
  не получить цикл и не выйти из подключённого корня.
* Перенос между дисками: копирование с проверкой хеша, только затем удаление
  оригинала. Отмена не оставляет незаметно потерянную исходную версию.
* Ревизия хранит снимок содержимого по явному действию; обычное автосохранение
  не увеличивает инженерный номер ревизии.
* Публикация дерева черновиков сначала показывает коллизии и недоступные пути.
  Возобновление использует журнал операций и не создаёт уже опубликованные файлы.

## Устройство интерфейса

Слева: Быстрый доступ, Рабочий стол, Документы, Загрузки, подключённые папки,
проекты и Корзина. Сверху: назад, вперёд, вверх, хлебные крошки, поиск и
обычная командная панель. Представления: список, подробности, плитки.
Справа по выбору: предпросмотр или свойства Flux. Пользователь может скрыть
инженерные столбцы и оставить привычные имя, тип, размер и дату Windows.
Контекстное меню содержит обычные файловые действия и одну группу Flux.
Фильтр «Только черновики» помогает завершить публикацию, не смешивая её с
остальными файлами. Обновление папки сохраняет выделение и прокрутку.

## Порядок внедрения и приёмка

1. Локальный файловый мост Electron: явные подключённые корни, перечисление,
   чтение, проверка версии, безопасная запись и корзина; renderer не получает
   произвольный доступ к диску через строку пути.
2. Проводник и рабочий стол Windows только для чтения, наблюдатель и сверка.
3. Редактирование исходных файлов в редакторах Flux, конфликты и восстановление.
4. Черновики в Windows-папках, публикация на месте, свойства и ревизии.
5. Перемещение, копирование, корзины и миграция старых папок Flux с проверкой.
6. Общие и сетевые папки, OneDrive, производительность больших деревьев.

Обязательная проверка на Windows: пример с десятью файлами; изменение извне
во время правки; файл открыт в Word; отсутствие прав и свободного места;
перезапуск в середине публикации; кириллица и длинный путь; переименование
папки; отключение сети; два окна Flux; копия файла с теми же тегами;
восстановление из обеих корзин; обновление portable без потери связей.
