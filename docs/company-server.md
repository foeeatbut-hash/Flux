# Общая база MariaDB для Flux и Flux Owner

Текущий вариант подключения настольных Flux и Flux Owner — только URI общей MariaDB/MySQL: `mysql://USER:PASSWORD@HOST:3306/Flux` или `mariadb://USER:PASSWORD@HOST:3306/Flux`. Пользователь не вводит адрес внешнего HTTP-сервера Flux и не размещает такой сервер. Каждый настольный Flux поднимает нужный внутренний API на loopback; это часть приложения, а не отдельная служба для установки.

Рабочая станция должна иметь сетевой TCP-доступ к MariaDB на порту `3306`, а учётная запись приложения — необходимые права на выбранную базу. URI содержит имя пользователя, пароль, адрес и имя базы. Это URI SQL-подключения, а не HTTPS-адрес.

При прямом подключении реквизиты SQL используются на рабочих станциях, а их права действуют непосредственно в БД. Такой вариант не даёт абсолютной защиты от патча клиентской программы или администратора БД с достаточными правами. Ограничивайте доступ к MariaDB сетью/VPN и выдавайте отдельной учётной записи только необходимые права.

Эта инструкция описывает текущие исходники. EXE с новым подключением ещё не выпущен; ранее скачанные сборки автоматически не обновляются.

Не используйте в инструкциях и переписке реальные пароли. В URI специальные символы в имени пользователя и пароле должны быть percent-encoded. Выдайте приложению отдельную учётную запись БД с нужными правами; `root@localhost` из phpMyAdmin не является учётной записью приложения. Если phpMyAdmin показывает MariaDB через локальный UNIX socket, это не подтверждает, что сервер принимает сетевые TCP-подключения или что у пользователя есть права для подключения с рабочей станции.

## Подключение владельца с Windows portable

Эта инструкция описывает новое подключение в исходниках; portable EXE с ним ещё не выпущен. Не считайте ранее скачанные сборки обновлёнными. Когда сборка будет доступна, положите Flux и Flux Owner в одну папку, запустите Owner и откройте уже созданное хранилище его паролем; повторно создавать ключи не нужно. В разделе «Подключение» введите URI MariaDB/MySQL, например `mysql://USER:PASSWORD@HOST:3306/Flux`, и нажмите «Подключиться».

Flux Owner найдёт Flux portable в той же папке и незаметно запустит его локальную серверную часть. Если автоматический поиск не сработает, программа предложит выбрать EXE. Локальный API нужен Owner для авторизованных операций и публикации; он слушает loopback и не заменяет внешний сервер компании. Устанавливать Node.js, настраивать SSH или ставить службу на NAS не требуется. Окно обычного Flux для этого способа не запускается. При каждом новом подключении Owner URI вводится снова.

Для самостоятельной работы в настольном Flux откройте внизу экрана входа «Подключение к общей базе», укажите URI MariaDB/MySQL и нажмите «Проверить и подключить». После успешной проверки URI сохраняется, а Flux предлагает перезапуск. Flux и Flux Owner используют одну общую MariaDB/MySQL; отдельный адрес HTTP-сервера Flux вводить не нужно.

Не публикуйте MariaDB или внутренний API в Интернет. Ограничьте TCP-доступ к порту `3306` корпоративной сетью/VPN и используйте отдельную учётную запись приложения. Успешное подключение к phpMyAdmin с самого сервера не заменяет проверку сетевого доступа с компьютера, где работают Flux и Flux Owner.

## Обновления

Flux Owner публикует обновления существующим комплектом ключей владельца. Сам Flux Owner обновляется вручную отдельным portable EXE. Если установленная сборка Flux содержит другие открытые ключи, новые лицензии или подписи она не примет: сборку нужно установить вручную с актуальными ключами, а лицензии выпустить заново.
