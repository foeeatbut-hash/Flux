Предыдущий isolated native-прогон выполнялся в настоящем Electron. Его результат
относится к предыдущей реализации, а не к новому SHA.
Native-набор читает настоящую временную SQLite через штатные GET-маршруты;
POST ручного значения меняет позицию и посылает `entity:changed`. Открытый
модуль показывает `1200 → 2400`, а версия позиции в БД увеличивается.
Вход подменён синтетическим авторизованным профилем, передача сокета в событие
окна — тестовой обвязкой. Проверка не подтверждает полный экран входа,
корпоративную MariaDB/PostgreSQL и два разных компьютера.

В том же Electron проверяются cookie и localStorage родителя, отсутствие
Electron/Node в iframe с настоящим preload у родителя, CSP страницы и Worker,
запрет записи без изменения БД, отбрасывание сообщения вне схемы, остановка
бесконечного Worker и запрет навигации iframe на внешний адрес.

Windows CI и его результат привязаны к последнему SHA в draft PR #134:
[Проверка модулей Flux](https://github.com/foeeatbut-hash/Flux/actions/workflows/verify-modules.yml).
Успех Linux не заменяет результат этого job на SHA передаваемой ветки.
Предыдущий isolated native-стенд показывает `ModuleHost` и `flux-module://` с
тестовой верхней панелью; его снимки не являются снимками полной оболочки.
Полный Flux UI-прогон локально прошёл 11 проверок на Linux/Xvfb/Electron. Он использует
обычный вход, настоящий API и временную базу; полный клиент запускается без
подставного preload, нативный IPC проверяется отдельно. В том же артефакте
`modules-windows-evidence` сохраняются снимки `flux-equipment-{light,dark}`,
`flux-tag-{light,dark}` и `flux-module-{light,dark}`, а также замеры и логи.
Локальные снимки просмотрены: кнопки обеих карточек высотой 28 px, шрифт
13 px/500; обёртка в позиции имеет padding 6 px и flex-shrink 0.
Для этого полного прогона промышленный preload не подключается: нативные
возможности не подменены заглушками и проверяются отдельным native-набором.

## Отрицательные прогоны

Для предыдущей реализации в отдельном worktree по одной убирались конкретные части реализации;
после каждой мутации восстанавливались исходники. Все десять запусков
завершились с кодом 1:

| Убрана защита | Первый наблюдаемый провал |
|---|---|
| Источник/origin моста | Чужие сообщения не доходят до чтения |
| Запрет лишних полей JSON Schema | Лишнее поле результата project запрещено |
| Ответ READ_ONLY | Запись получает READ_ONLY |
| Поколение асинхронного ответа | Ответ старого проекта не доставляется |
| Проверка доступного проекта | Закрытый проект не даёт читать оборудование |
| Отказ при HTTP 403 | Отсутствует ожидаемый отказ Promise |
| Ключ ручного значения `группа||параметр` | Ручное значение имеет приоритет |
| Sandbox дополнен allow-same-origin | Контекст не доходит, ожидание 1200 истекает до прямой проверки sandbox |
| CSP открывает HTTP/WS | Запрос доходит до запрещённого тестового адреса |
| Предел Worker увеличен до 60 с | Зависший Worker не останавливается в допуске |

Это проверка чувствительности к отсутствию конкретных частей реализации.
Она не называется прогоном новых API на старой ревизии, где их ещё не было.
Исходный срез старой ревизии — существующие architecture/app-policy/office-bridge.

Отдельно один и тот же launch-стенд запускался на настоящих исходниках
`596f5612` и предыдущей копии PR 1. Он импортирует только существовавшие на обеих
ревизиях React/router/store/`sectionForPath`, не подставляет ModuleHost.
На baseline маршрут `/module/equipment-inspector` разрешается в Dashboard
(`/`), iframe отсутствует и утверждение о запуске падает (exit 1, ошибка
утверждения, не импорта). На предыдущей копии PR 1 реестр разрешал маршрут модуля,
iframe появляется (exit 0). Это red/green для новой точки запуска;
гранулярные свойства новых API проверены десятью мутациями выше.

Для текущих правок пять отдельных отрицательных прогонов завершились с кодом 1:

| Мутация | Наблюдаемый провал |
|---|---|
| Лимит pending 16 → 17, overflow остаётся без результата | exit guard: main contract не завершён |
| Незавершающийся await в data | exit guard: main data не завершён |
| Снят предел частоты | За секунду должно выполняться 99 чтений после одного ready |
| Снят входной предел | Вход больше 1 МиБ в UTF-8 должен отбрасываться |
| Снят выходной предел | Ответ больше 1 МиБ в UTF-8 должен заменяться LIMIT |

## Находки и непроверенное

- Первый native CI обнаружил блокировку шрифтов: opaque origin требует CORS
  у протокола; маленький встроенный Vite-шрифт противоречил CSP. В протокол
  добавлен CORS только для собственных файлов, встроенные шрифты вынесены
  в файлы; сеть и eval остаются закрыты. Консоль обычного сценария пустая.
- Просмотр снимков обнаружил светлую пустую область iframe в тёмной теме.
  Холст документа теперь берёт тот же токен поверхности; отдельный замер
  проверяет совпадение фона тела и холста.
- Worker ограничен 30 секундами активного run, вне run — ping раз в секунду и 3 секунды ожидания. Без подписчиков поток завершается. State/calc вместе ограничены 256 КиБ; globalThis освобождается при перезапуске не позже 60 секунд жизни потока. Перезапуск после сбоя — по следующему событию с последним завершённым снимком, без непрерывного повтора плохого setup. Жёсткая квота heap браузерного Worker не подтверждается и не обещается.
- Полный `npm run check` без подготовленного общего UI/API/GenOffice-стенда
  не запускался: проверены затронутые наборы и отдельный native-стенд.
  Ручной portable Windows на рабочем месте компании не проверен.
- Настоящие внешние программы и E3 не проверяются: подключений к ним
  в PR 1 нет.

## Повторная приёмка этапа 1

Обновлены guard для обоих живых наборов: Windows либо явный Linux opt-in через FLUX_CHROME и DISPLAY; без dist — FLUX_VERIFY_SKIP с причиной.

Пять отдельных мутаций в временных копиях завершились exit 1:

| Снята защита | Обнаружившая проверка |
|---|---|
| Сторож вне run | Бесконечный setInterval в setup не остановлен в допуске |
| Лимит state/calc | Большой state не даёт ожидаемый STATE_LIMIT |
| Проверка формы при сборке | flux.bogus.x не отклонён сообщением о неверной привязке |
| Общий кэш | Два окна выполнили GET дважды |
| Условие offline у запасного таймера | При работающем сокете произошло перечитывание |

Положительный тест сторожа запускает настоящий поток и дополнительно проверяет его завершённый threadId; имитация postMessage не заменяет выполнение кода. Проверены восстановление state и очистка globalThis по сроку жизни. Сборка проверяет также flux.equipment.bogus и несуществующие колонки таблицы.

Итог Windows CI относится к последнему SHA PR; результаты 826dba9 выше — исторический срез, новый SHA до завершения CI не объявляется зелёным.

В новом локальном окружении Linux-проверки без opt-in корректно дали SKIP. Первый opt-in native-прогон остановился до интерфейса: X server ещё не был установлен (`Missing X server or $DISPLAY`). Этот запуск не считается проверкой продукта; Windows-прогон последнего SHA обязателен отдельно.
