# Проверки программ Flux

Обязательные правила: [методология](../methodology/04-testing.md).
Подробная матрица: [единый стандарт](../testing-standard-proposal-2026-10-04.md).
Исполняемый формат: [манифесты](manifest-format.md).

## Ответственность и паспорта

| Группа | Программы | Что проверяется |
|---|---:|---|
| [Файлы и Office](files-office.md) | 10 | Проводники, общий доступ, архивы, редакторы, заметки и стикеры |
| [Инженерные программы](engineering.md) | 7 | Теги, оборудование, выгрузка, каталог, конструктор и закупки |
| [Сотрудники и Owner](identity-owner.md) | 5 | Главная, проекты, сотрудники, настройки, Flux-Owner |
| [Совместная работа](collaboration.md) | 9 | Сообщения, почта, календарь, помощник, перевод, обращения и справка |
| [Оболочка и Play](shell-play.md) | 2 | Рабочий стол, окна, мониторы, уведомления, Дурак и бильярд |

Все действия и связи имеют стабильные ID, исходники, ожидаемый результат,
слой автоматического утверждения и отдельные ручные сценарии. Реестр
дополняется при появлении команды, кнопки, нового способа запуска или связи.
Согласованность реестра и успешный тест отдельного helper не доказывают
полную работоспособность программы.

## Запуск

```bash
npm run check:coverage -- --report /tmp/flux-source-inventory.json
npm run check:verification -- --report /tmp/flux-infrastructure.json
npm run check:programs -- --list
npm run check:programs -- --run --report /tmp/flux-program-verification.json
```

Последняя команда выполняет доступные наборы с блокировками общих ресурсов.
Внешние наборы требуют отдельной изолированной фикстуры и её явной метки;
рабочие корпоративные подключения не подставляются. Ненулевой exit code
при BLOCKED/SKIP показывает отсутствие доказательства, даже если нет FAIL.
Ручные сценарии остаются NOT_RUN до фактического выполнения.

AST-инвентаризация находит исходные обработчики и управляющие элементы,
проверяет наличие паспортов всех маршрутов и отдельных окон. Она сообщает
действия без автоматических утверждений. У неё пока нет полного соответствия
«каждый найденный контрол → контракт → выполненный сценарий»; динамические
меню, iframe и элементы Windows также требуют прямой проверки.

CI проверяет типы, согласованность паспортов, механизм исполнения,
целевые регрессии и компоненты интерфейса на локальных фикстурах. Это
не полный выпускной прогон и не проверка portable на Windows.

Результаты внедрения и ограничения: [проверка 4 октября](results-2026-10-04.md).
