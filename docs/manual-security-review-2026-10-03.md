# Ручная проверка безопасности и обновлений — 3 октября 2026

Проверены исходники подключения к общей MariaDB, входа владельца, лицензирования, публикации и получения обновлений, а также упаковка ресурсов. Исправления подтверждены изолированными негативными тестами и запуском скомпилированного API. Это ручная инженерная проверка, а не результат Codex Security deep scan: необходимый инструмент этого сканера недоступен в сессии. Проверка не доказывает отсутствие всех уязвимостей во всех программах Flux.

## Подключение и обновления

В пользовательском интерфейсе Flux и Flux Owner оставлено подключение к общей MariaDB/MySQL. Внешний адрес HTTP-сервера вводить не нужно. Внутренний API работает на loopback отдельно на рабочей станции; его нельзя удалить без замены прикладной логики. Старая настройка внешнего адреса больше не перенаправляет клиентские запросы или вход владельца.

URI допускает только `mysql://` или `mariadb://` с именем пользователя, паролем и базой. Параметры драйвера заданы явно: отключены чтение локальных файлов по запросу SQL-сервера, перенаправления и автоматическое получение открытого ключа сервера. Из query-параметров разрешён только `ssl=true|false`; `ssl=true` включает проверку сертификата. Это не включает TLS автоматически для ранее настроенного сервера без SSL. Ошибки проверки подключения и его сводка не возвращают пароль в интерфейс.

На отдельной пустой MariaDB **11.4.13** прошли **35 проверок** публикации владельцем и загрузки сотрудником через два независимых локальных API с общей БД. Проверялись отказ неавторизованным пользователям и администраторам, подпись версии и содержимого, параллельная публикация, повреждённые и отсутствующие блоки, отзыв во время загрузки, повторное использование отозванной версии, проверка загрузки и сохранность прежних байтов при неудачной замене. Аналогичный цикл прошёл на временной SQLite. Данные компании и её сервер не использовались.

Тест замены проверяет файловые операции и восстановление байтов, а не реальный запуск нового Windows EXE. Для MariaDB 10.11 добавлена отдельная проверка GitHub Actions; её результат следует смотреть в PR. Проверки Windows в CI также не заменяют приёмку на компьютере сотрудника с действующей лицензией, сетевыми правами и установленной сборкой.

## Подтверждённые проблемы и исправления

1. **Подделка сессии владельца с локальным HMAC-секретом.** В изолированном тесте до исправления такой токен принимался без закрытого ключа владельца. Теперь обычный вход не выдаёт OWNER-сессию, а запросы владельца требуют точного токена, выданного этим процессом после проверки одноразового Ed25519-вызова. Правка роли в БД и знание локального HMAC-секрета сами по себе этот вход не создают. После перезапуска API или смены БД владелец входит по ключу снова.
2. **Удаление ранее проверенного списка отзыва.** Работающий процесс запоминает подписанный список и отказывает при его удалении или откате. Память процесса ограничена; новый процесс или новый компьютер не знает историю уже удалённых записей. Эта правка не защищает от восстановления администратором старой БД после перезапуска всех клиентов.
3. **Лишние ресурсы portable.** Для Prisma введён список разрешённых ресурсов: схемы и миграции, без SQLite-файлов, WAL/SHM, конфигурации и хранилищ ключей. Отслеживаемый SQLite-шаблон удаляется из новой версии репозитория. Это не удаляет файл из истории Git или чужих клонов; его содержимое в рамках проверки не читалось.
4. **Неявная замена локальной БД.** Первый запуск создаёт чистую схему без копирования шаблона. Повреждённый существующий файл не удаляется и не заменяется автоматически. При ошибке API сообщает о недоступной БД, а интерфейс предлагает настройку подключения или выбор существующего локального файла. На тестах прежние файлы и контрольные записи сохранены.

## Свидетельства проверки

- Сессии: 17 проверок; фактические маршруты владельца: 38; лицензии сервера: 24.
- Подписи обновлений: 21; проверка загрузки: 18; защищённое хранение сессии: 18; общий набор безопасности: 52.
- Проверены валидация URI и безопасные опции драйвера, миграция старого адреса, состав ресурсов, создание новой схемы и сохранность существующей SQLite.
- Скомпилированный `dist/server.cjs` успешно стартовал с чистой временной БД. Он отклонил тестовый ключ владельца, автоматическую тестовую лицензию через переменные среды, парольный вход для добавленного через SQL OWNER и поддельный OWNER-токен с известным секретом этой тестовой установки.
- Проверки типов, архитектуры, сборки веб-интерфейса, Electron и тесты Flux Owner прошли. Интерфейс подключения проверен в светлой и тёмной теме при ширине 1024 и 1440 пикселей с имитацией IPC.

Все ключи, пароли, токены и базы этих тестов — отдельные фикстуры. Загруженные пользователем закрытые хранилища не расшифровывались, не включались в тесты и не публикуются. Открытые ключи сборки не являются секретами. Тестовые ключи не совпадают с доверенными производственными ключами.

### Проверка зависимостей

`npm audit --omit=dev` выполнен с доступным реестром npm. До дополнительных исправлений он сообщал о 49 затронутых пакетах, из них 35 уровня high. Это агрегированные package-level показатели, включающие зависимости и повторяющиеся цепочки, а не 35 независимых подтверждённых способов взлома Flux.

Точечно обновлены `fast-xml-parser` до 5.10.1 и зафиксированы overrides `mariadb` 3.4.7, `engine.io` 6.6.10, `socket.io-parser` 4.2.7, `ws` 8.21.0. Обновление MariaDB устраняет затронутый диапазон GHSA-cqhc-2h57-wpxf (передача пароля MITM при SSL) и связанные advisories; 3.4.6 в реестре отсутствует, поэтому выбрана доступная 3.4.7. Prisma adapter закреплял старую 3.4.5: его совместимость с override проверена фактическими 35 сценариями на временной MariaDB. XML-патч закрывает затронутый диапазон GHSA-8r6m-32jq-jx6q; тесты импорта ВЕЗА прошли. Реальные два Socket.IO-клиента на отдельном loopback-сервере подтвердили WebSocket, комнату, broadcast, ack и отключение после обновления транспортных пакетов. Это проверка совместимости транспорта, не отдельное доказательство всех прав доступа приложения.

После обновления: **24 затронутых пакета, 14 high, 10 moderate, 0 critical**. Указанные пять исправленных пакетов больше не перечислены в audit. Остаточные риски не устранены и требуют отдельной миграции/проверки:

- `xlsx` 0.18.5: GHSA-4r6h-8v6p-xvw6 (prototype pollution), GHSA-5pgg-2g8v-p4x9 (ReDoS); используется импортом Excel в интерфейсе и на сервере. Исправленной версии под тем же пакетом реестр npm не предлагает. Импорт произвольных недоверенных книг нельзя объявлять безопасным.
- `nodemailer`/`mailparser` и цепочка `html-to-text`/`deepmerge-ts`: почтовые пути отправки SMTP и чтения IMAP реально присутствуют. Обновление на иной major требует проверки этих интеграций, а не автоматического audit fix.
- `@xmldom/xmldom` через `mammoth`: затронут путь разбора DOCX. Нужны отдельное обновление и регрессии импорта документов.
- Для React Router часть advisories относится к RSC/SSR, тогда как Flux использует клиентский HashRouter и такой серверный путь не найден; остальные advisory-условия требуют дополнительной проверки. Нельзя автоматически считать все записи применимыми или все неприменимыми.

Audit также отражает ветви Prisma CLI/peerOptional и вспомогательные пакеты. Возможность реальной эксплуатации каждого остаточного advisory отдельно не воспроизводилась. Результат **не является «чистым» аудитом зависимостей**, даже при успешных функциональных тестах и CI.

## Что остаётся возможным

**Portable нельзя сделать неразбираемым.** На компьютере, контролируемом пользователем, можно читать ресурсы, наблюдать выполняемый код и менять программу. Шифрование упаковки и обфускация повышают стоимость анализа, но не доказывают невозможность копирования или обхода лицензирования. Проверка подписи данных не мешает запуску изменённого клиента, который вообще пропускает проверку.

**Общий SQL-доступ не является границей доверия.** Рабочая учётная запись должна читать и изменять данные Flux; получив её реквизиты, человек может обращаться к разрешённым таблицам вне программы. Профили и обычные права в БД не подписаны владельцем. Достаточные SQL-права позволяют менять профили, пароли, права, общие файлы и настройки. Локальный HMAC-секрет также не обеспечивает защиты обычных сессий от владельца компьютера. Исправление OWNER-входа не устраняет эти отдельные риски. Для защиты от такого противника потребуются дополнительные ограничения SQL/подписанные полномочия либо доверенная служба; один общий пароль с полным доступом их не заменяет.

**Реквизиты БД сохраняются в конфигурации Flux без шифрования DPAPI.** Ограничения файловых прав и безопасные сообщения уменьшают случайное раскрытие, но не скрывают пароль от пользователя с доступом к конфигурации. По присланному снимку MariaDB работает без SSL: защита транспорта требует настройки TLS на самой БД. Уже опубликованные в переписке реквизиты следует сменить у администратора БД.

**Открытый репозиторий раскрывает исходники.** По решению владельца видимость репозитория оставлена прежней. Пока он открыт, код можно скопировать независимо от защиты EXE. Закрытие позже не отзывает ранее скачанные копии. Юридическая защита авторских прав и лицензия дополняют технические меры, но не предотвращают само копирование.

**Подпись Flux-обновления и подпись кода Windows — разные проверки.** Flux проверяет свою Ed25519-подпись, хеш, размер и состояние публикации. В этой работе не добавлен коммерческий сертификат Authenticode. Выбранный Owner локальный Flux EXE проверяется по формату, но его издатель не подтверждается Authenticode: брать его нужно из проверенного выпуска.

## Состояние выпуска

Этот документ описывает исправленные исходники и проверочные сборки. Новые portable EXE в рамках этой проверки ещё не выпускались. Ранее скачанные Flux и Flux Owner не получают эти исправления сами по себе. Оба приложения должны быть собраны из согласованной версии исходников с уже действующими открытыми ключами; повторно создавать хранилище владельца не требуется.
