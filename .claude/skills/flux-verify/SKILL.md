# Проверка работы

## Наборы проверок

Логика, у которой есть правильный ответ, проверяется скриптом
`scripts/test-<имя>.ts`. Прогон — через `npm run check`: он запускает наборы
по очереди и печатает только провалы, строки «✗» и итог.

```bash
npm run check                  # все, кроме *live*
npm run check -- --live        # вместе с живыми
npm run check -- layout flow   # только наборы с этими словами в имени
npx tsx scripts/test-<имя>.ts  # один набор с полным выводом — когда разбираешь провал
```

Прошедший набор после этого не перезапускать, пока в его области нет новых
правок.

Наборам `api`, `flow`, `layout` и всем `*live*` нужен сервер (см. ниже).
`test-architecture` проверяет границы слоёв, размер файлов и храповик дизайна;
подробности — в skill `flux-architecture`.

Формат один на все наборы, без фреймворка: счётчик, функция сравнения,
названия проверок по-русски и по существу.

```ts
const eq = (name: string, got: any, want: any) => { /* … */ };
eq('разделитель между цифрами значим', normCode('бл2.1') === normCode('бл21'), false);
console.log(`\n${ok} проверок пройдено, ${fail} провалено`);
process.exit(fail ? 1 : 0);
```

Название проверки говорит, **что именно** сломается: «разные номера не
считаются похожими» лучше, чем «тест 4». Проверка пишется вместе с логикой, до
«готово». Здесь они ловили дефекты, которые в коде выглядели правильно:
слипание `бл2.1` с `бл21`, привязку `AHU-21` к `AHU-211`.

## Типы и сборка

```bash
npx tsc --noEmit    # ноль ошибок; любая новая — своя, чинить
npx vite build
npm run build:electron
```

## Сервер

`npx tsx server.ts` поднимает Express на порту 3000, создаёт SQLite в
`database/`, синхронизирует схему и засевает администратора `RaupovKhKh` с
паролем `1122`.

```bash
setsid nohup npx tsx server.ts > /tmp/srv.log 2>&1 &
until curl -s localhost:3000/api/health >/dev/null; do sleep 3; done
```

`test-api` — дымовая проверка HTTP-слоя: вход, отказ по чужому и
подделанному токену, списки, запись и удаление. Гонять до и после переноса
маршрутов из `server.ts` в `server/routes/*`.

Останавливать `pkill -f "tsx serv[e]r.ts"`: без скобок строка совпадёт с
командой самой оболочки, и та убьёт себя.

## Интерфейс

Новый экран проверяется снимком, а не «выглядит правильно»: Chromium через
`playwright-core` (путь — `FLUX_CHROME` или
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, `--no-sandbox`). Проверять
обе темы, отсутствие горизонтальной прокрутки и тишину в консоли (`pageerror`,
`console` типа `error`).

Если вёрстка ведёт себя странно, её надо **измерять**, а не угадывать
(`getBoundingClientRect`, `getComputedStyle`). Так нашлось, что кнопка `.ok`
обнуляла ширину бейджам `.badge.ok`: столкновение имён в каскаде на глаз не
отличить от случайности.

Остальное читать, когда оно нужно:

- [references/ui-live.md](references/ui-live.md) — вход с подменой ответа
  лицензии, раскладка в окне (`test-layout`), сценарии (`test-flow`), чему
  нельзя верить в проверке интерфейса;
- [references/cases.md](references/cases.md) — права доступа вдвоём, почта без
  внешнего сервера.

## Что сказать в отчёте

Захват с экрана целиком здесь не проверить: нужен Electron и буфер обмена.
exe собирается в GitHub Actions (skill `flux-release`).

Для непроверенного честная формулировка: «проверено разбором кода, типами и
сборкой; на живых данных не наблюдал». Рассуждение не выдавать за наблюдение:
если в отчёте сказано «работает», значит, это было видно.
