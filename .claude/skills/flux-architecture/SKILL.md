# Устройство кода Flux

## Зависимости текут в одну сторону

```
общее (lib, store, components, capture, import, assistant)
   ↓
экраны (screens) — то, что видно в разделе
   ↓
приложение (App, WindowsLayer, sections) — собирает разделы вместе
```

Общее знает о себе; экран знает об общем; приложение знает обо всём. Обратно —
нет. Из этого следует то, что проверяется механически:

- **раздел не импортирует другой раздел.** Разделы соединяются на уровне
  приложения (`src/workspace/sections.tsx`), а не друг через друга. Общее для
  двух разделов выносится в `src/components/`;
- **хранилище не импортирует интерфейс.** `src/store/*` не тянет `screens/` и
  `components/` — иначе состояние нельзя проверить без React;
- **разбор не зависит от React.** `src/capture`, `src/import`, `src/assistant` —
  чистые модули: только данные внутрь, только данные наружу. Поэтому их и
  получается покрыть скриптами;
- **клиент не импортирует сервер**, `electron/` не импортирует `src/`.

Проверка: `npx tsx scripts/test-architecture.ts`. ESLint в проекте нет и он не
нужен — правила живут там же, где остальные проверки.

## Куда класть новый код

| Что | Куда |
|---|---|
| Новый раздел программы | `src/screens/Имя.tsx` + строка в `SECTIONS` |
| Кусок интерфейса для двух и более разделов | `src/components/` |
| Общее состояние | `src/store/` (zustand) |
| Разбор текста, чисел, документов | `src/capture` / `src/import` (без React) |
| Запросы к серверу | `src/services/dataService.ts` |
| Логика сервера | `server/` (маршруты — `server/routes/`) |

Файл в `src/screens/`, не попавший в `SECTIONS`, — это на самом деле компонент
(`TitlePanel`, `VdrPanel`, `TextDocEditor`). Новые такие не заводить: сразу в
`components/`.

Бочковых `index.ts` (barrel-файлов) в проекте нет и заводить не надо — они мешают
Vite отбрасывать неиспользуемое.

## Размер файла — храповик

Новый файл больше 1200 строк не проходит проверку. Крупные файлы из истории
(`Registry.tsx` — 6071 строка, `server.ts` — 4919) перечислены в
`scripts/test-architecture.ts` с текущим размером: расти им нельзя, уменьшать
записанное число после выноса кода — нужно.

Разрастание лечится выносом куска в отдельный модуль рядом, а не поднятием
числа. Единственный случай, когда число поднимают, — осознанное решение с
объяснением в сообщении коммита.

## Как выносить маршруты из server.ts

Модуль в `server/routes/` экспортирует `registerXRoutes(app)` и берёт клиента
базы **лениво**: `const prisma = getPrisma();` в начале каждого обработчика.
Захватывать клиента при импорте нельзя — он пересоздаётся при смене базы.

Помощник, который нужен и в `server.ts`, и в модуле (хеш пароля, сброс кэшей),
не тащится импортом обратно — это круг. Он передаётся при подключении:

```ts
registerUserRoutes(app, { hashPassword, invalidateRolePerms, invalidateAuthUser });
```

Уведомления — через `notifyUser()` из `server/context.ts`, а не напрямую.

Порядок работы: снять срез `scripts/test-api.ts` на поднятом сервере, вынести,
прогнать снова, уменьшить число в храповике. Так уже переехали Проводник
(`explorer.ts`) и Сотрудники с ролями (`users.ts`).

## Ленивая загрузка разделов

Все разделы подключаются через `lazy(() => import(...))` в
`src/workspace/sections.tsx`. Так и оставлять: главный чанк и без того велик
(Univer, pdf.js, mammoth), а программа должна открываться сразу.

## Границы ошибок — по разделам, не одна на всё

Рабочий стол держит до четырёх разделов смонтированными одновременно
(keep-alive). Одна корневая граница означала бы, что сбой в одном разделе
уносит остальные вместе с несохранёнными правками. Поэтому каждый раздел
обёрнут в `SectionErrorBoundary` (`src/components/SectionErrorBoundary.tsx`):
падает только своя панель, её можно перезапустить или закрыть, сбой попадает в
Журнал. Корневая граница в `src/main.tsx` остаётся как последний рубеж.

Новый самостоятельный кусок интерфейса, который может упасть на чужих данных
(редактор, просмотр документа, таблица), заворачивать так же.

## Состояние — по видам, а не всё в одном

- **локальное** — `useState` в компоненте; поднимать выше только когда
  понадобилось соседу;
- **общее** — zustand-хранилище в `src/store/`, отдельное на область
  (`chatStore`, `workspaceStore`, `notificationStore`), не одно на всё;
- **серверные данные** — через `dataService`; хранить у себя только то, что
  реально переиспользуется;
- **состояние адреса** — путь и параметры раздела; рабочий стол «замораживает»
  адрес скрытой панели, поэтому раздел обязан переживать смену `location`.

Подписываться селектором (`useStore((s) => s.x)`), а не забирать хранилище
целиком — иначе перерисовка на каждое изменение чего угодно.
