## Решение

### 1. Как клиент получает «было → стало»

Сервер не знает, что показывал экран, — он знает только версию. Поэтому
сравнивает клиент: запись, которую экран показывал в момент действия (из
дерева), с `current` из отказа. Общее место — `src/lib/recordChanges.ts`, без
React и сети: `changesBetween(shown, current, rules) → [{ label, was, now }]`.
Правила полей (`rules`) у каждой программы свои и лежат рядом с ней; для
оборудования — `src/components/equipment/changeRules.ts`: название,
обозначение, тип (класс и вид), состояние, число, значения характеристик
(по одной строке на изменённую характеристику: `originalSpecs` дерева против
`specs` из отказа; ручные значения `overrides` так же), привязанные теги.
Поля, которых человек не видит (id, даты, служебные), в правила не входят.
Различий по правилам нет — так и сказано: «изменения не затронули показанные
поля».

Чтобы сравнить теги, отказ по позиции отдаёт `current` с `tags: [{ id, code }]`
(сейчас сырая строка без тегов) — через `present` в `sendVersionConflict`.

Показ — общий `src/components/ui/ConflictNotice.tsx`: текст отказа и перечень
«Поле: было → стало». В форме (тип, значение, окно добавления, выбор тега) он
стоит на месте прежней строки отказа; у действий без формы (удаление,
отвязка тега) открывается окном, потому что перечень в всплывающую строку не
помещается. Набранное остаётся в поле — как сейчас; дерево перечитывается.

### 2. Как сервер узнаёт, у кого запись открыта

Сервер у каждого свой, общая только база — поэтому, как и присутствие,
«открыто» живёт в общей таблице `OpenRecord`: `id`, `model`, `recordId`,
`userId`, `holderKey` (случайный ключ окна), `at`; уникально
(`model`, `recordId`, `holderKey`).

- Окно сообщает полный список открытого одним запросом
  `PUT /api/open-records { holderKey, records: [{ model, id }] }`: при смене
  выбранного и каждые 15 с. Сервер ставит этим строкам `at = сейчас` и удаляет
  остальные строки этого окна. Пустой список — «ничего не держу». При
  закрытии окна — тот же запрос маяком (`pagehide`, `POST`).
- «Открыта» в оборудовании — это выбранная позиция или установка (её
  карточка на экране) и запись, над которой открыто окно правки.
- Строка действует, пока свежа: 90 с без отметки — окно закрыли, Flux закрыли
  или пропала связь. Это не срок освобождения: пока Flux открыт и на связи,
  отметки идут и запись занята сколько угодно (решение владельца, п. 8).
  90 с, а не 45: свёрнутому окну браузер вправе будить таймер раз в минуту.
- Свои отметки человеку не мешают (любое его окно): удаляющий сам держит
  запись выбранной.
- Сверка — в `guardedDelete` (`openCheck`), в той же транзакции до удаления:
  запись и всё, что уйдёт каскадом (установка → блоки → позиции; позиция →
  вложенные). Занято — отказ 409 `{ error, code: 'RECORD_OPEN', holders:
  [{ userId, name }], record: { model, id, name } }`, ничего не удалено.
- Таблицы нет (общая база до синхронизации схемы) — удаление идёт без этой
  защиты; иной сбой чтения отметок — 503, а не удаление вслепую (то же
  правило, что у расписок повтора).
- Остаток, который не закрыть: коллега открыл запись в ту же секунду, когда
  её удаляют. Он увидит «запись уже удалена» при сохранении.

### 3. Словарь текстов

Одно место — `src/lib/refusalTexts.ts` (его берут и сервер, и клиент). Код —
отдельным полем, в тексте его нет. Имена людей — в именительном («открыта у
сотрудника: Иванов И. И.»), чтобы не склонять. Название записи — существительное
из словаря с формами («Позиция/Позицию», «Установка/Установку», «Блок/Блок»).

| Случай | Код | Текст |
|---|---|---|
| правка изменённой | `VERSION_CONFLICT` | «Позицию «X» изменили, пока вы её правили. Ваша правка не записана и осталась на месте. Ниже — что изменилось.» |
| удаление изменённой | `VERSION_CONFLICT` | «Позицию «X» изменили после того, как вы её открыли, поэтому она не удалена. Ниже — что изменилось. Если удалить всё равно нужно — повторите.» |
| создание внутри изменённого | `VERSION_CONFLICT` | «Установку «X», в которую вы добавляете, изменили. Новая запись не создана, введённое осталось в окне. Ниже — что изменилось.» |
| массовое действие | `VERSION_CONFLICT` | «Пока вы смотрели предпросмотр, часть записей изменили. Ничего не записано. Ниже — что изменилось; проверьте и подтвердите заново.» (текст и показ по записям готовы; сами массовые пути — строка 5) |
| правка удалённой | `RECORD_GONE` (404) | «Позицию «X» уже удалили. Ваша правка не записана.» |
| создание внутри удалённого | `RECORD_GONE` (404) | «Установку, в которую вы добавляете, уже удалили. Новая запись не создана.» |
| удаление удалённой | — (200, как сейчас) | на экране: «Позиция уже удалена.» |
| удаление открытой | `RECORD_OPEN` | «Позиция «X» сейчас открыта у сотрудника: Иванов И. И. Удалить её нельзя, пока запись открыта.» |
| удаление, открыто вложенное | `RECORD_OPEN` | «В установке «X» сейчас открыта позиция «Y» у сотрудника: Иванов И. И. Удалить установку нельзя, пока запись открыта.» |
| одновременная запись без версии | `VERSION_CONFLICT` | «Запись меняют одновременно, повторите действие.» |
| различий в показанном нет | — | «Изменения не затронули то, что показано на экране.» |

### 4. Чем доказывается

| Часть | Набор | Мутации |
|---|---|---|
| сравнение полей | `test-record-changes` | убрать правило поля; поменять местами было/стало; не разбирать характеристики |
| словарь | `test-refusal-texts` | убрать случай; вставить код в текст |
| открытые записи | `test-open-records` (настоящая SQLite) | убрать «кроме себя»; убрать свежесть; не удалять прочие строки окна |
| маршруты | `test-equipment-version-routes` (+) | убрать `openCheck` у удаления позиции и установки; не смотреть вложенные; убрать `tags` из `current`; вернуть 404 без кода |
| экран | `test-equipment-version-ui` (+), два человека, настоящая служба, снимки обеих тем | не показывать перечень; не слать отметку; сбросить набранное |
| храповик | `test-architecture`: всякий `guardedDelete` несёт `openCheck` или внесён в перечень с причиной | — |
