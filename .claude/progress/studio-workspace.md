Полное задание:

**A. Studio разработчика — одно рабочее окно вместо шести разделов**
1. Стартовый экран «Мои программы» + «Новая программа» одним диалогом
   (название, язык расчётов из 7, вид: форма / свой экран, пример на выбор).
2. Рабочее окно: слева дерево файлов и папок (создать, переименовать,
   переместить, удалить с подтверждением, загрузить, скачать и импортировать
   архив), в центре редактор с вкладками (редакторы формы и кода из #155,
   HTML/CSS/JS/TS, просмотр картинок), поиск по проекту; сверху «Запустить»,
   «Проверить», «Опубликовать»; внизу журнал: «Запуск», «Проблемы»,
   «Публикация», «Сбои у пользователей».
   Проект — папка на диске, как в Visual Studio: «Открыть папку как проект»,
   слежение за папкой, внешние изменения видны сразу, конфликт с
   несохранённым — вопрос; правка внешним редактором и git (шаг 1 — готово).
3. «Собрать»: TypeScript внутри Studio (esbuild-wasm в изолированном потоке),
   ошибки по файлам и строкам.
4. «Опубликовать» сама запускает проверку; диалог «что нового» с
   предложенным номером версии.
5. Ключ разработчика создаётся сам; одна кнопка «Запросить право
   публиковать»; выдача — только владельцем по запросу (решение владельца).
6. Адрес базы берётся у лежащего рядом Flux; ручной ввод — запасной путь.
7. `flux.openFile` — файл пользователя через диалог Flux (добавлением к v2).

**B. Studio — Владелец:** три пункта — «Программы на проверку» (запросы на
право публиковать, запросы на публикацию, выпуск одним окном, кому
доступны), «Flux: обновления», «Лицензии»; пароль хранилища один раз за
сеанс; пробный запуск программ-страниц.

**C. Слова:** без «канал», «договор», «привязки», «манифест», «бандл»;
подсказка первого запуска «путь за 5 шагов».

Правила: только добавление к договору; в сборке разработчика нет кода
владельца (`check-studio-bundle`); права на сервере; наборы с мутациями в
манифестах и workflow; настоящий запуск обеих Studio под Electron в CI;
без rebase и force-push; в коммитах и PR без названия модели; «программа»,
не «подпрограмма». Готовность — зелёный CI на последнем SHA, включая
«Flux Studio» и ручной `build-studio-owner.yml`.
