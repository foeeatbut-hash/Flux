## Устройство (решение руководителя, 14 ноября 2026)

### Самостоятельная программа

Признак вычисляется из манифеста, нового поля нет: `reads` пуст и места
запуска — только «Пуск». Одна чистая функция в `modules/` (рядом с реестром
разрешений), ею пользуются Flux, Store, окно установки и Studio.

- Открывается без выбранного проекта (после входа во Flux): пункт в «Пуске»
  и окно программы не требуют `activeProject`. Остальные программы ведут себя
  как раньше.
- Метка «работает без связи» (Store, окно установки, Studio) — у
  самостоятельной программы без разрешений на интернет/локальную сеть и без
  обращений к другим программам (`permissions` без `net*` и `program`).
  Подключения к программам на этом компьютере (COM и т. п.) метку не снимают.
  Метка — заявление о программе; сам запуск без связи появится на этапе 3.

### Хранилище программы (`flux.state` на диске)

- **Кому.** Только самостоятельной программе. Программа, читающая данные
  Flux, остаётся с `flux.state` в памяти, как сейчас: копии данных проектов
  вне базы на диск не попадают (`flux-data-safety`, `offline-work.md`).
- **Договор не меняется:** те же `state-load` / `state-keep` (объект целиком).
  Новых op для хранилища нет; программа не знает, в памяти оно или на диске.
- **Где.** Главный процесс Electron, папка данных приложения:
  `userData/program-data/<пользователь>/<id программы>/<область>/state.json`,
  где `<пользователь>` — первые 32 знака sha256 от id пользователя Flux,
  `<область>` — `released` | `dev`. Studio — своя папка данных Studio с той
  же раскладкой и областью `studio`. Три области друг друга не видят.
  Каналы выпуска (стабильный/бета) делят одно хранилище `released`: смена
  канала не должна терять данные человека.
- **Формат.** `{ format: 1, program, writtenBy: "<версия>", savedAt, state }`,
  JSON, UTF-8, без шифрования (портативная сборка переносится между
  компьютерами — привязка к учётной записи Windows потеряла бы данные).
  Запись атомарная: временный файл рядом → переименование. Файл с
  неизвестным `format` или битый — не затирается молча: переименовывается в
  `state.broken-<время>.json`, программа получает пустое состояние, строка в
  журнале программ.
- **Предел.** 1 МиБ на программу и человека (размер JSON поля `state`);
  прежний предел памяти 256 КиБ остаётся для несамостоятельных программ.
  Превышение — отказ `LIMIT`, прежнее сохранённое состояние остаётся целым;
  текст для человека и разработчика: «Хранилище программы заполнено: N из
  1 МиБ». Предел проверяет главный процесс, а не только окно.
  Ошибка диска — отказ `FAILED`, состояние в памяти окна живёт до закрытия.
- **Обновление и откат.** Данные не трогаются ни при обновлении, ни при
  откате версии; программа сама обязана читать свой старый и новый формат
  (пишется в справке разработчика). `writtenBy` — для диагностики.
- **Удаление программы.** Явное удаление программы человеком на этом
  компьютере удаляет папку `released` этой программы у этого человека; в
  подтверждении удаления — строка «Сохранённые программой данные на этом
  компьютере будут удалены». Удаление только по точному пути
  `<пользователь>/<id>` (id проверен по образцу id программы), никаких
  удалений по списку/фрагменту и никакой автоматической чистки при входе
  (отозванный выпуск или сбой списка не должны стирать данные).
- **Выход из профиля.** Память окна очищается, диск остаётся.
- **Без Electron** (браузер в проверках): память, как сейчас.
- **«Запустить во Flux».** Область `dev`: переживает перезапуск Flux и
  Studio и «Убрать» (иначе разработчику не проверить «переживает
  перезапуск»); очищается кнопкой «Очистить хранилище» рядом с «Убрать» и из
  Studio. С `released` не пересекается.
- **Studio.** На вкладке «Запуск»: строка «Хранилище: N из 1 МиБ» (или
  «в памяти — программа читает данные Flux»), кнопка «Очистить»; отказ
  `LIMIT` виден в журнале запуска тем же текстом, что у пользователя.

### Действие attach (только заложено)

- Реестр разрешений: новый вид `attach` — запись манифеста
  `permissions: [{ kind: 'attach', does }]`, `consent: true`; строка в окне
  установки «Прикрепляет результаты к проектам: <does>» (заметная), входит в
  отпечаток согласия (повторное согласие при появлении) и в разницу у
  владельца — всё через реестр, без отдельных веток кода.
- Договор: новый op `attach` (`flux.attach({ name, mime?, data, encoding })`
  — тот же вид файла, что `file-offer`). Ответ: без разрешения в манифесте —
  `FORBIDDEN`; с разрешением — `UNAVAILABLE` («прикрепление появится позже»),
  пока нет плана изменений. Записи нет нигде: ни сервер, ни Electron op не
  обрабатывают. Строка «Ничего не записывает во Flux» остаётся верной.
- То же поведение в Studio (журнал запуска показывает отказ).
