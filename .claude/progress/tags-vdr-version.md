## Решение

Граница строки: поштучные маршруты и два массовых действия, названных в части
2 (`bulk-metadata`, массовые правки ВДР с экрана). Импорт тегов, захват,
конструктор, комплекты, выпуск, импорт ВДР — строка 5, не трогать.

### Общий вид отказа (для всех трёх исполнителей)

- 409 `{ error, code: 'VERSION_CONFLICT', current }` — `current` голая запись,
  как её отдаёт обычное чтение (у тега — с разобранным видом, какой видит
  экран). Старые поля отказа (`conflict`, `tag`, обёртки `{ item }`,
  `{ register }`) убрать: программа не внедрена, старых сборок нет.
- 404 при правке/создании внутри — `code: 'RECORD_GONE'` (`sendRecordGone`).
- Удаление — `guardedDelete` с `openCheck`, версия в `?expectedVersion=`
  (целая `version` записи); отказы — `sendGuardRefusal`.
- Тексты — только из `src/lib/refusalTexts.ts` (существительные `tag`,
  `register`, `registerItem` уже добавлены руководителем; нужен новый текст —
  добавь функцию в конец файла, чужие не правь).
- Чем сверять правку: у тега остаётся `version` = `updatedAt`, у ВДР —
  `expectedUpdatedAt` / `expectedRevision`: они уже работают, на целую версию
  не переводим.
- Массовое действие по устаревшим данным: всё или ничего. Хоть одна запись
  изменена или удалена — не записано ничего, ответ 409 `{ error:
  bulkChangedText(), code: 'VERSION_CONFLICT', changed: [{ id, current }],
  gone: [id] }`; экран показывает перечень по записям (`ConflictNotice`,
  `groups`), перечитывает данные, человек подтверждает заново.

### Теги, сервер (И1)

- `PUT /api/tags/:id`, `PATCH /api/tags/:id/procurement`: отказ и 404 — общего
  вида. Правило «раскладка (x, y, _noPos) версию не сверяет и не двигает»
  остаётся.
- `DELETE /api/tags/:id`: `expectedVersion` + `guardedDelete` + `openCheck`;
  история и подъём версий позиций — в `before`, как сейчас в транзакции.
  В каскад проверки открытых входит только то, что удаляется вместе с тегом
  (выясни по коду: дочерние теги удаляются или остаются).
- `PUT /api/tags/bulk-metadata`: каждая запись несёт `version` (что видел
  экран); правило «всё или ничего» выше; только-раскладка сверку не требует
  (как у поштучной). `missing` больше не молчит: удалённый тег — отказ
  (`gone`). Срез 2000 молча — заменить отказом 400.
- `POST …/tags`, `POST /api/tags/generate` — создание в проекте, сверять
  нечего; не трогать.
- Наборы: `scripts/test-tag-version-routes.ts` (настоящая SQLite, express, два
  человека; база после отказа не изменилась) + мутации на каждую защиту.

### ВДР (И2: сервер и экран)

- `server/routes/vdr.ts`, `server/vdrWrite.ts`: отказ общего вида (голый
  `current`), тексты из словаря, 404 с кодом.
- `DELETE /api/vdr/registers/:id` (каскад открытых — его строки) и
  `DELETE /api/vdr/items/:id`: `expectedVersion` + `guardedDelete` +
  `openCheck`; «нет записи» — 200 `alreadyGone`, а не 500.
- `POST /api/vdr/items`: реестра нет — `RECORD_GONE` (создание внутри).
- `POST /api/docflow/links` → `applyReturn` (`server/docflowLinks.ts`):
  безусловную запись строки заменить на «сравни и поменяй» по собственному
  чтению (`updateMany where { id, version }`, проигрыш — повтор чтения или
  отказ), в той же транзакции.
- Экран (`src/components/vdr/`): карточка строки и реквизиты реестра при
  отказе показывают перечень «было → стало» и НЕ сбрасывают набранное (сейчас
  карточка подменяет поля текущими, а реквизиты закрываются); правила полей —
  `src/components/vdr/changeRules.ts` (только видимое: номера, названия, код,
  ревизия, статус, исполнитель, срок, замечания, теги; у реестра — реквизиты);
  массовые «назначить исполнителя» и «заполнить английские названия» шлют
  `expectedUpdatedAt` каждой строки, проверяют ответы и показывают, что
  записано, а что нет и почему (перечень по строкам); карточка строки и
  реквизиты держат запись открытой (`useOpenRecords`: `DocRegisterItem`,
  `DocRegister`).
- Наборы: дополнить `scripts/test-vdr-concurrency.ts`; экран —
  `scripts/test-vdr-version-ui.ts` по образцу `test-equipment-version-ui.ts`
  (настоящая служба, два человека, снимки обеих тем) + мутации.

### Теги, экраны (И3)

- `src/components/registry/tagWrite.ts`: отказ узнаётся по `code`; запись с
  экрана берётся до подмены; вместо строки «данные обновлены — повторите»
  человек видит перечень «было → стало», набранное в карточке
  (`TagCardModal`) и в поле остаётся.
- Правила полей — `src/components/registry/changeRules.ts`: код, наименование,
  марка, отдел, WBS, среда, оборудование, описания, связи, родитель, этап и
  поля закупки. Служебное (x, y, `_noPos`, `__procMeta`) не показывать.
- Удаление тега (`useTagTreeOps.ts`): версия в запросе, ответ проверяется,
  отказ (изменили / открыт у коллеги / сбой) показывается окном; сейчас при
  ошибке человек не видит ничего.
- `bulk-metadata` из «Закупок» (массовый этап, назначение шаблона) шлёт версии
  и показывает перечень по записям; из «Реестра» (раскладка) — как есть.
- Открыто: карточка тега (`editingTag`) и мини-панель (`cardPanel`) в
  «Реестре»; правка примечания в «Закупках».
- `Registry.tsx` в запасе 24 строки до предела — новое только в отдельных
  файлах (`src/components/registry/`).
- Наборы: `scripts/test-tag-version-client.ts` (правила полей, разбор отказа,
  запрет записи тега мимо общего места), экран —
  `scripts/test-tag-version-ui.ts` (настоящая служба, два человека, снимки
  обеих тем) + мутации.
